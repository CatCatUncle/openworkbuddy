# 合同审阅技能

## 先说清楚这份技能不是什么

**这不是法律意见**。你做的是「把风险点挑出来摆到人眼前」，让用户带着一份清单去找律师、去跟对方谈，
而不是替他决定签不签。每份输出的结尾都要有一句：本清单由 AI 整理，不构成法律意见，重大合同请律师过目。

## 1. 先把合同读进来

`read_document` 读 `.docx` / `.pdf`，扫描件走 OCR 那条路。
读进来第一件事是**确认自己站在哪一边**：甲方还是乙方？收钱还是付钱？
搞反了整份审阅就是反的。看不出来就用 `ask_user` 问一句，这一问值得。

## 2. 逐条过，不要跳

按条款顺序从头读到尾。下面这些是每次都要专门找一遍的：

| 关注点 | 找什么 |
|---|---|
| 钱 | 总额、付款节点、是否含税、税率、发票类型、逾期付款怎么办 |
| 交付 | 交付物是什么、验收标准、验收期限、超期不回复算不算通过 |
| 变更 | 需求变更怎么计价、返工几次以内免费、超了怎么算 |
| 违约 | 双方违约金比例是否对等、上限、是否约定了实际损失外的赔偿 |
| 知识产权 | 成果归谁、源码给不给、能不能拿去做案例、第三方素材授权谁担责 |
| 保密 | 期限、范围、是否单向 |
| 解除 | 谁能单方解除、提前多久通知、解除后已投入的成本谁承担 |
| 争议 | 仲裁还是诉讼、在哪个城市、这条对你远不远 |

## 3. 输出结构

```markdown
# <合同名称> 审阅清单
我方身份：乙方（服务提供方） ｜ 合同金额：¥xxx ｜ 审阅日期：2026-09-13

## 一、高风险（建议签字前必须改）
### 1. 第 8.2 条 违约金不对等
- **原文**：「乙方逾期交付的，每日按合同总额 5% 支付违约金……」
- **问题**：甲方逾期付款只按 0.5%/日，差十倍；且乙方违约金未设上限，拖二十天就赔光全款。
- **建议改成**：双方均按 0.5%/日，累计不超过合同总额的 10%。

### 2. ...

## 二、中风险（能争取就争取）
（同样格式）

## 三、缺了什么（对方没写，但你该要）
- 没有验收期限：建议加「甲方应在收到交付物后 5 个工作日内书面反馈，逾期视为验收通过」
- 没有不可抗力条款
- ...

## 四、还需要你确认的
- 第 3 条提到的《附件二 技术方案》没在文件里，需要一并看
- 第 11 条写的结算主体和落款公司名不一致，确认是否同一家
```

## 4. 三档怎么分

- **高风险**：可能让你干完活拿不到钱、赔钱、或者丢掉成果所有权。
- **中风险**：不公平但不致命，谈得下来最好，谈不下来可以接受。
- **缺失项**：对方没写、一旦出事没有依据可循的。缺失项往往比写坏的条款更危险，别漏。

## 5. 交付

写成 `.md` 或 `.docx` 给用户。
他要发回给对方或转给律师时用 `send_email`——注意**原合同文件要作为附件一起带上**，
只发一份清单对方看不懂在说哪一条。

## 红线

- **不要改合同原文**，只提修改建议。改稿是用户和律师的事。
- **原文一定要逐字引用**，不能转述。「大意是说……」在谈判桌上一文不值。
- **不确定的不要下结论**。看不懂的条款写进「还需要你确认的」，不要猜一个解释写成风险。
- **绝不说「这份合同没问题，可以签」**。你的职责到「这是我找到的风险」为止。
- 合同里的公司名、金额、身份证号、银行账号属于敏感信息，整理完提醒用户注意分发范围。

## 质量标准

- 每一条风险都能指到具体条款号，并附上原文
- 每一条都写清「为什么这对我方不利」，而不是只说「此条不利」
- 「缺了什么」这一节不为空——一份真实合同几乎不可能什么都不缺
- 用户拿着这份清单能直接跟对方逐条谈，不用再回来问「那我该怎么说」
