# 深度调研技能

## 适用场景
行业调研、竞品分析、技术选型、政策梳理、事件复盘等需要"查资料 + 出报告"的任务。

## 操作步骤

### 1. 先拆题，再开搜
把主题拆成 3-6 个能被独立查证的子问题（现状规模 / 关键玩家 / 商业模式 / 数据指标 / 政策与风险 / 趋势）。
拆完先把子问题列出来给用户看一眼（一两句话），然后立刻开工，不用等回复。

### 2. 检索：先 web_search 定位，再 fetch_url 读原文
- **`web_search` 是主力**，先用它拿到候选链接和摘要，再 `fetch_url` 抓真正要读的正文。
  只看搜索摘要就下结论 = 没做调研。
- 搜索词要换着问：中文一轮、英文一轮、加上"年报/招股书/白皮书/公告/数据"这类限定词一轮。
- `web_search` 拿不到东西时才退回抓搜索引擎结果页：
  `https://www.bing.com/search?q=关键词`、`https://www.sogou.com/web?query=关键词`，
  抓到后提取目标链接再逐个抓正文。
- **每个子问题至少读 2-3 个不同来源的原文**，同一家媒体的多篇稿子不算多来源。

### 3. 来源分级（写报告时按这个信任度取舍）
| 级别 | 类型 | 怎么用 |
|---|---|---|
| A 一手 | 官网、财报/年报、招股书、政府公告、法规原文、论文、官方文档 | 直接采信，优先引用 |
| B 权威二手 | 头部行业媒体、券商研报、知名咨询机构报告 | 可用，注明出处与发布时间 |
| C 弱来源 | 个人博客、内容农场、无署名聚合站、AI 生成的站 | 只当线索，必须回溯到 A/B 才能写进结论 |

### 4. 交叉验证与时效
- 关键数字（市场规模、份额、价格、用户量）**至少两个独立来源印证**；对不上就两个都写出来并标明分歧。
- **每个数据必须带时间**："2025 年 Q3 为 X"，不要写成"目前为 X"。
- 明确区分「实际发生」和「预测/规划」，预测要写清是谁预测的。
- 报告开头写明检索日期（用系统提示里给的今天的日期，不要用你记忆里的年份）。

### 5. 写完自己找一轮反证（这步最值钱）
初稿完成后，针对你最主要的 2-3 个结论，反过来搜一轮"反面/质疑/失败/翻车/被否"的证据。
找到了就把结论改软或加限定条件；没找到也在报告里说明"已做反向检索，未见公开反证"。

### 6. 结构化输出（写进 .md 文件，不要只在聊天里说）
- **摘要**：3-5 条核心结论，每条一句话说完，能直接转发给老板
- **分主题详述**：每个关键论断后面挂来源 `[标题](URL)`（有发布日期就写上）
- **数据表格**：所有数字集中成表，列出「指标 / 数值 / 时间 / 来源」
- **竞品必须成表打分**：凡是"竞品分析/选型/对比"，样本不少于 8 家（真的只有 3 家就写明"该品类公开可查的就这几家"），
  横轴是你自己定的评估维度（先写清每个维度怎么打分），每格填**可溯源的事实**而不是形容词，最后一列给总分和一句话结论。
  只写几段"A 家怎样、B 家怎样"的散文不算交付——用户要的是能横着比、能据此拍板的那张表。
- **风险与不确定性**：查不到的、来源打架的、时效存疑的，单列一节
- **参考来源清单**：按来源级别排序，标注 A/B/C

### 7. 分工
子问题多且互不依赖时，可以委派「调研专员」并行跑不同子问题，最后你自己合稿并统一交叉验证——
**不要把专家汇报直接拼起来交差**，重复的要合、打架的要判、口径要统一。

## 红线
- **不编造**：查不到就写「未查到公开信息」，不许用"约""据业内估计"糊。
- **不编来源**：URL 必须是真的抓到过的；不许凭印象造一个看起来很像的链接。
- **不把预测写成事实**，不把单一来源写成"业内普遍认为"。

## 质量标准
- 每个关键结论都能点着链接溯源
- 所有数字都带时间口径
- 有独立的"不确定性"章节，而不是通篇都很确定
- 报告可直接转发给他人阅读，不需要你再口头补充
