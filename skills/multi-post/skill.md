# 一稿多投

## 适用场景
「这篇稿子帮我发公众号、小红书，再出个抖音口播」「把这份发布会稿改成各平台的版本」。
产出 = 表单里选的每个平台一份能直接贴的文案 + 3 个标题候选（选了配图才出封面）+ 一页 交付.html。

## 第 0 步：开头一张表单，把岔路一次定完
第一件事调 `ask_user`，带上 `form: "multi-post"`：

```
ask_user({ question: "开工前把这几项定下来", form: "multi-post",
           defaults: { source: "用户给的文件名", platforms: ["公众号", "小红书"] } })
```

- `defaults` 只填用户原话里**明确说过**的项，没说的留给表单默认值。
- 表单返回的就是定稿：原稿、平台、改多少、配图，后面**一律不再问**。
- 返回里写了「用户补充：…」的，补充跟默认值冲突时以补充为准。
- 表单填完，步数和时长上限会自动放宽到 80 步 / 30 分钟，不用让用户去设置里调。
- 没有 `ask_user` 表单可用（外部引擎、老版本）：按用户原话 + 默认值开工，替用户定的每一项都写进交付清单的 `assumptions`。

## 第 1 步：读原稿
- 原稿是文件：`.docx` / `.pdf` 用 `read_document`，其他用 `read_file`；是贴进来的一段就直接用。
- 先列出原稿的核心观点、关键数据和不能改的说法（产品名、价格、日期），改写时这几样一个字都不动。

## 第 2 步：按平台改写
- 先 `use_skill content-repurpose` 拿各平台的改写规矩。
- 表单里选的每个平台一版，**一个平台一份，不合并**：
  - 公众号：坐下来读的，保留完整论证，小标题分节；
  - 小红书：刷到的，开头一句钩子，短句分段，结尾 5–8 个标签；
  - 抖音口播 / 视频号：听的，一句不超过 15 个字，开头 3 秒给结论；
  - 知乎：先答问题再展开；微博：140 字内一个观点；朋友圈：像人说话，别像广告。
- 「保留原意只改说法」：结构不动，只换句子和语气；「允许重排结构」：可以换顺序、删枝节，但核心观点和数据不许丢。
- **不编造原稿里没有的数据和结论**。

## 第 3 步：标题和封面
- 主平台（表单里第一个）出 3 个标题候选，每个平台自己的标题写在各自那份里。
- 表单选了配图才出封面：「每个平台一张排版封面」用 `html_to_image`；「AI 生图封面」用 `generate_image`。
  **上游已经收单之后报错，不许自动重试**，把任务号和报错原样告诉用户。封面**不加任何「AI 生成」水印**。
- 选了「只要文字」就不出封面，这不算缺。

## 第 4 步：交付清单和交付页
写 `交付清单.json`，再调 `delivery_page` 出 `交付.html`：

```
{ "title": "…", "recipe": "multi-post",
  "titles": ["…", "…", "…"],
  "platforms": [{ "name": "公众号", "title": "…", "body": "…", "tags": [] },
                { "name": "小红书", "title": "…", "body": "…", "tags": ["…"] }, …],
  "covers": [{ "file": "封面_公众号.png" }],
  "assumptions": ["替用户定的项"], "missing": ["没做出来的，照实写"] }
```

- 每个平台的 `body` 是能直接贴的全文，不写「此处省略」。
- 最后回一句：交付页做好了，点「在浏览器打开」，每个平台一键复制。
