# 邮件沟通技能

## 一封好邮件长什么样

对方在手机上扫一眼就知道：**这是什么事、要我做什么、什么时候之前**。
做不到这三点的邮件，写得再客气也是在浪费两个人的时间。

## 1. 动笔前先问自己三句

1. 收件人是谁？（客户 / 上级 / 平级 / 供应商 / 陌生人——语气差别很大）
2. 我要他做什么？（回复确认 / 付款 / 提供材料 / 只是知会不用回）
3. 有没有时限？

用户没说清楚就用 `ask_user` 问，别自己假设一个收件人身份写完再返工。

## 2. 结构

```
主题：<一眼看清是什么事>，带上关键信息

<称呼>，

<第一段：一句话说清来意。不要用"见字如面""希望您一切安好"开头。>

<第二段：必要的背景和细节。超过三条就用项目符号列出来。>

<第三段：明确说要对方做什么、什么时候之前。>

<落款>
```

**主题行是整封邮件最重要的一行**。
「关于合作的事」→ 废的。「9/20 前需确认：XX 项目二期报价单」→ 对方在收件箱列表里就知道该不该现在点开。

## 3. 分寸感

| 场景 | 注意 |
|---|---|
| 催款 / 催回复 | 不指责。「附上 8 月账单，付款日是 9/15，麻烦帮忙走一下流程」比「您一直没回复」有用得多 |
| 拒绝 | 先给结论再给理由，不要铺垫五行才说不行。可以的话给一个替代方案 |
| 道歉 | 承认具体的那件事 + 已经怎么补救 + 以后怎么防。不要连写三段「非常抱歉」 |
| 第一次联系陌生人 | 头两句就说清你是谁、从哪知道对方、为什么找他 |
| 坏消息 | 主题行别写成好消息骗人点开，正文第一段就说 |

## 4. 附件

提到「附件」就一定要真的带附件——这是最常见也最丢人的失误。
写之前确认文件路径存在；正文里用一句话说明附件是什么（「附件是报价单，含两种方案的价格对比」）。

## 5. 发出去

写完先把**全文给用户看**，不要写完直接发。
用户点头后 `send_email` 发出去（这个工具本身也会再弹一次全文让他确认，两道都不能省）。

用户没配 SMTP 时，就把正文整理好交给他自己复制去发，一样是完成任务。

## 红线

- **不许替用户做承诺**。价格、交期、赔偿方案，凡是用户没明确说过的，都用 `ask_user` 问，不要写一个"合理的数"进去。
- **不许伪造事实**。「我们已经安排工程师处理」——除非用户说了确实安排了。
- **收件人地址必须用户给或从往来邮件里明确取到**，不要从网页、不要从模型记忆里"推测"一个邮箱。
- 邮件一旦发出去收不回来。有任何一处不确定，宁可多问一句。

## 质量标准

- 主题行单独拿出来看，也知道这封信是什么事
- 全文能在手机一屏内读完（超过就说明该拆成附件或文档）
- 读完能准确回答「我要做什么、什么时候之前」
- 没有一句正确但没用的客套话
