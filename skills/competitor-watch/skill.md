# 竞品监控

## 适用场景
"帮我盯着这几家"、"竞品最近有什么动静"、"他们涨价了吗"。
跟 `deep-research` 的区别：调研是一次性挖深，监控是**反复跑同一套动作、只交差异**。

## 第一次跑：先立基线

### 1. 定监控对象和观测点
每家竞品固定盯这几页，URL 要具体到页，不要只写域名：

| 观测点 | 为什么值钱 |
|---|---|
| 定价页 | 涨价/降价/套餐改名/免费额度缩水，是最硬的信号 |
| 更新日志 / Release Notes | 他们把力气花在哪 |
| 首页主标题 | 一句话定位变了 = 战略变了 |
| 招聘页 | 招什么岗位，就是下半年要做什么 |
| 官方博客 / 公众号 / X | 对外叙事 |

### 2. 抓页面用 `check_page`，不要只 `fetch_url`
定价页和控制台大多是前端渲染的，`fetch_url` 抓回来是个空壳。
`check_page` 走真浏览器，能拿到渲染后的正文和整页截图。
截图存下来——下一轮对比时，"哪儿变了"用肉眼看比 diff 文本快。

### 3. 存基线
每家一个 `竞品监控/<公司名>/基线.md`，记：观测日期、每个观测点的 URL、抓到的关键字段
（价格数字、套餐名、版本号、在招岗位列表、首页主标题原文）。
**价格必须记成结构化的**：`专业版 / 月付 / 199 元 / 含 5 席位`，不要写成一段话，否则下轮没法比。

## 后续每轮：只交差异

### 4. 重抓 → 逐字段比 → 只写变了的
输出固定这四段，**没有变化就明说"本轮无变化"，不要为了显得有产出而凑字**：

```
## 本轮变化（2026-09-20，对比 09-13）
- 【定价】A 家专业版 199 → 249 元/月，免费额度从 500 次降到 200 次
- 【产品】B 家上了「团队空间」，更新日志 v3.4.0
- 【招聘】C 家新开 3 个「解决方案工程师」岗，全在上海 —— 像是要做本地化交付

## 没变的
A/B/C 三家首页主标题、C 家定价，均与上轮一致

## 这意味着什么（我的判断，不是事实）
...

## 存疑 / 没抓到
B 家定价页要登录才看得到，本轮没拿到
```

### 5. 判断那一段必须跟事实分开写
"他们涨价了" 是事实，"他们要往企业市场走" 是判断。判断段落自己标明是推测。

### 6. 定期跑用 `schedule_task`
确认用户要长期盯之后，用 `schedule_task` 排一条每周任务，提示词里带上观测点清单的文件路径。
排完告诉用户排在什么时间、怎么取消。

## 红线
- **不抓要登录的页面**，也不要用用户的账号去登竞品后台。抓不到就写"需登录，未获取"。
- **不编价格**。页面上没有的数字一律写"未公开"。
- 截图和正文存在工作目录里，别塞进聊天正文——一轮几万字没人读。

## 质量标准
- 每条变化都能点回具体 URL，并且写清"上轮是什么、这轮是什么"
- 无变化的项也列出来，证明这一轮真的看过
- 判断与事实分栏，不混写
