# 内容创作工作流

把每次创作当成一个项目，而不是一次性回答。优先使用当前工作区的文件、已生成成果和用户明确引用的素材；需要外部资料时保存来源 URL、标题和访问时间。

## 四步循环

1. **输入**：先列出素材和创作目标。网页、PDF、图片、音频、视频、Markdown 都是素材；长视频/音频先转写或提取关键片段，不要把整份原文塞进上下文。
2. **理解**：给素材做简短摘要、关键摘录、事实/观点/待核实标记。外部事实必须保留来源，用户自己的观点和 AI 推断要分开。
3. **创作**：先产出结构和第一版，再按用户的语气、平台、受众和长度迭代。文章、公众号、知乎、小红书、脚本、视频分镜分别调用已有专用 Skill；不要用一个模板硬套所有平台。
4. **交付**：交付 Markdown/HTML/Word/图片/音频/视频等真实文件，并保留可编辑源文件。若从一份内容派生多个版本，明确标记源稿与派生稿。

## 和用户共同创作

- 默认使用 `Ask` 思路处理理解、提纲、比较和事实核查；需要写文件、改稿、生成媒体、发布草稿或批量重写时才执行 Agent 工具。
- 用户说“改这一段/换个标题/更像我”时只做局部编辑，保留上一版或先另存版本，不整篇覆盖未读内容。
- 支持用 `@` 引用当前工作区文件、资料库文件、画布节点和已经生成的成果；引用多个素材时说明每个素材解决什么问题。
- 每轮结束给出“已完成、仍待确认、下一步可选动作”，不要把大量过程日志混成正文。

## 内容复用

当用户要推广或多平台发布时，先确认一个“母稿”，再派生：标题/摘要、长文、短帖、卡片文案、口播稿、分镜、配图提示词、音频稿。派生版本必须保留母稿链接或文件名，避免多份稿件互相漂移。

## 质量门

- 事实、引用和个人观点分层；不确定信息写明“不确定”并建议核验。
- 文章可以从头编辑到尾，Markdown/HTML 预览必须保留滚动位置、目录和版本入口。
- 图片、视频、音频先保存后预览；文件名、路径、来源和模型写入成果清单。
- 交付前至少检查：结构完整、没有占位符、链接可用、媒体文件存在、目标平台的标题/尺寸/长度限制满足。
