# 销售开发信

## 适用场景
"帮我给这几家公司写开发信"、"这个线索怎么跟"、"开发信没人回，帮我改改"。

## 顺序不能反：先研究，再写信

不研究直接套模板的信，收件人三秒就认出来了。每个线索**至少花两分钟**查：

| 查什么 | 怎么查 | 用来干嘛 |
|---|---|---|
| 公司在做什么 | `web_search` + `check_page` 官网 | 别把 to B 公司当 to C 写 |
| 最近发生了什么 | 新闻、官网博客、招聘页 | 开场第一句的钩子 |
| 收件人是谁 | 公开主页、领英式公开资料 | 决定讲业务价值还是讲技术细节 |
| 他们现在用什么 | 官网技术栈、案例页 | 判断是替换还是补充 |

查不到有价值的东西，就**别发这封信**。没有钩子的信只是骚扰。

## 信怎么写

**四句话，150 字以内，手机一屏读完。**

1. **第一句：证明你研究过他** —— 具体到某件事。"看到你们上个月开放了 API"，不是"贵公司业务发展迅速"
2. **第二句：这类公司常见的一个具体麻烦** —— 说痛点，不说你的产品
3. **第三句：你做过什么** —— 一个同类客户 + 一个可验证的结果
4. **第四句：一个极小的请求** —— "方便的话我发一份 3 分钟的对比给你？" 不是"约个 30 分钟的会"

标题 8-12 字，像同事之间发的，不像广告：
✅「关于你们 API 文档的一个想法」 ❌「【重磅】XX 解决方案助您降本增效」

### 一眼假的写法，全删
- "希望这封邮件找到你时一切都好"
- "我们是行业领先的……"
- 通篇"赋能""抓手""闭环"
- 一整段产品功能列表
- 附件直接甩一份 PDF

## 跟进节奏

回复大多来自第二、三封，但**每一封都得有新东西**，不能只是"想跟进一下"。

| 时间 | 内容 |
|---|---|
| 第 1 天 | 开发信 |
| 第 4 天 | 换个角度：一个相关案例或一篇有用的资料 |
| 第 10 天 | 一句话 + 一个具体问题（问题比陈述更容易被回） |
| 第 21 天 | 收尾信：说清不再打扰，留一句门一直开着 |

四封没回就停。继续发只会被标垃圾邮件，还连累域名。

## 发送

用 `send_email` 发。**发之前必须把最终内容给用户看一遍，等用户明确同意再发。**
一次别群发一大批——分小批发，看回复率再调。
`schedule_task` 可以把跟进排进日程，但每一封仍然要先过目。

批量线索整理成表：`公司 / 联系人 / 钩子 / 已发第几封 / 状态 / 下次动作日期`，
存成 `线索.xlsx`，跟进时更新。

## 红线
- **不许编造案例、客户名和数据。** 一次被戳穿这个域名就废了
- 不爬取、不购买私人邮箱；只用公开渠道能查到的工作邮箱
- 对方说"别再发了"就立刻停，并从表里标记
- 不要假装是共同好友介绍的、不要伪造回复线索

## 质量标准
- 第一句只对这一家公司成立，换一家就不通
- 全信 150 字以内
- 请求足够小，回一个字就能答应
