# 网页生成技能

## 适用场景
网站设计、落地页、在线报告、H5 展示页、数据看板、小型 Web 工具。

## 动手前先想清楚三件事

1. **这页是给谁看的、看完要他干什么**（留资？读懂数据？下单？）——决定首屏放什么。
2. **内容从哪来**：用户给了材料就先 `read_file` 读进来，用真实文案；没材料就按主题写具体可信的文案，
   **绝不允许出现 "Lorem ipsum"、"这里是标题"、"产品简介占位" 这类占位符**，那等于没做。
3. **要不要联网**：交付物默认必须断网可用（用户经常是双击本地文件打开的）。

## 硬规范

1. **单文件交付**：所有 CSS/JS 内联在一个 `.html` 里，双击即用。
   - 图表优先用**纯 SVG / Canvas 手写**或内联数据 + 原生 JS 画；确实要用 ECharts 这类库时，
     必须先问清楚"这页要联网用吗"，或者直接告诉用户"这页依赖 CDN，断网打不开图表"。
   - 图片用内联 SVG 或 CSS 画；**不要引用不存在的本地图片路径**（`img/hero.png` 这种一定是坏的）。
2. **响应式**：移动优先。`meta viewport` 必写；用 `clamp()` 控字号、`grid`/`flex` + `minmax` 控栅格；
   宽表格、代码块、图表放进 `overflow-x:auto` 的容器里，**页面本身绝不允许横向滚动**。
3. **深浅色都要能看**：用 CSS 变量定义配色，配 `@media (prefers-color-scheme: dark)`。
   除非用户明确要求只做一种。
4. **语义结构**：`header/nav/main/section/article/footer`，标题层级 h1→h2→h3 不跳级；
   图片带 `alt`，按钮用 `<button>` 不用 `<div onclick>`；正文与背景对比度 ≥ 4.5:1。
5. **视觉基线**：
   - 圆角 12-16px；阴影克制（`0 6px 24px rgba(0,0,0,.06)`），不要满屏投影
   - 字体栈 `"PingFang SC", "Microsoft YaHei", system-ui, -apple-system, sans-serif`
   - 间距用 4 的倍数；一屏之内主色不超过 2 个 + 1 个强调色
   - 对齐优先于装饰：相关的东西靠近、无关的拉开

## 避开"AI 味"（重要，这是最容易被一眼看穿的地方）

- ❌ 紫蓝渐变大标题 + 居中三张卡片 + emoji 当图标 + "赋能/闭环/一站式/全新升级"
- ❌ 每个区块都是"标题 + 一句话 + 三个并列卡片"的同一种节奏
- ✅ 配色从主题里长出来（餐饮暖、金融冷、儿童亮、法务稳），不是随手拿默认紫
- ✅ 版式有节奏变化：大图/两栏/引用/数据条/时间轴交替，别一路卡片到底
- ✅ 文案写具体的事（"3 天出图，改到满意为止"），不写形容词（"专业高效的服务"）

## 交付前必须自己走一遍（不做这步不算完成）

1. `read_file` 把生成的文件读回来，确认：标签闭合、`<style>`/`<script>` 完整、没有被截断。
2. 自查清单：viewport 有没有 / 有没有外链依赖 / 有没有占位符文案 / 有没有引用不存在的资源 /
   375px 宽会不会横向滚动 / 深色模式下字看不看得清。
3. 发现问题当场改完再交付，**不要把"你可以自己调一下"当交付**。

## 交付后

告诉用户成果文件名，并主动提一句：
> 已经在右侧预览里打开了。如果想在真实浏览器里（或手机上）看效果，点预览顶部的**「本地部署预览」**
> 就能起一个本机服务，相对路径、fetch、localStorage 这些在那儿才是正常的。

## 质量标准
- 浏览器打开零报错、零横向滚动条
- 375px 手机宽度排版正常，深浅色都可读
- 首屏就能看懂"这是什么、给谁的、下一步干什么"
- 断网双击也能完整显示（除非用户同意用 CDN）
