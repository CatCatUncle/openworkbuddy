# 小红书图文（6–9 张一组）

## 适用场景
「出一组小红书图文」「把这个选题做成 7 张卡片」「带一下我们的产品，做组种草图」。
产出 = `卡片_01.png`…（1242×1656，3:4 竖版）+ 3 张封面候选 + 3 个标题 + 正文和标签 + 一页 交付.html。

## 第 0 步：开头一张表单，把岔路一次定完
第一件事调 `ask_user`，带上 `form: "xhs-carousel"`：

```
ask_user({ question: "开工前把这几项定下来", form: "xhs-carousel",
           defaults: { topic: "用户原话里的选题", count: "7" } })
```

- `defaults` 只填用户原话里**明确说过**的项，没说的留给表单默认值。
- 表单返回的就是定稿：选题、产品、张数、出图方式、风格、语气，后面**一律不再问**。
- 返回里写了「用户补充：…」的，补充跟默认值冲突时以补充为准。
- 表单填完，步数和时长上限会自动放宽到 120 步 / 45 分钟，不用让用户去设置里调。
- 没有 `ask_user` 表单可用（外部引擎、老版本）：按用户原话 + 默认值开工，替用户定的每一项都写进交付清单的 `assumptions`。

## 第 1 步：选题角度和大纲
- 先定一个角度：干货讲清单和步骤，种草讲场景和感受，测评讲对比和结论（照表单的「语气」）。
- 列出每张卡片放什么：第 1 张是封面钩子，中间每张一个要点，最后一张收尾（总结或行动号召）。张数照表单。
- 带产品的，产品只在 1–2 张里自然出现，不写成硬广；**不编造功效和数据**。
- 这一步只出大纲，先别排版。

## 第 2 步：做卡片
- 先 `use_skill xhs-cards` 拿排版规矩（它的第 0 步由这张表单代替，出图方式已经定了，别再问）。
- **排版截图**：每张一个 HTML（放 `素材/card_01.html`…），`html_to_image` 截成 `卡片_01.png`…，宽 1242、高 1656。
- **AI 生图**：`generate_image` 按大纲逐张出，提示词写明「竖版 3:4，上下留白给标题」。
  **上游已经收单之后报错，不许自动重试**——重试等于再花一次钱。把任务号和报错原样告诉用户。
- 表单上出图方式是「这次不做」（截不了图，AI 生图没人选）：**不改用 AI 生图**。每张卡片的 HTML 照样写好放 `素材/`，文案照出，交付清单 `missing` 写「卡片图没截：这里截不了图，去桌面版打开 素材/ 里的 HTML 截」。
- 风格照表单：浅色杂志 / 深色质感 / 手账拼贴 / 极简大字。一套卡片一个视觉系统，只换内容。
- 图上**不加任何「AI 生成」水印或角标**。
- 每张截完确认 PNG 存在；溢出了就删字或缩字号重截。

## 第 3 步：封面候选、标题、正文和标签
- 3 张封面候选 `封面_A.png` / `封面_B.png` / `封面_C.png`，各用一个不同的钩子（数字 / 痛点 / 结果）。
- 3 个标题候选，每个 20 字以内。
- 正文 100–300 字，分段短句；5–8 个话题标签。

## 第 4 步：交付清单和交付页
写 `交付清单.json`，再调 `delivery_page` 出 `交付.html`：

```
{ "title": "…", "recipe": "xhs-carousel",
  "images": [{ "file": "卡片_01.png" }, { "file": "卡片_02.png" }, …],
  "covers": [{ "file": "封面_A.png", "note": "数字钩子" }, …],
  "titles": ["…", "…", "…"],
  "platforms": [{ "name": "小红书", "title": "…", "body": "…", "tags": ["…"] }],
  "assumptions": ["替用户定的项"], "missing": ["没做出来的，照实写"] }
```

- `images` 按顺序排，交付页用它做手机样式的左右滑动预览。
- 文件缺了就写进 `missing`，不拿占位图充数。
- 最后回一句：交付页做好了，点「在浏览器打开」就能滑着看、能一键复制文案。
