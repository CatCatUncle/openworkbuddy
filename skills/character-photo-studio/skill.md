# 角色写真/剧照批量生图

## 核心红线：不能写作品名和演员名

用户的需求几乎总是「86版《西游记》孙悟空」「87版《红楼梦》林黛玉」这种表述，
但**生图渠道（doubao-seedream）会按版权拦截**，返回：

```
OutputImageSensitiveContentDetected.PolicyViolation
```

实测结论（已多次复现）：
- prompt 里出现 **`《西游记》`/`《红楼梦》` 等具体剧名** → 必拦
- 出现 **演员真名**（六小龄童、陈晓旭等）→ 必拦
- 出现「86版」「87版」这类指向具体作品的限定词 → 高风险
- 改成 **纯造型描述**（「中国古代神话里的猴王形象」「中国古典贵族少女」）→ 稳定通过

**做法**：把用户给的所有造型细节（头饰、服装配色、道具、神情、动作、发型）
一个不漏地保留，只把「作品名 + 演员名 + 版本号」替换成中性身份描述。
开场白里就说明这一点，别等被拦了再说。

## 标准工作流

1. **清点需求**：几个角色、几张图、什么场景/影调/画幅、有没有特殊构图要求。
2. **一张一个 generate_image 调用**，文件名格式：`<角色>_<场景>_<影调>.jpg`
   （例：`沙僧_海中逆光_黑白剧照.jpg`）——中文文件名，一眼看得出内容。
3. **并行发起**：不依赖彼此的多张图放在同一轮里一口气发出去，系统会并发执行（默认同时 2 张，
   不是全部一起——每张都花钱，一次并十张出错了就是十份钱）。每张的文件名必须不一样，
   第 2 步那个命名法天然就不会重。
4. **prompt 结构固定四段**（照抄这个骨架，最稳）：
   - 第 1 段：**影调与介质**（胶片/CCD/黑白/数码 + 质感关键词）
   - 第 2 段：**人物造型**（脸型、妆容真假体、头饰、服装配色、道具、神情、动作、姿态）
   - 第 3 段：**环境与背景**（地点、光线、天气）
   - 第 4 段：**质量兜底句**（见下）
5. **质量兜底句必写**（不写就出手指畸形、面部扭曲）：
   `人物四肢完整正常，手指数量正确，面部清晰不扭曲，画面里不要出现任何文字、水印和logo。`
   若要画面内有指定文字（如海报歌名），就明确写出文字内容+位置+字体+颜色，
   并补一句「除此之外画面里不要出现任何其他文字、水印和logo」。
6. **交付后用 run_shell 核对**：`file -b xxx.jpg` 拿真实像素尺寸，别凭记忆写。

## 画幅与尺寸

- 模型默认输出比例受 prompt 里画幅词影响，**也受历史出图比例影响**：
  先出横图后要竖图时，画幅词（「竖构图」「横构图」）必须写在 prompt 最前面。
- 实测尺寸：横 2368×1776 / 2496×1664 / 2816×1584，竖 1584×2816、1776×2368。
- 要精确尺寸就交付后用 ffmpeg 裁切，别指望模型听话。

## 验证与交付

- **默认不开图核验**（用户明确说过「别看图了，直接生成」；且视觉模型渠道不稳定，常超时/额度报错）。
- 主动告知用户「未开图核验」，并**点名最容易翻车的地方**让他重点看：
  手部（多指/断指）、面部扭曲、画面内指定文字是否写对、多格拼接的背景一致性、特殊坐姿/趴姿的肢体结构。
- 生成后如实报尺寸、如实报是否被版权拦截过、如实说明「脸是模型生成的，不是原演员本人」。
- **绝不带 AI 水印**（用户明确要求，渠道已接受 watermark=false）。

## 进阶：带排版结构的图

用户要「海报」「拼贴」「多格」「带歌名字幕」这类**带版式**的成品时：
生图负责出画面，**文字和分格改用 HTML 排版 + html_to_image 截图来叠**，
成品干净可控得多，也不会出现生图把中文字写糊的问题。
先出画面，再问用户要不要走这条升级路线。
