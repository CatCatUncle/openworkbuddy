# 数据分析

## 适用场景
用户丢来一个 CSV / Excel / 一堆日志，问"帮我看看这份数据"、"为什么这个月掉了"。

跟 `data-viz` 的分工：那份管**怎么把图画好看**，这份管**先算对、先看出东西来**。画图时去读那份。

## 步骤

### 1. 先看清楚这是什么数据，再动手
`read_document` 读 Excel，`run_node` 读 CSV。**先打印前 20 行和每列的类型/缺失率**，
别上来就聚合——列名叫 `amount` 的那一列里混着 `1,200` 和 `¥1200` 和空值是常事。

给用户一句话说清：多少行、几列、时间范围是哪到哪、哪几列有缺失。

### 2. 清洗，并且把清洗动作记下来
常见的坑，逐个检查：
- 数字被存成文本（千分位逗号、货币符号、全角数字）
- 日期格式混用（`2026/9/1`、`2026-09-01`、Excel 序列号 46266）
- 重复行（同一订单号出现两次）
- 单位不统一（元和万元混在一列）
- 空值到底是"没有"还是"是 0"——**这两个意思完全不同，弄反了结论就反了**

清洗掉多少行、改了什么，写进报告里。删了 30% 的数据却不说，是造假。

### 3. 算：先看整体，再拆维度，最后找异常
```
整体   → 总量、均值、中位数、分布（均值和中位数差很多 = 有长尾，别只看均值）
拆维度 → 按时间、按地区、按渠道、按客群各切一刀
找异常 → 哪几天/哪几个客户贡献了大部分变化
```
**归因要落到具体的行**："9 月下滑 12%"没用，"9 月下滑 12%，其中 9 个点来自华东区
的 3 个大客户续费延后"才有用。

### 4. 别算这些
- 样本不到 30 就做显著性检验
- 相关性直接说成因果（"广告花得多所以卖得好" ≠ 数据支持）
- 环比和同比混着说（春节、双十一会把环比彻底搅乱）

### 5. 出图：一个结论一张图
用 `gen_diagram` 的 `kind:"echarts"`。图的标题直接写结论
（"华东区 9 月续费延后拖累整体 9 个点"），不要写"各区域销量图"。

### 6. 交付
写 `分析报告.md`：

1. **结论**：3-5 条，每条一句话，带数字
2. **怎么算的**：数据来源、清洗动作、口径定义（"活跃"指的是什么，说清楚）
3. **分维度详情** + 图
4. **异常与存疑**：对不上的、数据本身有问题的
5. 需要的话把清洗后的数据另存一份 `.xlsx`，用户能自己接着看

分析脚本也留在工作目录里，下个月同样的数据能直接重跑。

## 红线
- **不许猜数**。缺失就是缺失，不要用均值填充之后当真数据讲。
- **不许只报统计量**。"标准差 14.7" 不是结论，"波动主要来自周末" 才是。
- 结论跟数据打架时，先怀疑自己的清洗，再怀疑数据。

## 质量标准
- 每个结论都能指回具体的行或切片
- 口径写清楚，别人拿同一份数据能算出同样的结果
- 有一节专门写这份数据不能回答什么
