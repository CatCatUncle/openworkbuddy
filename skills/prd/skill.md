# 需求文档技能

## 判断标准只有一个

**开发看完能不能开工，测试看完能不能写用例。**
不能，这份 PRD 就是没写完，不管它有多少页。

「提升用户体验」「优化交互流程」「打造闭环」——这类词一个都不要出现在正文里。

## 1. 先搞清楚在解决谁的什么问题

动笔前必须有答案：

- **谁**在用？（不是「用户」，是「每天要处理 50 单以上的客服」）
- 他现在**怎么做**这件事？现在哪里难受？
- 做了这个功能，什么数字会变？变多少？

这三条答不上来就先用 `ask_user` 问，不要先写功能列表。
用户给了调研记录、竞品截图、会议纪要的，`read_document` / `transcribe_audio` 先读进来。

## 2. 结构

```markdown
# <功能名> PRD
版本 v1 ｜ 2026-09-13 ｜ 需求方：运营部 ｜ 状态：待评审

## 一、要解决什么问题
**现状**：客服每天手工把 50+ 订单从后台复制到 Excel，平均耗时 90 分钟。
**问题**：耗时、易错（上月因抄错发错货 3 单）。
**目标**：导出耗时降到 5 分钟内，抄录错误归零。

## 二、做给谁用
主要用户：客服专员（约 12 人，日均处理 50-80 单）
使用场景：每天下班前统一导出当日订单交给仓库

## 三、功能需求
### 3.1 批量导出
| 项 | 内容 |
|---|---|
| 入口 | 订单列表页右上角「导出」按钮 |
| 前置条件 | 已登录，且有「订单-导出」权限 |
| 主流程 | 1. 勾选订单（支持全选当前筛选结果）<br>2. 点导出 → 选字段 → 确认<br>3. 生成 xlsx 并下载 |
| 边界 | 一次最多 1000 条；超出提示「请缩小筛选范围后再导出」 |
| 异常 | 生成超过 30 秒 → 转为后台任务，完成后站内信通知 |
| 权限 | 无权限时按钮置灰，hover 提示「需要订单导出权限」 |

### 3.2 ...

## 四、不做什么（本期范围外）
- 定时自动导出 —— 二期
- 导出为 PDF —— 不做，仓库只收 Excel

## 五、验收标准
| # | 场景 | 预期 |
|---|---|---|
| 1 | 勾选 10 单点导出 | 5 秒内下载到 xlsx，行数=10，字段与所选一致 |
| 2 | 筛选出 1200 单点全选导出 | 提示超限，不发起请求 |
| 3 | 无导出权限的账号 | 按钮置灰且有提示 |

## 六、埋点
- `order_export_click`：点击导出，参数 = 选中条数、来源筛选条件
- `order_export_done`：导出成功，参数 = 耗时、条数

## 七、待确认
- 导出字段默认勾选哪些？需要运营给一份清单（09-18 前）
```

## 3. 每个功能点都要写全五样

**入口、前置条件、主流程、边界、异常**。少一样开发就会来问你一次，或者更糟——自己猜一个。

边界和异常是最容易漏也最费返工的：空状态长什么样？数据量到上限怎么办？网络断了点两次会不会重复？
没有权限的人看到什么？这几个问题每个功能都要回答一遍。

## 4. 「不做什么」这一节不能省

写清楚本期不做的事，比列做什么更能防止扯皮。
每一条还要说明是「延到二期」还是「决定不做」——这两个对开发的架构决策影响完全不同。

## 5. 交付

写成 `.md` 或 `.docx`。评审要发给多方就 `send_email`（记得带上原型图/截图作附件）。
定了评审日期的，顺手 `schedule_task` 排一条提前一天的提醒。

## 红线

- **不许写没有验收标准的功能点**。写不出验收标准，说明这条需求自己还没想清楚。
- **不许用「等」「等等」「相关的」收尾**。「支持导出订单号、金额等字段」——等哪些？开发会问，不如现在写全。
- **不许替业务方定关键规则**。定价、免费额度、审核标准这类，用 `ask_user` 问，或者列进「待确认」，不要写一个看起来合理的数进去当既定事实。
- **不许把竞品截图里的文案当成自己的需求**抄进来，参考归参考。

## 质量标准

- 随便挑一个功能点，五样（入口/前置/主流程/边界/异常）都在
- 验收标准能直接变成测试用例，每条都有明确的预期结果
- 「不做什么」不为空
- 第一节的目标里有一个可量化的数字
- 全文没有一句删掉也不影响开发的话
