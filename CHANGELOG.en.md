- **Sep 22** **A long session has to be compacted first, and for those ten-odd seconds the screen said nothing.** Compaction is itself a call to the model, and it sits between **pressing send** and **the first token** — with nothing on screen, all you see is a spinner that won't say what it is doing, and you are left guessing whether the model is stuck or the network is down. - **Sep 22** **The "vision model" slot in settings was pushing aside a main model that could already see.** The old rule had exactly one condition — is that slot filled? — and a filled slot always bypassed the main model. A wrong tick doesn't cost you the image either: when the main model answers 400 "doesn't support images", the dedicated channel takes over and the answer says where to untick it. - **Sep 21** **To connect a model server of your own, the onboarding wizard made you pick "skip for now".** The preset vendors come with an official URL and a default model; a self-hosted gateway (an in-house vLLM, LM Studio on your own laptop, the company one-api box) has neither, and only you know what it serves — so the wizard's provider table filtered it out entirely, and the very first step pushed newcomers to "skip, I'll fill it in later under Settings", which means typing a URL, creating a channel and then adding a model, the easiest path to get wrong. - **Sep 20** On macOS the **downloaded app wouldn't open on a double-click**, and at least one person was stuck on 0.6.2 because of it. - **Sep 19** Eval runs **no longer touch your real memory, preferences or quota ledger**, and the task set grew three shapes a single-turn task can't test. The harmful part first: eval used to share one data directory with normal use, so an agent that called `remember` mid-task wrote "the user prefers Firefox" straight into your long-term memory — and the next run was then influenced by what the last one wrote, which makes scores irreproducible and leaves you with memories from nowhere. The task set went 15 → 18: a **long-haul task** (12 order files, the spec hidden in one of them, 40+ steps) asks whether a rule read at step 3 still holds at step 30 — the spec has to live in a *file*, because the prompt sits at the head of the history and survives trimming while the tool output in the middle is what gets dropped; a **multi-turn task** runs three turns with the format rule stated once, in turn one, and never repeated; a **memory-recall task** seeds the rules into long-term memory and mentions none of them in the prompt, plus two deliberately irrelevant seeds, to see whether it forces unrelated memories into the deliverable. Alongside it, a **free offline gate** (`node test/eval.js`, 100 assertions, zero model calls): feed every task's checks an empty directory and require that **not one of them goes green** — an agent that did nothing scores zero, so any check still passing there isn't grading, it's giving marks away. Finally, "changed a prompt or a tool description? run the eval" is now written into CONTRIBUTING, with the triggers spelled out (the agent.js system prompt, tool `description` text, skill prompts, trimming and memory-injection logic).
- **Sep 19** When two tasks change the same repo, **the later one gets its own git worktree** (`worktree.js`). The old isolation was one output folder per conversation — fine for document work, useless the moment the working directory is your own code repo: both tasks read the same `src/`, A changes a function to three arguments, B is still holding the two-argument text, and B's write erases A's change. Nothing errors, the tests may even stay green; what's broken is the version in between. The approach is Codex's: same `.git`, separate working copy, changes land on `owb/<session>`. Three deliberate limits: **only a collision triggers it** (one person with one task is the overwhelming majority, and dropping someone into an unfamiliar directory for no reason just means they can't find their files); **the first task is left alone** (it edits the tree in front of you, which is what you expect — the later one is the extra); and it **never merges back**. A few more things that would make the feature a lie if skipped: your uncommitted changes are **carried over** (not the `.gitignore`d ones, or an 800MB `build/` would ride along), because without them the second task sees a repo rolled back to the last commit and redoes work you already did; the work is **auto-committed** to that branch at the end, since uncommitted changes can't be merged and you'd follow the hint, run `git merge`, and find the branch identical to your own; a run that produced nothing is **removed on the spot**, directory and branch, or every collision would leave behind a branch nobody dares delete; and anything with work in it is **never deleted** — after 14 days only the directory goes, the branch stays. The collision list includes terminal runs (one web task plus one terminal task is the common case, and they're separate processes that see each other only through the `data/cli-live` ledger). The prompt states outright that the agent must not merge, rebase or push. Every failure mode (no git, no first commit yet, bare repo, patch won't apply…) falls back to the old behaviour in the original working directory with one log line, so a task never fails to start because of this. `openworkbuddy worktree` lists them; `openworkbuddy worktree 清理` sweeps the empty ones

- **Sep 19** A stuck task **stops itself** now instead of spinning until morning. There used to be two tiers, both of them nagging: three identical results in a row pushed a "try another route" note into the history, five in a row blocked one call. If the model ignored both, it spun on to the step or runtime cap — and what the user saw was "maximum runtime reached, wrapping up", which reads like the job was too big, so they raised the cap and the next run burned longer. The third tier is a **hard stop**, and it knows five shapes of stuck: the same call returning the same result 6 times, the same error text word for word 6 times (changing arguments doesn't help, so the arguments were never the variable), 12 consecutive failures, 4 calls into a channel that is already tripped, and `A→B→A→B` — a two- or three-step loop repeated 4 times with identical arguments and results, the one shape where no single tool looks repetitive and only the sequence gives it away. **This kind of stop never auto-continues** (the first thing a continuation would do is run the same loop again), and the closing line no longer suggests raising the cap — a bigger cap just buys more laps.
