## 2026

- **Sep 18** Clicking a file in the library now **lands on the exact exchange that produced it**, instead of reopening the whole conversation. Each file row grew a small speech-bubble button (it lights up when you hover the row), and the "from task" line is tagged with the round number. It used to just open the session and scroll to the bottom — on a task that ran a dozen rounds you still had to scroll back yourself, so the jump helped with nothing. The round number is counted from the **user entries in the transcript**, not from the array index: replay starts one round per user entry and the array has assistant entries interleaved, so an index is off by nearly 2× and would drop you on an exchange that has nothing to do with the file you clicked. A file edited across several rounds anchors to the **first** one — you clicked it to see where it came from, and that sentence is in the round that first wrote it. **When it can't jump, it says so**: old sessions never recorded rounds and transcripts can be trimmed, so the server invents nothing, the UI simply doesn't draw the button, and the old scroll-to-bottom behaviour stands. The landing round highlights briefly (with "reduce motion" on there's no fade — the tint is just there) — without a marker you only know "the page moved", not where to look.
- **Sep 18** **You can quote one reply and ask about it.** The action bar under a reply grew a "quote" button: it drops that reply's text into the composer as a `>` blockquote and you write underneath it. **Select part of it first and only that part is quoted** — a reply is often several screens, and quoting the whole thing points at nothing. Why the composer rather than an attached chip: a quote **has to be editable**. The real use is almost always "one sentence in here is wrong" — you keep that sentence and delete the rest. It takes the rendered body only: no progress cards, no button bar, no token counts. A half-written message isn't clobbered (the quote is appended after a blank line); pressing quote twice on the same passage doesn't insert it twice (it says it's already there); anything over 400 characters is truncated with an ellipsis — past that it's restating, not quoting, and the bulk drags the model off course.
- **Sep 18** Fixed three icons that were **rendering as empty boxes**: "last run" in the automation list, "skill and connector scan" in security settings, and "last generated" on the canvas. `<use href="#i-a-typo">` throws no error and logs no warning — the browser quietly draws a blank the same size as a real icon, and only someone staring at that one cell notices. Added a gate on the way out: all 379 hard-coded icon names in the UI are now checked against the sprite (each page has its own, checked separately), and the 78 built from variables are reported as a count rather than pretended to be covered.
- **Sep 18** Added the **Jev decision model** (TypeSafe System One). It doesn't write prose — it returns a chosen option, a score, or a probability, plus how sure it is. It is deliberately *not* in the model dropdown: a chat model takes prose and returns prose, while this one takes a state plus a **typed** question, so putting it there would 400 on every call. It gets its own path instead: `openworkbuddy jev` on the CLI, `/api/decide` over HTTP, and the "test it" button on a channel in settings (which knows better than to ping a decisions model at the chat endpoint). **If you already use OpenRouter, nothing to configure** — the key you have works. The first real use inside the product is **Goal-mode verification**: it used to ask a chat model to emit `{"results":[…]}` against the acceptance criteria, which is asking something that writes prose to imitate a table — it occasionally answers off-format and a whole round of checkboxes stays frozen. Now each criterion is one yes/no question whose shape cannot drift. More importantly there is now a confidence: **a box is ticked only above 70%, and anything below stays unticked with the card saying "not sure" rather than "not done"** — the way this card misleads people is that once a box is ticked, nobody looks again. On a machine without this model configured it falls back to the old path silently, byte for byte. Quota is metered **per question**, not per request (one request carries up to 32 questions, so a per-request gate would gate nothing); output tokens are free and a three-question round costs about $0.00002.
- **Sep 18** The sidebar's **task history now searches the conversation itself**, and by meaning. The magnifier used to filter titles only — but titles are auto-written when a task finishes, and nobody ever reads them. What people remember is the sentence they typed ("pull the duplicate rows out of this csv") or the file they got back ("cleaned.xlsx"); a title filter finds neither, so you open sessions one by one and give up around the fifth. It now matches three ways and **labels every hit with which way found it**: title / produced file / in the conversation / close wording / similar meaning. Without the label, the semantic hits look like unrelated tasks appearing out of nowhere and people conclude the search is broken. Typing filters titles locally at once rather than waiting on the network (waiting leaves the list empty, and an empty list looks exactly like "no matches"); the server pass lands 300ms later and takes over. If that request fails, it falls back to the local title filter **and says it failed** instead of passing it off as "nothing found" — those are two different things. With no embedding channel configured, the result says plainly that the "similar meaning" pass did not run; no silent downgrade. The CLI's `/resume` gets the same: `/resume duplicate rows` reattaches a session whose title contains none of those words, and a row matched only through the body is tagged "in the conversation". Search still goes through the same ownership filter — **a session you cannot see in the sidebar cannot be found by searching either; search is not a back door around ownership**.
- **Sep 18** The picker grew a **search box**, and it is always there. It used to echo the query after the title once you had typed something — so nobody who had not already typed knew it could search at all; "type to search" lived in the footer, in the middle of a row of key hints, where a line of prose goes unread. The box now sits at the top from the first frame, saying what it filters on while empty (`/resume`: titles, session ids, origin; `/model`: model name and vendor), echoing what you type with the caret following along. **A search that matches nothing keeps the words you typed** — clear the box and there is nothing left to tell you what to backspace. The footer dropped "type to search" on the way: the box is right there, and saying it twice only makes the key hints longer.
- **Sep 18** Picking up an earlier conversation in the terminal went from counting numbers to choosing. Bare `/resume` opens a picker: ↑↓ to move, type to search live (titles, session ids and origin are all searchable), Enter to attach, Esc to forget it — sessions started in the desktop app are in the same list, each row carrying where it came from, how many turns it ran and how long ago. It used to print a numbered table to type a number into, and a number has to be counted by eye: one row off and you attach **a different conversation**, which you only discover when the next answer makes no sense. `/model` uses the same picker, so the two commands share one interaction rather than growing two. Longer lists scroll with the selection always kept on screen. **In a pipe, or on a terminal that cannot paint an overlay, both fall back to the old numbered table** — sharing the one "this terminal can't do it" switch with the `/` menu, because half the interaction beats a scrambled terminal.
- **Sep 18** Three long-missing commands. `/compact` folds the earlier turns into a summary by hand — **the manual one ignores both the threshold and the "auto-compact off" setting**, since that setting means "don't do it behind my back", not "I'm not allowed to"; the originals are still archived, and it reports "12 turns into 1, context 100k → 40k, 60% back" — or says plainly that it compacted nothing rather than hiding behind "below threshold". `/diff` lists the files this session touched, **counted from tool calls rather than from what the model said it did** — a model that claims an edit without ever calling `write_file` exists, and taking its word for it means covering for it; files deleted since are still listed, marked gone. In a git repo it adds `git diff --stat`; outside one it says so, so nobody thinks the diff is broken. `/mcp` reports which connectors are up and how many tools each brought, and **why the others are not** (an expired token says expired token) — a bare cross just makes people restart a hundred times.
- **Sep 18** `/init` has it read the current working directory and write an `AGENTS.md` at its root: what the project is, how to run it and test it, which directories are the trunk, which conventions are already settled. Both the desktop app and the CLI read that file before every run, so how accurate it is decides how well the next few dozen runs go. **It does not write the file itself — it hands the request back as an ordinary task**, so the permission mode, the confirm-before-editing step and the `/diff` record all still apply; a command that silently leaves a new file on your disk with nothing asked in between is exactly the mistake this kind of command invites. Two things are pinned in the wording: copy the commands you actually found in `package.json` or the docs (otherwise it invents an `npm test` this project may not have), and only write down conventions you found evidence for. If an `AGENTS.md` or `CLAUDE.md` is already there it reads it first and adds to it — **never overwrites** — because that one was probably written by hand.
- **Sep 18** Two key bindings, so switching a mode is not a command. `Shift+Tab` cycles this run's permission level (read-only → ask every step → edit files → back round), printing which level and what it means each time, and **touching nothing in the config file**. **The cycle does not reach "full auto"**: that key sits next to Tab, one mis-hit would switch off command confirmation while you are looking at your own half-typed line — full auto has to be typed as `/perm full`. `Esc Esc` lists what you already asked in this session and puts one back on the input line to edit and re-send. It **only puts it back; it does not rewind history**: deleting turns that already ran erases work the model did with nothing on screen to show for it — start over with `/new`, attach elsewhere with `/resume`, both in the open. One fix rode along: `/d` is nobody's shorthand any more, since `/diff` and `/drop` both start with d and claiming it means choosing for someone who typed one letter.
- **Sep 17** When a task finishes, it asks whether to clear out the intermediate files it just made. One short-film task splits out hundreds of frames, one soundtrack separates into four stems, one build spits out a `node_modules` - and once the cut has been delivered all of that is still sitting in the workspace, quietly costing gigabytes a month that nobody ever goes looking for. The end of a run now carries a card: "this run made N intermediate files, XX on disk", grouped by where they came from (extracted frames, separated stems, build output, scratch and temporary files, one-shot scripts), each group saying **why it is safe to delete** (the cut is still there, the original audio is still there, the `package.json` is still there, this is a script that was run once) - tick what you want, press once, and "keep them for now" does nothing at all. The same entry is pinned to the "Give me the work" home screen with the current figure written on it, because something you do this often has to be within reach: a cleanup buried in Settings may as well not exist. **The panel is deliberately two halves**: the top is what I am confident is scratch (deletable, each line carrying its reason), the bottom is where the space actually went - usage per task, reported and not judged. The real weight on the disk is usually the three-week-old video task's finished cut, which no rule will ever touch, but you cannot decide about it until you can see it; every row there can be narrowed to "tidy just this task" or opened in Finder. **The red line**: `apply()` only accepts paths that this round's own `plan()` proposed and refuses everything else - including a `../../users.json` or `/etc/hosts` posted straight at it - because this is an endpoint that deletes files, and outside that allow-list there should be no second way in. Deliverables (the cut, the report, the delivery note) take part in no rule at all; a directory only counts as build output while its `package.json` is still there; a `.py` inside a source tree is not a one-shot script; one batch of wav files is reported once rather than counted twice by two rules. Delete means delete rather than a move to `.trash`, because moving the same bytes somewhere else is not the space back - and every deleted path goes into the audit log, so who cleaned what, and when, is still answerable afterwards
- **Sep 17** The library stopped handing you a screenful of rows that answer "this file no longer exists" when you click them, and it now treats the two causes differently. **Files the upgrade moved are followed, not hidden**: `migrate.js` sweeps loose files older than a day out of the workspace root into a dated archive folder, and afterwards the library was still looking up the bare filename it had recorded — a whole batch of files sitting perfectly well on disk were reported as gone when they had merely moved one level down. They are now reported at their new path, so a click actually opens them, and they are claimed on the way so the same file no longer shows up a second time under "unclaimed". Not searching the whole workspace by filename is deliberate: two task folders each hold a `cover.png`, a search would likely hand back the other one, and "that is not the image I asked for" is harder to notice than "it is gone"; the new path is only trusted under the *current* workspace root, because it is about to be used as an address — finding a namesake under some other root and handing back an address that will not open is worse than saying the file is gone. **Files that really were deleted stay hidden by default**: one video task splits out hundreds of frames and cleans them up after the analysis, and every such row is a claim that a file is there, paid for with a click that gets nothing; a task whose whole output is gone does not appear at all, since an empty shell you can only click into a "no such file" is worth less than nothing. Nothing is swallowed silently — a line underneath says how many are left out and brings them back in one click (struck through, marked gone), and the choice is remembered in localStorage.
- **Sep 17** Every API the company buys now goes through one door, and neither staff nor other programs touch the real keys any more. Upstream keys are entered once in the admin page; what goes out is a virtual key beginning `sk-`, speaking plain OpenAI on the wire — nobody's code changes, only the `base_url`. **Not just chat**: `/v1/chat/completions`, `/v1/embeddings`, `/v1/images/generations`, `/v1/videos/generations`, `/v1/audio/speech`, `/v1/audio/transcriptions` and `/v1/search` all pass the same gate — a company never buys chat alone, and the capabilities left outside the gate are exactly the expensive ones (video is billed by the second). Each key carries its own capability switches: an image-only key that calls speech gets a 401 on the spot, and `/v1/models` does not even list the chat models for it — every id in that list is a promise that you may call it, and a promise that answers 401 sends the developer on the other side digging through their own code before they find the switch. Generated images and clips land at `/v1/files/<id>/content`: they expire in 24 hours and are deleted on expiry, and another tenant fetching that id gets a **404, not a 403** — a 403 would confirm the id exists. The real key is only ever assembled into the upstream request in memory; it appears in no log and no response. Virtual keys are stored hashed, the UI shows the last four characters, and a lost one is reissued rather than recovered.

- **Sep 17** The relay bills the way each vendor actually sells, and the quota is a gate rather than a report. Chat is metered per token (yuan per million, against a built-in price list current to 2026-09-17, USD converted at 7.1); the other four go by their own units — images per picture, video per second, speech per thousand characters, transcription per minute. Folding all of them into tokens would make the numbers look wonderful, and the invoice at the end of the month would not follow. Prices layer three deep: built-in → what the admin edited → what one channel overrides. The admin table edits a single capability-plus-model row, takes effect on save, and every row says whether that price is the built-in one or yours; an auditor can read it and cannot write it, since editing that table is editing every figure on the page down to zero. Anything whose price cannot be computed — a model that shipped last week — is recorded in its own "cost unknown" column and **never as 0**: the moment it is written as 0 the money is unrecoverable. The quota reserves before the call and settles after it, and going over returns 402 `insufficient_quota` there and then. Three levels of cap — organisation, department template, single key — where 0 means unlimited. **What your staff run from the UI, and what the scheduler runs overnight, come out of that same budget**: only the outbound path used to pass the gate, and the half that leaked was the half with a Retry button on it. The message names whose budget ran out — "the whole organisation is out of budget this month, not just you: cap ¥2.00, spent ¥2.10" — because a message that doesn't will be read as bad luck and clicked again.

- **Sep 17** Source files in the workspace now render as code: a line-number gutter that stays put when you scroll sideways, five-colour highlighting, and — the part that mattered — **no wrapping**. They used to fall through to the plain-text `<pre>`, which is tuned for logs and prose: `white-space: pre-wrap` plus `overflow-wrap: anywhere` keeps a long URL from stretching the panel, but the same rule applied to code breaks words at *arbitrary* points — `fun` on one line, `ction` on the next. That is what "looks like mojibake" meant: every character correct, every break wrong. Bundler output is worse still — a rolldown/esbuild `.mjs` is routinely one line of fifty thousand characters. So when a file looks minified (longest line over 400 characters) it is laid out for you by default: broken at `{` `}` `;`, indented by bracket depth, with a banner naming the longest line's length and a "show original" toggle beside it. The reformat only inserts newlines and indentation — not one character changes, and nothing is written back to the file. It **deliberately does not build an AST**: bundler output contains every strange construct there is, and a parser that meets one gives up on the whole file, whereas a scanner that only understands strings, comments and regexes can at worst break lines in ugly places without ever losing content. Those three it must understand — the braces in `var q="}}}"` are not structure, the slashes in `/[/{};]+/g` are not a comment, the semicolons in `for(let i=0;i<3;i++)` are not statement ends — and each has its own test. Highlighting covers six language families (C-like / `#`-comment / JSON / CSS / tag markup / SQL), with colours measured against the dark `#16181f` background (comments went from 3.1 to 5.2 contrast — a comment is there to be read, not to hide). Past 5,000 lines only the first 5,000 are drawn, and the banner says so (the file itself is untouched; download it and it is complete)

- **Sep 17** Skills get screened before they're installed. A skill's body *is* a set of instructions aimed at the agent, and the agent has a shell — install one from a link and it will be followed on the next task. So everything is scanned first: a directory, a single `.md` from GitHub, or text you pasted into the box yourself — all three go through the same gate. Three verdicts: **clean** installs; **worth a look** (outbound hosts, dependency installs, reading environment variables) shows you the actual lines and asks once more; **don't** (`curl | bash`, reading `id_rsa`, rifling `~/.aws`, `rm -rf ~`, reverse shells — 10 rules in all) is blocked, and only a platform admin can override, which is written to the log *and* to `.install.json` inside the skill folder: which repo, which commit, who waved it through, what the scan said. No score: of 34 rules only 10 can block and the other 24 only ever warn, because nobody can answer "it scored 7.5, do I install it?". It reads combinations, not keywords — `printenv` on its own means little; `printenv` next to an outbound address means something — and a line preceded by "don't" / "never" is ignored, since "never use `curl | bash`" is security advice, not an attack. A warning inside the frontmatter is escalated to a block, because `description` is injected into the system prompt of **every** task, so a sentence hidden there runs around the clock. **What it misses is stated too**: static scanners of this kind catch roughly three quarters on public benchmarks — one in four gets through — and on this repo's own 34 skills the false-block rate measured 5.9% (2 skills, both genuine literal matches rather than phantom hits). That number is pinned in the test suite, so a future rule change that starts over-blocking turns CI red instead of surprising someone mid-install.

- **Sep 17** Skill and connector screening can borrow a second ruler from outside: with [toolward](https://github.com/CatCatUncle/toolward) installed on the machine (another project by the same author — 37 rules in six families: prompt injection and tool poisoning TW1xx, supply chain TW2xx, secrets TW3xx, execution and permissions TW4xx, network and exfiltration TW5xx, governance TW6xx), installing a skill or saving a connector runs a second pass, and both sets of findings land in one list with each line labelled by who said it. `.install.json`, the override record and the explanation text did not change by a single character, because the external report is shaped **exactly like** the built-in scanner's: the gate, the explanation and the on-disk record needed no edits at all — only a `merge()` at each of the three install entry points. Merging **only ever tightens**: what it blocks is blocked, what it doesn't mention keeps the original verdict, so bolting it on can never turn a block into a pass (there is a reverse assertion watching that). **Not in `package.json`, and never `npx`-ed**: toolward is PolyForm Noncommercial 1.0.0 — free for personal, teaching, academic, charity and government use, a company needs a separate licence (see the LICENSE in the toolward repo) — and quietly attaching a licensing obligation to every commercial user of this project is not a thing to do on their behalf; meanwhile `npx -y` fetches an unaudited version on every run, which is exactly the behaviour its own TW2xx family flags, and doing that while auditing the supply chain does not hold up. So it only uses the binary you installed yourself with `npm i -g toolward` (Electron's PATH is stunted, so a few usual directories — `/opt/homebrew/bin`, `~/.volta/bin`, `~/.bun/bin` — are checked too), or one exact path pinned in Settings, which then never falls back to PATH, so "I thought it was running the build I compiled" cannot happen. **A crash is not a block**: a timeout (20s), a bad exit code, or output that isn't JSON all report "it never ran" rather than "it found nothing" — the latter is a lie that would print "clean" on screen. Repeated failures also buy a five-minute cool-off, so a broken binary doesn't cost 20 seconds per install. On the connector side it only advises, never blocks, and **the `.mcp.json` handed to it carries none of your keys**: every `env` and `headers` **value** becomes `***` while the key names stay (they are what lets it see "there is a token field here"; replacing the names too would make every correctly configured connector look like a plaintext secret), URLs are cut back to their path with the query dropped, and `command` and `args` pass through verbatim, since those are the fields that actually reveal an unpinned `npx` package or a semicolon chained into a command — the test has a fake toolward echo back the temp file it was handed, and the real key is checked character by character not to be in it. The whole thing has an `OPENWORKBUDDY_TOOLWARD=off / advisory / auto` switch (the environment variable wins over the setting), and the test suite turns it off by default: otherwise a machine with toolward installed globally would quietly change skill-guard's own 76 assertions, and green would depend on what the developer happened to have installed

- **Sep 17** The film can carry a music bed: drop an "Audio" node on the canvas with its purpose set to "BGM" / "Score" and the compose panel gains a "lay music underneath" checkbox — with the track it picked named right next to it (when several pieces of music sit on the board, mixing in the wrong one costs you the whole render). The music ducks while someone is speaking (only where this machine's ffmpeg has `sidechaincompress`; otherwise it sits at a fixed level, and you are told before the run starts, not at the last command). A track shorter than the film loops; a longer one never leaves seconds of black at the end. And the dialogue does not lose a single dB: ffmpeg's `amix` divides every input by 2 by default, which is the quietest way to make a whole film's dialogue half as loud — so the voice is boosted back first and the mix goes through a limiter.

- **Sep 17** The `wb` short form is gone from the repo for good — the earlier rename only touched the command name and left everything else behind. Environment variables `WB_*` → `OPENWORKBUDDY_*` (`WB_HOME` names a host directory, which is not the container's `OPENWORKBUDDY_HOME`, so it became `OPENWORKBUDDY_DATA`), the Docker data directory `wb-data/` → `openworkbuddy-data/`, backup filenames `wb-backup-*.tar.gz` → `openworkbuddy-backup-*.tar.gz`, the login cookie `wb_token` → `openworkbuddy_token`, and the browser-local keys and CSS tokens `wb-*` / `--wb-*` → `owb-*` / `--owb-*`. One mismatch fixed along the way: the REPL help still printed `wb>` long after the real prompt became `openworkbuddy>`. **Two things to do when upgrading**: on a Docker install rename the directory (`mv wb-data openworkbuddy-data`) and re-copy the variable names from `deploy/env.example`; and everyone signs in once more, because the cookie changed name. Nothing else is manual — the sidebar's task history migrates itself, and existing backup archives are still recognised and still listed.

- **Sep 17** The `context 87%` bar above the composer no longer follows you into the next conversation. There is only one such bar for the whole UI and it is only repainted when a running task emits an event — switching to a conversation that hasn't started yet leaves nothing to wait for and nobody to clear it, so the previous conversation's line ("it'll be compacted before the next round") stayed on screen pointing at somebody else's number: a brand-new, empty conversation looked nearly full. All three ways of changing conversation (history, following a terminal run, starting a new task) now clear it first and let the conversation's own replayed number fill it back in. The other half is closed too: a conversation running in the background no longer paints its budget onto the one you are looking at.
- **Sep 17** Another wall between branch offices. When a file is looked up by relative path, the fallback pass sweeps **every workspace directory the server remembers** — including other branches' — so someone in a branch could read head-office files with nothing but a filename, or by pasting another directory's fingerprint into the URL. Candidate directories now pass a tenant filter first and anything outside the tenant is refused. Lookups across sub-projects within one tenant still work, and the personal install (no login — Feishu callbacks, cron jobs) takes exactly the old path.

- **Sep 17** Execution traces stop sharing one name. The label used to come from the **first** user message of the conversation, but one turn opens one trace and the whole history is what gets passed in — so ten turns in one session produced ten identical rows, and you had to open each to tell them apart. It now takes the **most recent message that actually says something**, skipping filler like "go on" / "ok" / "sure" (but not "go on and wire up the logs" — that is a real request), and every row is tagged with its turn number so even similar names stay distinguishable. **Traces already on disk are split apart too**: the ledger is not rewritten, but each record still carries the full input it was created from, so it is re-derived on read — and only when the record carries the old rule's fingerprint (the name ends exactly with the history's first message, and there is more after it). A name you chose yourself cannot match that, so it is never touched.
- **Sep 17** Forgot your password, and lost the phone with your 2FA codes? You no longer have to wait for an admin. On the server itself, `openworkbuddy passwd <user>` prints a fresh random password (or takes the one you supply), and `openworkbuddy 2fa <user>` shows two-factor status with `--off` to turn it off. Either way every session that user has open is revoked on the spot. **Neither is exposed over HTTP, ever** — the authority here is "you can read `users.json` on the server", which is already the highest privilege there is; adding a network endpoint would only give it away.
- **Sep 17** Onboarding and offboarding are each one step now, and each prints a receipt. Offboarding closes everything at once: account disabled, every session token revoked, paired phones and tablets knocked offline, unused invite codes they issued revoked, two-factor unbound, and their scheduled jobs stopped and optionally handed to a named successor (**still disabled after the handover**, so whoever takes over reads them before switching them on). Their conversations, output files, usage ledger and audit trail stay exactly as they are — the books still have to balance after someone leaves. Two guards against a slip: you cannot offboard yourself, and you cannot offboard the org's last active admin (nobody could get into the console afterwards). Onboarding applies a department template — role and monthly quota — so hiring the third person into a team does not mean remembering how the first two were configured.
- **Sep 17** You can see what is happening now: runtime logs land on disk daily and rotate on their own so they cannot fill the disk (still redacted — keys do not leak out through the log), and a snapshot of the key metrics is rolled every minute — request volume, latency percentiles, failure rate, spend per channel — on one page under Settings → Operations, with alerts pushed to WeCom / DingTalk when a line is crossed. One alert per rule per 30 minutes, and **recovery is announced too** — a system that only ever cries wolf gets ignored inside two weeks. Percentiles switched to nearest-rank: with few samples, interpolation reports a P95 that **never actually happened**, and it always looks better than reality.
- **Sep 17** The usage ledger is sharded by month, which also fixes an old design that **silently under-counted**. It used to be one `usage.json`: every entry meant reading the whole book, inserting a row and writing it all back — capped at the newest 2000 rows. Fifty people at ten calls a day **hit that ceiling in four days**, after which "usage this month" and "who is using it" quietly under-reported, with no error anywhere. Entries are now one line appended to `data/usage/2026-09.jsonl`; append cost is independent of history length (the old path took 262ms at 100k rows, paid at the end of every single task), "this month" reads one shard, and there is no cap any more — what a cap throws away is billing and audit data. An existing `usage.json` is split apart the first time the ledger is touched; it is **not deleted**, just renamed `.migrated` and left in place so you can reconcile. Execution traces got rotation in the same pass (six files kept, roughly a 144 MB ceiling).
- **Sep 17** The two remote doors each got a switch, and **both are off by default**: "allow pairing remote devices" (a phone, a second computer) and "allow driving a running terminal task from the web or a phone". Left on by default, somebody may not realise what they just exposed to the office LAN. The switches live in the org settings, and **turning one off knocks already-paired devices offline on their next request** — otherwise the switch is a lie: you think the phone is disconnected and it is not.
