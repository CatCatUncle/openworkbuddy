# 命令行用法

CLI 跟桌面版共用同一份配置、同一批技能和 MCP 连接器——`~/OpenWorkBuddy/config.json` 改一次，两边都变。区别只在外壳：这边没有窗口，答案直接落到 stdout，可以塞进任何管道和脚本里。

```bash
npm run cli -- "帮我写一份本周周报"
```

嫌前缀长就做个短命令：

```bash
echo 'alias wb="node /你的路径/openworkbuddy/cli.js"' >> ~/.zshrc && source ~/.zshrc
```

下文一律写 `wb`。

## 三种跑法

```bash
wb "把 logs/ 里今天的报错归个类"     # 单发：跑完就退，退出码说明成败
wb                                   # 交互式：像聊天窗一样连着问
cat error.log | wb "这是什么问题"     # 管道：内容作为附加材料一起送进去
```

## 选项

| 选项 | 作用 |
| --- | --- |
| `--mode craft\|plan\|ask` | 执行模式，默认 `craft` |
| `-C, --workspace <dir>` | 这次在哪个目录干活。**只影响本次**，不写回配置 |
| `-c, --continue` | 续接最近一次 CLI 会话 |
| `--session <id>` | 续接指定会话 |
| `--list [n]` | 列出最近 n 个 CLI 会话，默认 10 |
| `--json` | 事件按 NDJSON 打到 stdout，给脚本消费 |
| `-q, --quiet` | 只要最终答案，不打进度 |
| `--no-mcp` | 跳过 MCP 连接器，启动快几秒 |

## 交互式（直接敲 `wb`）

```
wb> 把 logs/ 里今天的报错归个类
```

十条内置命令，`/help` 一次全列出来：

| 命令 | 作用 |
| --- | --- |
| `/help` | 列出这些命令（也能写 `/?`） |
| `/mode craft\|plan\|ask` | 换执行模式；不给值就说当前是哪个 |
| `/new` | 开一个新会话。刚才那段不会丢，它会把旧 id 告诉你 |
| `/session` | 当前会话 id 和存盘位置 |
| `/status` | 模式、底层引擎、工作目录、这个会话跑了几轮 |
| `/model [序号或名字]` | 换这趟活儿谁来干：本机引擎或你配的模型；不给值就把能选的列出来 |
| `/cd <目录>` | 换工作目录。认 `..`、`~`、相对路径 |
| `/files` | 工作目录里现在有什么（也能写 `/ls`） |
| `/clear` | 清屏，会话和上下文都不动（也能写 `/cls`） |
| `/exit` | 退出（也能写 `/quit` `/q`） |

**`/model` 把两件事合成一张表。** 配置里「谁来跑」和「调哪个模型」是两个字段，可坐在终端前的人只关心一件事——这句话待会儿是谁回的。所以选单上半截是本机引擎（装了 Claude Code / Codex 就能选，花的是你自己的订阅），下半截是你配的模型（内置循环 + 你的 API Key），序号连着编，`/model 3` 或者 `/model kimi` 都认。

三条脾气：选了台机器上没装的引擎会**当场拒绝并告诉你怎么装**，绝不偷偷退回内置拿 API Key 去跑；从引擎切到模型时会**说一句**它顺手把底层引擎扳回了内置，因为不扳的话选模型不起作用；换完**只管这一趟**，配置文件一个字没动——要长期改去设置里的「模型」。

还有四件事值得知道：

**多行需求直接粘。** 贴进来的一整块会合成一条发出去，不会被拆成好几条、也不会只进去第一行。

**打错的命令不会被当成任务发给模型。** `/moe craft` 会当场停下来告诉你「你是不是想说 `/mode`」——不然那一行会被原样喂进去，模型一本正经地去执行一条不存在的指令，钱照花。想发一句本来就以 `/` 开头的话：**行首加个空格**，或者**写成 `//`**。以 `/` 开头的路径（`/Users/…`、`/etc/hosts`）本来就不会被当成命令。

**任务跑着的时候打字回车 = 插话。** 那句话会在下一步带给 agent，不用等它停下来。跟手机、网页上补的那句是同一个入口。

**Ctrl+C 停的是这趟活儿，不是退出。** 空着的时候连按两下才退出，`Ctrl+D` 也退。历史存在 `<数据目录>/data/cli-history.txt`，权限 0600，上下箭头能往回翻。


## 写进脚本之前，先知道这三件事

**一、每次单发都是干净上下文。** 想接着上一条继续，得显式 `-c` 或 `--session <id>`。这不是省事，是防串台：CLI 会把助手回复和工具结果追加进会话历史，如果多条命令共用一个会话，第二条任务会拖着第一条的全部上下文——既烧 token，又让模型在别的任务的阴影里答新问题。

```bash
wb "读一下 package.json，记住这个项目叫什么"
wb -c "那它依赖了哪些包"          # 这条才看得到上一条
```

**二、答案走 stdout，进度走 stderr。** 所以重定向出来的是干净的正文，不会混进「第 1 步 思考中…」：

```bash
wb -q "生成本周周报" > 周报.md     # 文件里只有周报
wb "跑一下测试并解释失败原因" 2>/dev/null   # 只看答案
```

**三、退出码说实话。** `0` 成功，`1` 出错，`130` 被 Ctrl+C 打断。所以 `&&` 串起来是安全的——上一步真炸了就不会往下走：

```bash
wb -q "检查 src/ 有没有明显的空指针风险" && echo "检查通过" || echo "有问题，别提交"
```

`-C` 指了个建不出来的目录会直接退出，不会默默退回默认工作目录——不然文件会写到你没想到的地方。

## 给脚本用：`--json`

每行一个 JSON 事件，最后一行一定是 `done`。常见类型：`step_start`（第几步）、`tool_use` / `tool_result`（调了什么工具、结果如何，同一个 `id` 配对）、`text`（正文，**按 `delta` 分块流式吐出**）、`usage`（token 账单）、`done`（收尾，带 `ok` 和 `session`）。

```bash
# 只要正文。注意用 -j 不换行，因为 text 是一小块一小块来的
wb --json "整理今天的会议纪要" | jq -j 'select(.type=="text") | .delta'

# 只看成败和账单
wb --json "跑个活" | tail -1 | jq '{ok: .ok, tokens: (.usage.prompt + .usage.completion)}'

# 盯它调了哪些工具
wb --json "把 logs 归个类" | jq -r 'select(.type=="tool_use") | .name'
```

## 跑不起来：`wb doctor`

什么都还没配好的时候也能跑——它就是用来查「为什么什么都没配好」的。

```bash
wb doctor
```

八项一次查完：Node 版本、依赖、数据目录、配置文件、模型渠道、端口、工作区、底层引擎。不合格的每条跟一句「怎么修」，能直接照着做。

两个细节值得知道：

- **有要处理的就退出码 1**，所以能写进安装脚本和 CI：`wb doctor && npm start`。
- **只报数不报值**——「12 个渠道，其中 7 个还没填 Key」，但一个 Key 的内容都不会出现。报告整段贴进 issue 是安全的。

端口那一条会分清两件相反的事：3800 上跑着的是 OpenWorkBuddy 自己（那叫「已经开着」，正常），还是别的程序（那才要去处理）。

## 常用几条

```bash
# 让它在别的项目里干活，不动全局配置
wb -C ~/code/another-repo "这个仓库是干什么的，读 README 和入口文件后告诉我"

# git 钩子里做提交前检查
wb -q --no-mcp "看看这些改动有没有明显问题：$(git diff --cached)" 

# 定时任务：每天下班前收个尾
0 18 * * * cd ~/work && /usr/local/bin/node ~/openworkbuddy/cli.js -q "总结今天 git log 里的进展" >> ~/日报.md
```
