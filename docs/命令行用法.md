# 命令行用法

CLI 跟桌面版共用同一份配置、同一批技能和 MCP 连接器——`~/OpenWorkBuddy/config.json` 改一次，两边都变。区别只在外壳：这边没有窗口，答案直接落到 stdout，可以塞进任何管道和脚本里。

```bash
npm run cli -- "帮我写一份本周周报"
```

嫌前缀长就做个短命令：

```bash
echo 'alias openworkbuddy="node /你的路径/openworkbuddy/cli.js"' >> ~/.zshrc && source ~/.zshrc
```

下文一律写 `openworkbuddy`。

## 三种跑法

```bash
openworkbuddy "把 logs/ 里今天的报错归个类"     # 单发：跑完就退，退出码说明成败
openworkbuddy                                   # 交互式：像聊天窗一样连着问
cat error.log | openworkbuddy "这是什么问题"     # 管道：内容作为附加材料一起送进去
```

## 选项

| 选项 | 作用 |
| --- | --- |
| `--mode craft\|plan\|ask` | 执行模式，默认 `craft` |
| `--score` | 配合 `openworkbuddy jev`：把后面那几个选项当成从低到高的档位，问一道打分题 |
| `--perm plan\|ask\|auto\|full` | 这一次放多少权，默认按配置里的（见下面「这一趟放多少权」）|
| `-C, --workspace <dir>` | 这次在哪个目录干活。**只影响本次**，不写回配置 |
| `-f, --file <路径>` | 带一个文件/图片一起问，可以重复写几次 |
| `-c, --continue` | 续接最近一次 CLI 会话 |
| `--session <id>` | 续接指定会话 |
| `--list [n]` | 列出最近 n 个 CLI 会话，默认 10 |
| `--model <名字>` | 这一次用哪个模型（配置里 models 的名字或型号 id），不改配置；认不出就停 |
| `--max-steps <n>` | 这一次最多走几步（1–500），默认按配置 |
| `--append-system <文字>` | 给这一次追加一段规矩，比如「只用 TypeScript」 |
| `--json` | 事件按 NDJSON 打到 stdout，给脚本消费 |
| `-q, --quiet` | 只要最终答案，不打进度 |
| `--raw` | 答案原样输出 Markdown，不在终端里渲染 |
| `--no-mcp` | 跳过 MCP 连接器，启动快几秒 |
| `--ask-remote` | 没人坐在终端前也允许 agent 提问，答案从手机上给（见下面「人不在电脑前」） |
| `--allow <规则>` | 这一趟预先点头的一类操作，可以写几次：`npm test`、`write`、`code`、`danger:git-force-push`（见下面「预先点头」） |
| `-V, --version` | 打印版本号 |
| `-h, --help` | 看帮助 |

子命令（动词式的写法，老选项一个没动）：

| 子命令 | 作用 |
| --- | --- |
| `openworkbuddy sessions [n]` | 列最近 n 个会话（桌面端开的也在里面） |
| `openworkbuddy resume [id] ["接着做…"]` | 续接会话；不给 id 就接最近动过的那个 |
| `openworkbuddy engines [use <id>]` | 看本机能拿什么当底层，或一键换过去 |
| `openworkbuddy doctor` | 跑不起来时先跑它，见下文 |
| `openworkbuddy pair` | 把手机/另一台电脑连上来，见下文 |
| `openworkbuddy passwd <用户名> ["新密码"]` | 忘了密码：在服务器上改回来，见下文 |
| `openworkbuddy 2fa <用户名> [--off]` | 看二次验证状态；手机丢了用 `--off` 关掉，见下文 |
| `openworkbuddy owner [用户名]` | 看谁是超级管理员；给用户名就把这个位子指给他，见下文 |
| `openworkbuddy review [基准分支]` | 把改动当别人的代码挑一遍毛病，只审不改；不给基准审还没提交的，见下文 |
| `openworkbuddy worktree [清理]` | 看有哪些「分身」：两条任务同时改一个仓库时，后来那条会去自己的 git worktree 里改，见下文 |
| `openworkbuddy completion <shell>` | 生成 Tab 补全脚本，见下文 |

## 交互式（直接敲 `openworkbuddy`）

```
openworkbuddy> 把 logs/ 里今天的报错归个类
```

二十一条内置命令，`/help` 一次全列出来：

| 命令 | 作用 |
| --- | --- |
| `/help` | 列出这些命令（也能写 `/?`） |
| `/mode craft\|plan\|ask` | 换执行模式；不给值就说当前是哪个 |
| `/perm plan\|ask\|auto\|full` | 换这一趟放多少权（只看不动/每步都问/自动改文件/全自动）；不给值就把四档摆出来 |
| `/new` | 开一个新会话。刚才那段不会丢，它会把旧 id 告诉你 |
| `/resume [序号或会话id]` | 接着之前那段往下聊（也能写 `/r`）；不给值就弹选择器，↑↓ 挑、打字搜 |
| `/session` | 当前会话 id 和存盘位置 |
| `/status` | 模式、底层引擎、工作目录、这个会话跑了几轮、一共花了多少 token（也能写 `/cost` `/usage`；查得到价的会给个约数） |
| `/init` | 让它把这个目录看一遍，写一份 `AGENTS.md`；以后每趟活儿都会先读它 |
| `/compact` | 把前面聊过的压成一段摘要腾地方；原文归档到 `data/compact-archive`，不删 |
| `/review [基准分支]` | 把改动当别人的代码挑一遍毛病，只审不改；不给基准就审还没提交的，给了就审这条分支从分叉起改的 |
| `/diff` | 这个会话动过哪些文件；工作目录要是 git 仓库，顺带出 `git diff --stat` |
| `/rewind [序号]` | 把这个会话改过的文件退回某一步之前（那一步和之后动过的一起退，新建的删掉、改过的恢复）；不给序号先列出能退的步。回退本身也留底，退错了再 `/rewind` 最新那一步就回来 |
| `/mcp` | 外部连接器接上了没有、各自带了几个工具、没接上是卡在哪儿 |
| `/model [序号或名字]` | 换这趟活儿谁来干：本机引擎或你配的模型；不给值同样弹选择器 |
| `/cd <目录>` | 换工作目录。认 `..`、`~`、相对路径 |
| `/files` | 工作目录里现在有什么（也能写 `/ls`） |
| `/open [名字或序号]` | 用系统默认程序打开产出（也能写 `/o`）；不给就打开工作目录 |
| `/paste` | 把剪贴板里的截图、文件或一大段文字带进来（也能写 `/v`） |
| `/drop` | 带上了还没发出去的文件、`!命令` 的输出，不要了 |
| `/clear` | 清屏，会话和上下文都不动（也能写 `/cls`） |
| `/exit` | 退出（也能写 `/quit` `/q`） |

**`/model` 把两件事合成一张表。** 配置里「谁来跑」和「调哪个模型」是两个字段，可坐在终端前的人只关心一件事——这句话待会儿是谁回的。所以选单上半截是本机引擎（装了 Claude Code / Codex 就能选，花的是你自己的订阅），下半截是你配的模型（内置循环 + 你的 API Key），序号连着编，`/model 3` 或者 `/model kimi` 都认。

三条脾气：选了台机器上没装的引擎会**当场拒绝并告诉你怎么装**，绝不偷偷退回内置拿 API Key 去跑；从引擎切到模型时会**说一句**它顺手把底层引擎扳回了内置，因为不扳的话选模型不起作用；换完**只管这一趟**，配置文件一个字没动——要长期改去设置里的「模型」。

**`/resume` 是原地换一条，不是重开。** 顶上那条 `openworkbuddy resume` 得开新进程，而人已经坐在交互模式里了——一 `/exit` 再重开，当前这段的上下文、带着还没发出去的文件、临时调过的 `/mode` `/perm` 全跟着没了。

`/resume` 不带参数会弹一个**选择器**：顶上一个搜索框，↑↓ 挑、直接打字就往框里去、实时筛（标题、会话 id、来源都在搜索范围里）、回车接上、Esc 算了。**框是一直摆着的**，不是打了字才冒出来——等人先打字才现身的搜索，只有已经知道能搜的人搜得了。桌面端开的那些也在里面，每行标着来源和多久以前。列表比屏幕长就自己滚，选中的那条始终在窗口里。想跳过选择器直接接也行：`/resume 2` 认序号、`/resume 周报` 认标题里的几个字、`/resume cli_20260918_001618_a3x` 认 id——**按 id 那条不受十二行限制**，更早的照样接得回来，所以 `/new` 和 `/resume` 每次都会把「刚离开的那条」的 id 打给你。

`/model` 不带参数走的是同一个选择器，同一个搜索框。

**Plan 出完计划会问你下一步。** `/mode plan` 下一趟跑完，底下摆两条：「按这份计划开干」「接着改计划」。回车就是开干——切到 Craft，把「按上面这份计划开始做，做完逐条对照计划交账」发出去，不用自己去敲 `/mode craft` 再想一句怎么说；切过去就留在 Craft。选接着改、或者 Esc，都留在 Plan，下一句直接说哪儿要改。出错了、Ctrl+C 停掉的那趟不问（半截计划不该让人开干）；跑着的时候你已经在输入行上打了字的也不问——你已经在说下一句了。终端画不了单子时印一句怎么接着走。

搜索框搜的不只是标题：**你当时打的那句话、这趟产出的文件名也在搜索范围里**。标题是任务跑完自动起的，你多半没读过；真要找回半小时前那段，能想起来的通常是自己说的话或者最后拿到的那个文件。所以 `/resume 重复的行` 接得上一条标题叫「表格清洗」的会话——只靠正文对上的行，选单里会在后面标一句「对话里」，好让你看明白这个看着不相干的标题为什么冒出来。管道里跑、或者这台终端画不了这种覆盖式界面时，两条命令都会自动退回老样子——印一张带序号的表，敲序号一样使。

接过去的时候它会顺手印一行上下文占用：一条跑过二十轮的会话接过来，你下一句话就带着那二十轮一起发出去，这个数不印出来，只能在账单上发现。接的要是桌面端那条，它还会多说一句——桌面同时开着的话，两边写的是同一个文件，后写的会盖掉先写的。

**`/init` 是让它自己去看，不是塞个模板给你。** 敲下去它会把当前工作目录摸一遍，写一份 `AGENTS.md` 放在根下：项目是干什么的、怎么跑怎么测、哪几个目录是主干、有哪些既定规矩。以后不管在桌面端还是命令行，每趟活儿开跑前都会先读这份——它写得准不准，直接决定后面几十趟顺不顺。

它走的是正常那条路：该问你的照问、改文件前照样确认、动过的文件 `/diff` 里也查得到。目录里已经有 `AGENTS.md` 或 `CLAUDE.md` 的话，它会先读完再增补，**不整篇盖掉**——那份很可能是你自己手写的。

**读哪几份规范：从工作目录往上，一直到 git 仓库根。** 每一层带一份（`AGENTS.md` 优先，空的或读不出来才轮到 `CLAUDE.md`），根上那份放前面、子目录的放后面，两份说法冲突时以离工作目录近的为准。仓库根再往上的不带——`~/AGENTS.md` 管不到这个项目；不在 git 仓库里就只看工作目录自己。几份共用 6000 字上限，离工作目录越近的越先分到；超了会截掉并告诉模型「后面还有，拿不准先整份读一遍」，也会在终端里提醒你。`/status` 里有一行「项目规范」，写着这一趟带了哪几份、各多少字——写了规矩没生效，先看这一行。

**`/review` 审的是哪一份，由你定。** diff 先取好塞给它，它按只看不动跑，手里没有 shell——不让模型自己去猜 git 参数。没进 git 的新文件单独列出来让它去读；diff 超过 8 万字符就截，截了会在结论里写明只审了前一部分。

**自己的斜杠命令。** 把一段常用的话存成 `.openworkbuddy/commands/<名字>.md`（跟着仓库走），或 `~/.openworkbuddy/commands/<名字>.md`（只给自己），敲 `/<名字> 参数` 就发出去。模板里 `$ARGUMENTS` 是整行参数、`$1`…`$9` 是第几个（引号里的空格不切）；一个占位符都没写的，参数接在最后。开头可以有一段 `description:` 的 frontmatter，`/help` 里显示它。同名时项目那份优先；跟内置命令撞名的不接，启动时会说哪条没接上、为什么。

```
# .openworkbuddy/commands/fix-issue.md
---
description: 修一个 issue
---
把 issue #$1 修掉，先写个能复现的测试，再改代码，最后跑全量测试。
```

**两个键位，省得敲命令。** `Shift+Tab` 循环切权限档（只看不动 → 每步都问 → 自动改文件 → 转回来），每按一下当场把切到哪档、那档意味着什么打出来。**它到不了「全自动」**——那个键就挨着 Tab，误碰一下就把命令确认也关了，而人正盯着自己那半行字根本不会去读屏幕，所以要全自动得明着敲 `/perm full`。

`Esc Esc`（连按两下）把这个会话里问过的话摆出来，挑一条原样放回输入行，改完再发。它只管「放回去」，不回卷历史——真把已经跑过的那几轮删掉，等于把模型做过的事悄悄抹了而你看不见抹了什么；要重来开 `/new`，要接回去用 `/resume`，两条路都在明面上。

还有六件事值得知道：

**产出的图，终端里直接看。** 一轮跑完，这轮产出的图会试着画在终端里（SVG 会先转成位图）。能不能画取决于终端：kitty、Ghostty、iTerm2、WezTerm 可以；macOS 自带终端、普通 xterm 不行。**认不出来的终端一律不画**——画了得到的是满屏 base64，比不画还糟。

画不出来也不耽误看：末尾那行 `看图：/open 架构图.svg` 交给系统默认程序开（浏览器、预览、Excel、播放器都行），任何终端任何格式都成立。`/open 2` 数的是刚打出来那行产出清单的序号。

VS Code 的终端其实支持，但要先在设置里打开 `terminal.integrated.enableImages`；开关状态这边探不到，所以默认不画，只提示一句。开完设 `OPENWORKBUDDY_TERM_IMAGES=1` 就会画了。反过来嫌吵就设 `=0`。

**多行需求直接粘。** 贴进来的一整块会合成一条发出去，不会被拆成好几条、也不会只进去第一行。

**打错的命令不会被当成任务发给模型。** `/moe craft` 会当场停下来告诉你「你是不是想说 `/mode`」——不然那一行会被原样喂进去，模型一本正经地去执行一条不存在的指令，钱照花。想发一句本来就以 `/` 或 `!` 开头的话：**行首加个空格**，或者**双写成 `//`、`!!`**。以 `/` 开头的路径（`/Users/…`、`/etc/hosts`）本来就不会被当成命令。

**`!` 开头 = 自己跑一条 shell，不经过模型。** `!git status`、`!npm test`：在工作目录里当场跑，输出边跑边上屏，不花钱也不等模型。跑完的输出会记下来，**跟着你下一句话一起带给它**——先 `!npm test` 看一眼红了哪几条，再说一句「修一下」，它拿到的就是那份现场，不用再自己跑一遍。每条最多带 4000 字（太长留头尾、中间省略），最多带最近 5 条；颜色码和进度条的重画会先剥掉。不想带就 `/drop`。会话记录和网页上那条对话显示的还是你自己打的那句话，不是一大段命令输出。`Ctrl+C` 停的是这条命令（连它起的子进程一块儿），不是退出；`vim`、交互式 `python` 这种等输入的东西这里跑不了，`Ctrl+C` 收掉就行。全角的 `！` 不算，中文里一句感叹不会被当成命令跑掉。

**它拿不准的时候会反问你一句。** 岔路口上（「报告交 Word 还是 PDF」这种，选错了后面全白做）它会停下来摆一道选择题，每个选项底下带一句「选它意味着什么」：

```
？ 这份季度复盘报告交哪种格式？后面所有图表的做法都跟着它走。
  ❯ 1. Word（.docx）
       甲方能直接在里面批注和改动，代价是排版到了别人机器上会跑
    2. PDF
       版式锁死，打印和投屏到哪儿都一样，但对方改不了一个字
    3. 都不是，我自己打一句

  ↑↓ 选 · 回车确定 · 数字直接选 · Esc 或 5 分钟没人答就让它自己定
```

跟审批那张单子一个挑法。选项都不对就挑最后一条，把你的想法打进去（空着回车＝让它自己定）。单子刚冒出来那 0.4 秒里按的回车、数字、Esc 都不算——那多半是之前多敲的，不该替你拍板。Esc 只跳过这一题，活儿照跑；Ctrl+C 才是停下这趟。
终端不认按键的时候（比如 stderr 被重定向走了）退回敲一行：序号、选项名、名字的一小段（`word` 就能选中 `Word（.docx）`）都认，回车＝第 1 条，也可以直接打你的想法。**只有真有人坐在终端前才会问**——`echo … | openworkbuddy …`、`--json`、cron 里跑的那些，agent 收到的是「没人在线，按你判断的最合理默认继续做」，不会挂在那儿等一个永远不来的回答。超时（默认 5 分钟）同理。

**人不在电脑前：`--ask-remote`。** 坐在终端前起的活儿，问题本来就会同时推到手机上——人下楼拿杯咖啡，
回来不会看见「用户没回应，我按默认继续了」。但 `echo … | openworkbuddy …`、cron 里那些，那头是真没人：
默认按「无人值守」走，模型自己定，一秒都不等。确实打算挂在后台、答案从手机上给的，显式加 `--ask-remote`——
它只是把「允许等人」这件事说出口，等不到照样会超时收场，不会把一个夜里跑的批处理堵到天亮。

**这一趟放多少权：`--perm`。** 跟网页设置里那个下拉是同一份四档，含义一个字不差：

| 档位 | 意思 |
| --- | --- |
| `plan` | 只看不动。不写文件、不跑命令，适合先让它把现场看明白 |
| `ask` | 每步都问。写文件和跑命令都要你点头，最谨慎也最费手 |
| `auto` | 自动改文件（默认）。工作目录里的文件随便改；命令按名单来，删除、sudo 这些照样问 |
| `full` | 全自动。命令也不问了，只剩文件黑名单、高危命令确认和审计 |

**它只管这一趟，不会把 `config.json` 改掉**——跟 `-C` 一个规矩。这条是特意这么定的：
为了让一条 cron 跑全自动就去把配置文件改成 `full`，跑完忘了改回来，明天所有交互式的活儿
也一起不问人了，而人根本不记得自己动过这个开关。所以放权只活在这一条命令里，退出就没了。

**预先点头：`--allow`。** 没人坐在终端前的时候（管道、cron、CI、`--json`），碰到要批准的那一步会**当场拒掉**，不像以前那样干等两分钟最后照样是拒。stderr 上会说是哪一步被拒了、下回怎么放行：

```
  ✗ 这一步要人批准，终端前没人，直接拒了（删除保护（rm 类命令需审批）：rm dist/old.js）
    预先放行这类：--allow "rm"；从手机上批：加 --ask-remote
```

`-q`、`--json` 下这句照样打——活儿少干了一步，不能一声不吭。模型那边收到的是「没批准」，会换个办法或者说明卡在哪。确实要它在无人值守时做这一类的，开跑前点名：

```bash
openworkbuddy --allow "npm test" --allow "git status" -q "跑测试，挂了就修" > 修复记录.md
openworkbuddy --perm ask --allow write "整理 docs/ 下的错别字"   # 每步都问，但改文件不用问
```

认这几种写法：命令前缀（`npm test`、`rm`，按整词比：放行 `rm` 不等于放行 `rmdir`）；`write`（「每步都问」档下写文件不问）；`code` / `code:child_process`（跑代码不问 / 只放「代码里开子进程」那一类）；`danger:<类别>`（高危命令，类别有 `git-force-push`、`sql-drop`、`compose-down-v`、`dev-write`、`dd-dev`、`mkfs-disk`）。写错了当场退出码 `2` 并列出能写什么——拼错一个字等于没放行，跑到半夜被拒才发现就晚了。带 `;` `&&` `|` 的也会被拦下：规则按单条命令比，那样的规则永远比不中。高危表和询问名单是两道闸，`mkfs`、`diskutil erase` 两张表里都有：放了 `danger:mkfs-disk` 还会按 `mkfs.ext4` 再拒一次，照提示再加一个 `--allow` 就行。

跟 `--perm` 一样只管这一次、只活在内存里，放行了什么会印在开头那行状态下面。它是内置 agent 那一套；底层换成本机引擎（Claude Code / Codex）时它们按自己的权限开关走，开头会说一句不认 `--allow`。想让人不在电脑前也能从手机上批，用 `--ask-remote`。

交互里也能临时换：`/perm` 不给值就把四档连同各自含义摆出来，`/perm ask` 当场切，下一步就生效。
不是默认那档的时候，开头那行状态里会多印一个「权限 …」——`full` 和 `plan` 这种「以为自己在另一档」
会出事的状态，不该只存在于自己的记忆里。

**任务跑着的时候打字回车 = 插话。** 那句话会在下一步带给 agent，不用等它停下来。跟手机、网页上补的那句是同一个入口。

**它要动手了、得你点头的时候，↑↓ 挑一条回车。** 三档：这一次允许 / 这类都允许（本次运行内）/ 不允许。
数字键 1/2/3、y / n 直接选，Esc 就是不允许。单子刚冒出来那 0.4 秒里按的回车、数字、字母都不算——那多半是之前多敲的，
不该替你放过一条 `rm -rf`；一次粘进来、输入法一次上屏的一串字也不算，哪怕打头是个 y。命令原文整条印在单子上面，不截断。管道里、cron 里、`--json` 下跑（没人坐在终端前）就没人能批：**当场拒掉**，在 stderr 上说是哪一步、下回怎么放行，不干等——见下面「预先点头」。

**每一步干了什么，看 `●` 那行。** `● Shell(npm test)`、`● Edit(src/app.js)`：跑的哪条命令、动的哪个文件，
下面 `└` 挂着输出的头 4 行，剩下的只说还有几行；命令退出码不是 0 时第一行就写出来。

**Ctrl+C 停的是这趟活儿，不是退出。** 空着的时候连按两下才退出，`Ctrl+D` 也退。历史存在 `<数据目录>/data/cli-history.txt`，权限 0600，上下箭头能往回翻。


## 写进脚本之前，先知道这三件事

**一、每次单发都是干净上下文。** 想接着上一条继续，得显式 `-c` 或 `--session <id>`。这不是省事，是防串台：CLI 会把助手回复和工具结果追加进会话历史，如果多条命令共用一个会话，第二条任务会拖着第一条的全部上下文——既烧 token，又让模型在别的任务的阴影里答新问题。

```bash
openworkbuddy "读一下 package.json，记住这个项目叫什么"
openworkbuddy -c "那它依赖了哪些包"          # 这条才看得到上一条
```

**二、答案走 stdout，进度走 stderr。** 所以重定向出来的是干净的正文，不会混进「第 1 步 思考中…」：

```bash
openworkbuddy -q "生成本周周报" > 周报.md     # 文件里只有周报
openworkbuddy "跑一下测试并解释失败原因" 2>/dev/null   # 只看答案
```

**三、退出码说实话。** `0` 成功，`1` 出错，`2` 参数写错了，`130` 被 Ctrl+C 打断。`2` 单独留一格是有用的：`openworkbuddy --qiet "写周报"` 这种打错字的，跟「任务真的失败了」在脚本里得分开处理。所以 `&&` 串起来是安全的——上一步真炸了就不会往下走：

```bash
openworkbuddy -q "检查 src/ 有没有明显的空指针风险" && echo "检查通过" || echo "有问题，别提交"
```

`-C` 指了个建不出来的目录会直接退出，不会默默退回默认工作目录——不然文件会写到你没想到的地方。

## 给脚本用：`--json`

每行一个 JSON 事件，最后一行一定是 `done`。常见类型：`step_start`（第几步）、`tool_use` / `tool_result`（调了什么工具、结果如何，同一个 `id` 配对）、`text`（正文，**按 `delta` 分块流式吐出**）、`ask_user` / `ask_answer`（它反问了一句、以及那句的回答，同一个 `ask_id` 配对）、`usage`（token 账单）、`done`（收尾，带 `ok` 和 `session`）。

```bash
# 只要正文。注意用 -j 不换行，因为 text 是一小块一小块来的
openworkbuddy --json "整理今天的会议纪要" | jq -j 'select(.type=="text") | .delta'

# 只看成败和账单
openworkbuddy --json "跑个活" | tail -1 | jq '{ok: .ok, tokens: (.usage.prompt + .usage.completion)}'

# 盯它调了哪些工具
openworkbuddy --json "把 logs 归个类" | jq -r 'select(.type=="tool_use") | .name'
```

## 手机连上来：`openworkbuddy pair`

在终端里敲一句，出一个二维码，手机扫了就能用。

```
openworkbuddy pair
```

```
  ███████ ▄▄ ▄ ███████
  █ ▄▄▄ █ ▀█▄█ █ ▄▄▄ █      U6MU-YNR8   ← 手机上填这串，或者扫左边的码
  █ ███ █ ▀▄ ▀ █ ███ █      http://192.168.1.84:3800
  █▄▄▄▄▄█ ▀ █▀ █▄▄▄▄▄█
  ⋯                         等着…（180 秒内有效，Ctrl-C 退出）
```

手机连上的那一刻，终端里会打出「✓ iPhone 连上了」，然后自己退出。

几件事值得说清楚：

- **密码不会离开这台机器。** 手机拿到的是一条只属于它自己的凭证，跟你的密码是两回事。
- **配对码三分钟作废，而且只能用一次。** 它只存在服务进程的内存里，重启就没了，硬盘上不留。
- **手机丢了不用改密码。** 打开 设置 → 安全 → 远程访问，把那台踢掉就行，别的设备不受影响。
- **要有一台服务在跑**（`npm start` 或桌面端）——手机连的就是它。二维码里那个地址是这台机器
  在局域网里的地址：手机得跟电脑在同一个网络里。要从外网用，得自己做端口映射或内网穿透，
  那时候请务必上 HTTPS，见《[远程访问](远程访问.md)》。

网页版里也有同一套：设置 → 安全 → 远程访问 → 生成配对码。

## 进不去了：`openworkbuddy passwd`、`2fa --off`、`owner`

这三条是**在服务器本机上**跑的救急口子——不发邮件、不连网、服务开着关着都能用。

```bash
openworkbuddy passwd 张三                  # 随机生成一串新密码，只在屏幕上显示这一次
openworkbuddy passwd 张三 '自己定的新密码'   # 也可以自己定，照样要过组织的密码策略
openworkbuddy 2fa 张三                     # 只看状态：开着没有、什么时候开的、还剩几个恢复码
openworkbuddy 2fa 张三 --off               # 手机丢了、恢复码也没了：把二次验证关掉
openworkbuddy owner                        # 各组织现在的超级管理员分别是谁
openworkbuddy owner 李四                   # 把李四所在组织的超管指给他，原来那个改任管理员
```

`owner` 守的是另一种进不去：**同档动不了同档**，所以一个组织唯一的超级管理员离职、号被停、
或者手机连着密码一起丢了，界面上就再没有出口了——谁也没有权限把这个位子拿回来。分公司还能
找平台超管跨组织救场，平台超管自己出事就只剩这一条。理由跟 `passwd` 是同一条（见下），
**同样绝不接到 HTTP 上**：一接就成了人人可用的提权接口。

```
✓ 张三 的密码已改

  z5W5hyFx7jk6   ← 新密码，这一次之后不会再显示

  自己定一个的话：openworkbuddy passwd 张三 '你的新密码'
  他在别处的登录状态已经全部作废，需要重新登一次。
```

**为什么不做「发邮件重置」。** 那要一台 SMTP 服务器、一个发信域名、一条反垃圾记录，
还得把每个人的邮箱存起来。本项目默认装在你自己的电脑或自己的 VPS 上，为一个一年用两次的
功能接一整套邮件设施，代价和风险都不划算——那条重置链接本身就是一把能登进来的钥匙，
它会躺在邮箱里。

**凭什么让命令行改别人的密码。** 因为跑得起这条命令的人，已经能读到 `users.json` 了。
这份文件跟所有会话记录、所有记忆、`config.json` 里的全部 API Key 在同一个目录下（都是 0600）。
能读它的人本来就拿到了这台机器上的一切，再拦一道密码只剩一个后果：忘了密码就彻底进不去。
换句话说，这条口子不降低安全性，它只是把「你已经是机主」换成一个不用手改文件的入口。

**反过来说的那一条，同样要记住：这几条命令绝不接到 HTTP 上。** 网页那侧的重置永远要管理员
身份（管理后台 → 成员 → 重置密码）；网页那侧要换超管，永远得由现任本人转让（管理后台 →
管理员角色 → 转让超级管理员）。

几个细节：

- 改完密码，这个人**在所有设备上的登录状态一起作废**，需要重新登一次。忘记密码往往是因为
  很久没登，那些还挂着的旧令牌现在是谁在用，说不好。
- 账号如果还开着二次验证，光改密码是登不进去的——终端会当场提醒你再跑一句 `openworkbuddy 2fa <用户名> --off`。
- 关掉二次验证是**整套密钥和恢复码一起作废**，不是「暂时停用」。本人登进去以后要到
  设置 → 安全 里重新绑一次，旧的认证器条目可以删掉了。
- 两条都会进审计流水（管理后台 → 审计），事后查得到是谁在什么时候动的。
- 账号处于「已停用」（离职）状态时，改了密码也登不上——终端会直说，别改完了还在门口试。

## 分几步跑：`openworkbuddy workflow`

一件事要「先想方案 → 照方案改 → 再审一遍」，写成一个 JSON 文件按顺序跑：

```json
{
  "steps": [
    { "name": "plan",   "mode": "plan", "prompt": "看一下 src/，想好怎么加导出 CSV" },
    { "name": "build",  "prompt": "照这个方案做：\n{{plan}}" },
    { "name": "review", "mode": "ask",  "prompt": "审一下刚才的改动" }
  ]
}
```

```bash
openworkbuddy workflow 流程.json -C ~/代码/项目
```

- 几步共用一个会话；`{{plan}}` 把那一步的最终回复原样贴进来（最多 2 万字）。只能指前面的步骤。
- 没写 `mode` 的跟命令行 `-m` 走；`name` 不写就是 `step1`、`step2`……
- 一步没成后面就停，退出码 `1`；确实不相干的那步写 `"continue_on_error": true`。
- 文件写错了（JSON 坏了、名字重了、`{{…}}` 指错了）一次全列出来，一步都不跑，退出码 `2`。
- 管道和 `-f` 带进来的材料跟着第一步走。

## 两条任务撞一个仓库：`openworkbuddy worktree`

工作目录指在自己代码仓库上的时候，同时开两条任务是危险的：A 刚把函数改成三个参数，B 手里还是两个参数的旧文本，写回去就把 A 的改动抹了——谁也不报错，测试可能还是绿的，坏的是中间那一版。

所以**撞上了**才隔离：发现这个仓库已经有别的任务在改，后来的这条就去一个 git worktree 里干活——同一个 `.git`、独立的工作区、分支叫 `owb/<会话>`。先到的那条不动，它还在你眼皮底下那份工作区里改。一个人一条任务的时候，什么都不会变。

你手上没提交的改动会一起带过去（被 `.gitignore` 忽略的不带），不然第二条任务看到的是一个「退回上次 commit」的仓库，它会以为同事的活没干，把你改好的地方再改一遍。

任务跑完，分身里的改动会自动提交到那根分支上——但**绝不自动合回来**。合不合、怎么合冲突，是你按的：

```bash
openworkbuddy worktree                 # 现在有哪些分身、各自在哪、合回来的命令是什么
git -C <你的仓库> diff HEAD...owb/xxx  # 先看它改了啥
git -C <你的仓库> merge owb/xxx        # 合回来
openworkbuddy worktree 清理             # 收掉白跑的那些（有改动的一个都不碰）
```

- 白跑的那趟（agent 一个字没写）跑完就地收掉，目录和分支都不留。
- 有产出的留着，放满 14 天只删目录、**分支一直留着**——腾的是磁盘不是你的成果。
- 分身放在数据目录里（`~/OpenWorkBuddy/data/worktrees`），不在你仓库里面。
- 开不出来的时候（没装 git、仓库还没有第一次提交、裸仓库……）就照旧在原工作区跑，日志里写一句，任务不会因为这个起不来。

## Tab 补全：`openworkbuddy completion`

```bash
# zsh（macOS 默认）
mkdir -p ~/.zsh/completions && openworkbuddy completion zsh > ~/.zsh/completions/_openworkbuddy
# ~/.zshrc 里要有这两行：
#   fpath=(~/.zsh/completions $fpath)
#   autoload -Uz compinit && compinit

# bash
openworkbuddy completion bash > ~/.openworkbuddy-completion.bash
echo 'source ~/.openworkbuddy-completion.bash' >> ~/.bashrc

# fish
openworkbuddy completion fish > ~/.config/fish/completions/openworkbuddy.fish
```

补出来的东西：子命令、全部选项、`--mode` 的三个值、`openworkbuddy engines use` 后面本机认得的引擎、以及 `openworkbuddy resume` 后面的会话 id。zsh 那份还带每个选项的中文说明，`openworkbuddy -` 按一下 Tab 就是一张说明表。

两个实现上的选择，说在前面：

- **脚本跟 `--help` 长在同一张表上。** 加一个选项，帮助、解析、三种 shell 的补全同时就有了——不存在「补全落后半年」这回事。
- **会话目录是生成时烤进脚本的，不是每次按 Tab 去问 `openworkbuddy`。** 起一个 node 要过启动检查、要 require 一堆东西，按一下 Tab 等半秒的补全没人会用。代价是搬过数据目录（改了 `OPENWORKBUDDY_HOME`）得重新生成一次，生成出来的脚本头上写了这句话。

## 不要颜色：`NO_COLOR`

设了 `NO_COLOR`（[no-color.org](https://no-color.org) 那条通用约定），进度和报错里的转义序列全部去掉，话还是那些话。屏幕阅读器、日志收集器、以及一切分不清 `ESC[33m` 和正文的下游都靠它。反过来，CI 里没有终端但日志面板认颜色，设 `FORCE_COLOR=1` 能把颜色要回来；两个都设时 `NO_COLOR` 说了算。

## 跑不起来：`openworkbuddy doctor`

什么都还没配好的时候也能跑——它就是用来查「为什么什么都没配好」的。

```bash
openworkbuddy doctor
```

八项一次查完：Node 版本、依赖、数据目录、配置文件、模型渠道、端口、工作区、底层引擎。不合格的每条跟一句「怎么修」，能直接照着做。

两个细节值得知道：

- **有要处理的就退出码 1**，所以能写进安装脚本和 CI：`openworkbuddy doctor && npm start`。
- **只报数不报值**——「12 个渠道，其中 7 个还没填 Key」，但一个 Key 的内容都不会出现。报告整段贴进 issue 是安全的。

端口那一条会分清两件相反的事：3800 上跑着的是 OpenWorkBuddy 自己（那叫「已经开着」，正常），还是别的程序（那才要去处理）。

## 问一下判断模型：`openworkbuddy jev`

判断模型跟对话模型不是一路货。对话模型吃一段话、吐一段话；**Jev 吃一段材料加一道有类型的题，吐回来的是选中的那个选项、一个分数、或者一个 0~1 的概率，外加一个「有多确定」。它不会写字。**

所以它没挂在「模型」那个下拉里——挂上去每一趟都是 400。它是单独一条路。

```bash
# 是非题：两个参数，材料 + 问题
openworkbuddy jev "客服工单：收款连了三天都连不上，订单在丢，麻烦尽快" "这条要升级给主管"

# 单选：第三个参数起是选项
openworkbuddy jev "帮我把这个 csv 去个重" "这活儿归哪一路" 表格 写作 代码 研究

# 打分：加 --score，后面那几个选项当成从低到高的档位
openworkbuddy jev --score "rm -rf ./build" "这条命令有多危险" 只读不改 会新建或改动 会删除或覆盖

# 不给参数就测活：拿一段固定材料真问三道题，通不通、多快、多少钱一次看完
openworkbuddy jev
```

每行答案前面有个记号：`√` 是确定度过了 70%，可以照做；`?` 是它自己也拿不准，后面跟一句「别自动照做」。**这一格才是这个模型最值钱的地方**——对话模型不会告诉你它在瞎猜。

`--json` 出一行 JSON（`{ok, model, ms, answers, usage, cost}`），写进脚本用这个。退出码：0 答上来了 / 1 上游没答 / 2 命令敲错了。

### 配在哪儿

**默认不开**，配了 OpenRouter 聊天渠道也不会自动用。要用就在 **设置 → 模型** 里加一条「TypeSafe Jev」渠道：Key 去 [console.typesafe.ai](https://console.typesafe.ai/settings/keys) 办；想拿 OpenRouter 的 Key 跑，地址填 `https://openrouter.ai/api/v1`。环境变量只认 `TYPESAFE_API_KEY`。

自建网关就在那条渠道的地址栏里填自己的，填了就发去那儿。想彻底关掉：config.json 里写 `"decide": { "off": true }`。

### 它在这个项目里已经在干的活儿

**目标模式（Goal）的验收**那一步换成它了。原来是让对话模型对着几条验收标准吐一段 `{"results":[…]}` JSON——那是拿一个会写字的东西模拟一张表格，它偶尔就不按格式回话，目标卡会整轮不动。现在每条标准就是一道是非题，格式在类型上就跑不掉，快一个数量级、便宜三个数量级。

更要紧的是多了一格「有多确定」：**过 70% 才打勾，没过线的留着不打，并在卡上写清是「拿不准」而不是「没干」**。目标卡最容易骗人的地方就是——打了勾的，人就不再看了。

没配这个模型的机器上，这一步安安静静退回原来那条对话模型的路，行为一个字节不差。

### 多少钱

输入 $0.042 / 百万 token，**输出不要钱**。上面那趟三道题的测活，一次大约 $0.00002。它快到可以放进循环里，所以「设置 → 用量」里给它单独立了一格按**题数**记的额度——一次请求能塞 32 道题，按请求数记那道闸等于没有。
