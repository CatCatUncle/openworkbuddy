# 命令行用法

CLI 跟桌面版共用同一份配置、同一批技能和 MCP 连接器——`~/OpenWorkBuddy/config.json` 改一次，两边都变。区别只在外壳：这边没有窗口，答案直接落到 stdout，可以塞进任何管道和脚本里。

```bash
npm run cli -- "帮我写一份本周周报"
```

嫌前缀长就做个短命令：

```bash
echo 'alias wb="node /你的路径/openworkbuddy/cli.js"' >> ~/.zshrc && source ~/.zshrc
```

下文一律写 `wb`。

## 三种跑法

```bash
wb "把 logs/ 里今天的报错归个类"     # 单发：跑完就退，退出码说明成败
wb                                   # 交互式：像聊天窗一样连着问
cat error.log | wb "这是什么问题"     # 管道：内容作为附加材料一起送进去
```

## 选项

| 选项 | 作用 |
| --- | --- |
| `--mode craft\|plan\|ask` | 执行模式，默认 `craft` |
| `-C, --workspace <dir>` | 这次在哪个目录干活。**只影响本次**，不写回配置 |
| `-c, --continue` | 续接最近一次 CLI 会话 |
| `--session <id>` | 续接指定会话 |
| `--list [n]` | 列出最近 n 个 CLI 会话，默认 10 |
| `--json` | 事件按 NDJSON 打到 stdout，给脚本消费 |
| `-q, --quiet` | 只要最终答案，不打进度 |
| `--no-mcp` | 跳过 MCP 连接器，启动快几秒 |

交互式里还有 `/mode` `/new` `/session` `/cd` `/files` `/exit` 六个内置命令，`/help` 能看到。

## 写进脚本之前，先知道这三件事

**一、每次单发都是干净上下文。** 想接着上一条继续，得显式 `-c` 或 `--session <id>`。这不是省事，是防串台：CLI 会把助手回复和工具结果追加进会话历史，如果多条命令共用一个会话，第二条任务会拖着第一条的全部上下文——既烧 token，又让模型在别的任务的阴影里答新问题。

```bash
wb "读一下 package.json，记住这个项目叫什么"
wb -c "那它依赖了哪些包"          # 这条才看得到上一条
```

**二、答案走 stdout，进度走 stderr。** 所以重定向出来的是干净的正文，不会混进「第 1 步 思考中…」：

```bash
wb -q "生成本周周报" > 周报.md     # 文件里只有周报
wb "跑一下测试并解释失败原因" 2>/dev/null   # 只看答案
```

**三、退出码说实话。** `0` 成功，`1` 出错，`130` 被 Ctrl+C 打断。所以 `&&` 串起来是安全的——上一步真炸了就不会往下走：

```bash
wb -q "检查 src/ 有没有明显的空指针风险" && echo "检查通过" || echo "有问题，别提交"
```

`-C` 指了个建不出来的目录会直接退出，不会默默退回默认工作目录——不然文件会写到你没想到的地方。

## 给脚本用：`--json`

每行一个 JSON 事件，最后一行一定是 `done`。常见类型：`step_start`（第几步）、`tool_use` / `tool_result`（调了什么工具、结果如何，同一个 `id` 配对）、`text`（正文，**按 `delta` 分块流式吐出**）、`usage`（token 账单）、`done`（收尾，带 `ok` 和 `session`）。

```bash
# 只要正文。注意用 -j 不换行，因为 text 是一小块一小块来的
wb --json "整理今天的会议纪要" | jq -j 'select(.type=="text") | .delta'

# 只看成败和账单
wb --json "跑个活" | tail -1 | jq '{ok: .ok, tokens: (.usage.prompt + .usage.completion)}'

# 盯它调了哪些工具
wb --json "把 logs 归个类" | jq -r 'select(.type=="tool_use") | .name'
```

## 常用几条

```bash
# 让它在别的项目里干活，不动全局配置
wb -C ~/code/another-repo "这个仓库是干什么的，读 README 和入口文件后告诉我"

# git 钩子里做提交前检查
wb -q --no-mcp "看看这些改动有没有明显问题：$(git diff --cached)" 

# 定时任务：每天下班前收个尾
0 18 * * * cd ~/work && /usr/local/bin/node ~/openworkbuddy/cli.js -q "总结今天 git log 里的进展" >> ~/日报.md
```
