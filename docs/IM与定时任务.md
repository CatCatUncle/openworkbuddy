# 手机远程指挥（IM）与定时任务

## 手机远程指挥（IM）

在手机上给它下任务，干完推回来。

侧栏的**助理模式**就是这些渠道的总控台：顶部列出已连接的通道，中间是所有渠道汇成一条的对话历史（落盘保存，重启不丢），底部输入框可以直接跟助理对话——和在飞书里 @它 一样，任务在这台电脑上执行。

| 渠道 | 要不要公网 | 说明 |
|---|---|---|
| 飞书 | 不要 | 长连接，填 `app_id` / `app_secret` 就行；另可**扫码**授权你本人的身份（见下） |
| QQ | 不要 | 官方机器人 WebSocket 长连接 |
| 微信 iLink | 不要 | 扫码登录 + 长轮询 |
| 企业微信自建应用 | 要 | 回调地址得能被访问到 |
| 微信公众号 | 要 | 同上 |
| 企业微信群机器人 / 钉钉 | 不要 | 只推结果，不收指令 |
| 通用 Webhook | 看你怎么接 | 桥接任何东西 |

通用 Webhook 长这样，同步返回 `{ reply, files }`，iOS 快捷指令、自动化平台、你自己的脚本都能接：

```bash
curl -X POST http://localhost:3800/im/task \
  -H "Content-Type: application/json" \
  -d '{"message": "帮我生成本周周报", "secret": "你配的密钥"}'
```

**飞书扫码授权**：设置 → 助理设置 → 飞书 → 扫码授权，用飞书 App 扫一下，AI 就能以**你本人**的身份读日历、翻云文档、查邮件、写多维表格（走飞书官方设备码流程，密码不经过 OpenWorkBuddy）。依赖本机的 [lark-cli](https://github.com/larksuite/cli)（MIT）：`npx @larksuite/cli@latest install`。

> 免得误会：机器人**收消息**必须有应用的 `app_id` + `app_secret`，这是飞书的设计，扫码替代不了。扫码解决的是另一半——用户身份的 API 调用。两者互不冲突，可以只配一个。

**取消本人身份连接**：在「飞书增强 → 飞书本人身份」中点击「取消连接」并确认。应用调用 `lark-cli auth logout --json`，清除本机当前应用的用户登录态，并停止待完成的扫码；机器人连接、App ID 和 App Secret 保留。失败会显示原因，不能只隐藏已授权状态。这个操作不撤销飞书服务端的应用授权，完整撤权请在飞书授权管理中处理；其他 CLI profile 的登录态也不会被批量删除。

**飞书扫码新建应用**：设置 → 助理设置 → 飞书 → 「📱 扫码新建应用」。本机装了 lark-cli 的话，它会替你在飞书开放平台**建一个新应用**，页面上给一张二维码（扫不了就点旁边的链接），你在飞书/浏览器里确认一下，`app_id` 自动填回卡片。

- 这是上面那句「扫码替代不了」的唯一例外：扫码换不来现成机器人的凭证，但可以扫码把应用**建出来**，凭证是新应用自己的。
- **App Secret 还得你复制一次**：lark-cli 的 secret 是只进不出的——macOS 上它默认锁进系统钥匙串，`lark-cli config show` 只回一串 `****`。所以建完之后页面会给一条直达这个应用「凭证与基础信息」页的链接，你复制 App Secret 粘到卡片的「粘一段过来自动识别」里即可。手打的只剩一次 Ctrl+V。
- 那串 `****` 我们一个字节都不会存进配置：读不出真凭证时宁可拒绝导入，也不会把你原来能用的 Secret 顶掉（顶掉的后果是界面显示「已保存」、连接却报 10014，比直接失败难查得多）。
- 建完还要去开放平台给这个应用开权限（`im:message`、`im:message:send_as_bot`）并发布版本，机器人才收得到消息。
- 建应用需要你的账号有创建应用的权限；企业管的严的话会被管理员挡下，页面会原样告诉你。
- 已经有现成应用的，用卡片里的「粘一段过来自动识别」：把开放平台「凭证与基础信息」那一整页复制粘进去就行，不用一个字段一个字段抠。

> 凭证不会被空输入冲掉：设置页是整页保存，密码框刷新后本来就是空的——现在空值一律当「没改」，只有点「取消连接」才会真清。

## 定时任务

**助理引擎可独立选择。** 助理页的模型菜单可选已配置的 API 模型、本机 Codex 或 Claude Code，远程 IM 使用同一个助理选择；不会改普通对话或定时任务的引擎。运行联网脚本时仍须遵守所选引擎的网络权限，取数失败不应通过自动切换付费 API 模型来处理。

**本机 CLI 的飞书消息通道。** `send_feishu_message` 使用当前任务目录下已绑定的 `lark-cli` 应用，以机器人身份发给明确指定的接收人。只有本机主人可使用，借给 CLI 时只把这一个消息工具交回应用；其他工具仍按原执行设置运行。它不导出密钥、不降低钥匙串保护、不打开沙箱网络，未拿到回执不会假报成功。工具不存在或权限不足时如实报错，不换机器人尝试补发。

**飞书主动通知需要接收目标。** 在「设置 → 助理设置 → 飞书」填写机器人凭证和「通知接收 ID」：用户用当前应用下的 `ou_` ID，会话用 `oc_` ID。机器人须有发送权限，并能访问该用户或群。长连接在线只表示接收通道正常；不填通知接收 ID，不会根据历史会话猜测或群发。清空接收 ID 即停止主动推送。

通知由应用直接调用飞书接口发送，不依赖本机引擎读取系统钥匙串。任务描述只需交代要完成的工作，最终回复会由应用推送；已有任务若明确要求自行用 CLI 发送，请先移除重复发送指令再启用应用通知。自动化运行记录分别展示执行结果和通知送达情况：飞书返回 `message_id` 才算送达；权限拒绝、缺接收目标、超时未确认都会留痕。通知失败不会重跑已经完成的任务。

飞书结果发送遵循单次任务的送达记录：内置执行工具及交回应用执行的 CLI 工具拿到 `message_id` 成功回执后，不再切换 profile 或机器人重复发送；参数、认证或平台明确拒绝时可修正重试，超时、断连或无回执先核对原消息。每一轮任务独立记录，不会拦住第二天的正常发送。本机引擎自行执行、未交回应用的命令由引擎执行，任务说明同样要求单目标发送。

界面的**自动化**页管这一摊：定时任务、运行记录、批量开关/删除、从模板一键添加。加任务在 **自动化 → 定时任务**，或者调 API：

```bash
curl -X POST http://localhost:3800/api/schedules \
  -H "Content-Type: application/json" \
  -d '{"name": "每日晨报", "cron": "0 9 * * 1-5", "task": "抓今天的 AI 行业新闻，生成晨报 markdown"}'
```

cron 5 字段（分 时 日 月 周），支持 `*` `,` `-` `*/n` `1-30/5` `5/10`；周里 `0` 和 `7` 都是周日。日和周同时写了具体值时按标准 cron 取**或**（`0 9 1 * 1` = 每月 1 号或每周一）。越界（`70 * * * *`）、写反（`5-1`）、步长 0 一律当场报错——收下不报的后果是任务永不触发，界面上却一切正常。

**错过了会补跑**（每个任务可关）。这是台式应用，合上盖子睡一夜、或者应用压根没开着，到点那次就没人执行。下次醒来会把该跑没跑的补一次：

- 一段时间里错过好几次也**只补一次**，补的是最近该跑的那次——补的是「这件事还没做」，不是把闹钟按次数重放
- 最多往回补 24 小时，更早的按过期丢掉（关机一个月，不该开机就把一个月的晨报全补一遍）
- 装好后第一次启动不补跑，否则一上来就会把历史全部重放
- 同一个任务不叠着跑：上一次还没跑完，这次就跳过
