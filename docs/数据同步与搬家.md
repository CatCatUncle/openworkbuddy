# 数据存在哪 · 怎么同步 · 怎么搬家

## 先把「同步」这个词说清楚

这套东西是**本地优先**的：一台机器上跑一个 OpenWorkBuddy 服务，数据只有一份，就在那台机器的硬盘上。

Mac 桌面端、浏览器、手机、终端 `wb` —— 这四个都不是四份数据，是同一台服务的四张脸。
所以**它们之间没有「同步」这回事**：你在手机上发的话，桌面端刷新就在；终端里跑完的任务，网页的成果面板里就有。
不存在「等它同步」，也不存在「两边冲突」。

真正需要动手的只有两件事：

| 你想干的事 | 看哪一节 |
| --- | --- |
| 手机 / 平板 / 另一台电脑要连上我这台 | [让别的设备连过来](#让别的设备连过来) |
| 换电脑了，要把东西整个搬过去 | [搬家](#搬家) |

## 数据到底存在哪

所有会被写的东西都在一个**数据根目录**下面，代码目录是只读的，不往里写：

| 怎么跑起来的 | 数据根目录 |
| --- | --- |
| `git clone` + `npm run app`（开发态） | 仓库目录本身 |
| `.dmg` / `.exe` 装出来的 | `~/OpenWorkBuddy` |
| Docker（`deploy.sh`） | `./wb-data` |
| 自己指定 | 环境变量 `OPENWORKBUDDY_HOME=/你的/路径` |

装机态之所以不写回应用包：macOS 往签名过的包里写会破坏签名，Windows 装在 `Program Files` 下普通用户也没有写权限。
之所以放家目录而不是 `Library/Application Support`，是因为 `workspace/` 里放的是 PPT、Word、Excel 这些要交到你手上的成果文件 —— 得让你在访达/资源管理器里自己找得到、能拖走。（见 `paths.js`）

数据根下面：

| 东西 | 路径 | 进备份吗 |
| --- | --- | --- |
| 账号、登录令牌、角色 | `data/users.json` | ✅ |
| 组织 / 部门 / 成员 / 邀请码 | `data/orgs.json` | ✅ |
| 会话记录 | `data/sessions/` | ✅ |
| 微信 / 飞书那边的会话 | `data/im-sessions/` | ✅ |
| 记忆（手写区 + 条目 + 向量） | `data/memory.md`、`data/memories.json`、`data/memory_vectors.json` | ✅ |
| 每个人自己的偏好 | `prefs/<账号>-<指纹>.json` | ✅ |
| 用量、积分、额度 | `data/usage.json`、`data/api-usage.json` | ✅ |
| 审计日志 | `data/audit.json` | ✅ |
| 全部配置（**含 API Key**） | `config.json` | ✅ |
| 定时任务 | `schedules.json` | ✅ |
| 专家 / 专家团 | `experts.json` | ✅ |
| **自己写的**技能 | `skills/<名字>/` | ✅ |
| 出厂自带的技能 | `skills/<名字>/` | ❌ 新机器上本来就有 |
| 成果文件 | `workspace/` | ❌ 太大，而且你自己看得见摸得着 |
| 插件 | `plugins/` | ❌ 装回去就行 |
| 执行追踪账本 | `workspace/.openworkbuddy/traces.jsonl` | ❌ 里面是原始提示词，默认不入 git |
| 评测跑分记录 | `eval/` | ❌ 重跑就有 |
| 项目工作目录 | `projects/<项目名>/` | ❌ 跟 `workspace/` 一样，是成果，自己拷 |
| 启动日志 | `logs/` | ❌ |

备份覆盖哪几项写在 `server.js` 的 `BACKUP_ENTRIES` 里（`prefs/` 在 `data/` 外面，所以单列了一项），自己写的技能由 `userSkillEntries()` 挑出来加上。
**出厂技能不进备份是故意的**：光 `ppt-master` 一个就 170M，每备一次背一遍，备份会大到没人敢点。
代价说在明处：你要是改过出厂技能，那份改动不跟着走，新机器上会是出厂那一版 —— 想留住就把它另存成一个新名字。

## 什么是自动跟着账号走的，什么是每台设备各管各的

跟着**账号**走（存在服务端，换设备/换浏览器都在）：

- 会话记录、记忆、成果文件
- 个人偏好：桌面宠物、快捷指令、上次挑的模型、引擎与思考档位（`prefs.js` 里 `split()` 划成「个人」的那些，落在 `prefs/`）
- 组织身份、角色、额度

跟着**这台设备**走（存在浏览器 localStorage 里，不上传）：

- 主题、皮肤、字号、字体、字重密度
- 成果面板是「全部」还是「只看成果」、资料库的视图和分组
- 「正在忙的时候发消息」是排队还是插队
- 画布名、上次待的场景、侧栏各块的宽度

这一条是**有意这么设计的**，不是漏了：「这台机器上看着舒服」本来就是设备的事 —— 台式机 27 寸和手机屏要的字号不是一个字号，把它跟着账号同步过去只会让人两头都别扭。
（对应 `public/js/app-02.js` 里外观那一节开头的注释。）

## 让别的设备连过来

不用搬数据，让它们连到同一台服务就行。

**同一个 Wi-Fi 下（手机连电脑）**：默认**只听 `127.0.0.1`** —— 这个进程手里有 `run_shell` 和整个文件系统，绑 `0.0.0.0` 等于把一个 shell 挂出去，所以不默认开。
要让手机连得上，启动时显式放开：

```bash
HOST=0.0.0.0 npm start          # 或者在 config.json 里写 { "server": { "host": "0.0.0.0" } }
ipconfig getifaddr en0          # Mac：查本机局域网 IP（Windows 用 ipconfig）
```

然后手机浏览器开 `http://<那个 IP>:3800`。
注意：一绑到回环之外，「个人桌面版」那层简化就自动关掉了 —— 平台管理员的闸门和凭证脱敏全部照旧生效（见 `admin.setDeployment`）。

**不在一个网里**：别把 3800 直接暴露到公网。两条路 ——

1. 内网穿透（Cloudflare Tunnel、frp、Tailscale 都行），前面加一层 HTTP Basic Auth；
2. 或者干脆把服务部署到一台 VPS 上，见 [部署到服务器](./部署.md)。

不管哪条路，**多人用之前先把自助注册关掉**，改成管理员发邀请码 —— 企业后台 → 成员 → 生成邀请码，复制出来的是一条带码的注册链接，发过去打开就是填好码的注册页。（见 [多人协作](./多人协作.md)）

## 搬家

> 换电脑、从本机搬到服务器、从服务器搬回本机，都是这一套。

### 旧机器上

1. 设置 → 数据 → 数据备份与恢复 → **立即备份**
2. 在下面那条记录上点**下载**，得到一个 `wb-backup-20260917-1030.tar.gz`
3. `workspace/` 里的成果文件**不在这个包里** —— 要带就自己拷贝那个文件夹（设置 → 数据 → 工作空间 → 「打开当前文件夹」能直接跳过去）

### 新机器上

1. 先把 OpenWorkBuddy 装好、跑起来、建好第一个管理员账号
2. 设置 → 数据 → **导入备份文件**，选那个 `.tar.gz`
3. 它会出现在下面的列表里，点**恢复**
4. 按提示**重启应用** —— 不重启的话磁盘上已经是新数据了，但内存里还是旧的
5. 把 `workspace/` 拷回去（如果你带了）

导入的包会被改名成 `...-imported.tar.gz`，一眼看得出是外来的，不会跟本机自己打的混在一起。
恢复之前系统会**自动把当前现状再备一份**（名字里带 `before-restore`），恢复错了还能回来。

### 导入这一步会拒掉什么

这是整套备份里唯一一个「外面来的文件」入口，而恢复那一步是实打实的 `tar -xzf 包 -C 数据根目录`。
所以包在落盘之前会被整个拆开看一遍，下面任何一条不合格就原地拒掉，磁盘上不留痕迹：

- 不是 gzip（前两个字节不是 `1f 8b`）
- 解不开 / 是半截文件
- 里面有绝对路径（`/etc/...`）—— 会写到数据目录外面去
- 里面有 `..` 路径 —— 同上，换个写法
- 里面有软链接或硬链接 —— 先塞一个 `data/x -> ~/.ssh/id_rsa`，后面往 `data/x` 里写就落到链接指的地方了；正常备份里不会有这东西
- 顶层有 `data/`、`prefs/`、`skills/`、`config.json`、`schedules.json`、`experts.json` 之外的东西 —— 那根本不是这套系统的备份

备份里有 `config.json`（含全部 API Key）和所有人的账号数据，所以**只有管理员**能备份、下载、导入、恢复。
`test/e2e.js` 的 `testBackupRoundTrip()` 把上面每一条都钉住了。

### 服务器版（Docker）

数据全在 `./wb-data` 一个目录里，容器随便删，那个目录别删。搬机器可以直接：

```bash
tar -czf wb-data.tar.gz wb-data        # 旧机器
scp wb-data.tar.gz 新机器:~/           # 搬过去
tar -xzf wb-data.tar.gz && bash deploy.sh   # 新机器
```

比走界面快，而且连 `workspace/` 一起带走。**注意 `wb-data/config.json` 里有明文 API Key**，别扔进任何云同步文件夹或者公开仓库。

## 常见的几个问题

**手机上看不到电脑上的对话？**
它俩连的不是同一台服务。手机浏览器地址栏里是不是 `localhost` —— 那是手机自己。得填电脑的局域网 IP。

**换了浏览器，主题和字号没了？**
按设计如此，见上面那一节。会话、记忆、偏好都在，只有外观是每台设备各管各的。

**恢复完还是旧数据？**
没重启。恢复只写磁盘，内存里那份要重启才换掉。

**两台机器各跑一个，想让它们互相同步？**
不支持，也不建议。这套系统的数据一致性是靠「只有一份」保证的，不是靠合并。
要多设备就让它们连同一台服务；要多人就用企业版的组织与成员，见 [多人协作](./多人协作.md)。

**备份能定时自动做吗？**
目前是手动点。`backups/` 是个普通文件夹，想自动就用系统的定时任务 `curl -X POST localhost:3800/api/backup`（带上管理员的 `wb_token` Cookie），或者直接拿 `tar` 打包数据根目录。
