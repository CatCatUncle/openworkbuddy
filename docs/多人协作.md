# 多人一起用（多租户）

先说清楚这里的「多租户」是什么，免得期待错位：

> **一套程序、一台机器、一份配置，多个账号共用。** 每个人有自己的账号、自己的任务历史、自己的用量账单；但模型 Key、技能、连接器、成果文件目录是**全组共用的一份**。
> 它**不是**"一人一套独立环境"——这个 agent 手里有 `run_shell`，能读写这台机器的文件，应用层挡不住一个成员去读另一个人的产出。真要硬隔离，见本节最后一段。

适合：自己一个人用（默认就是这样，什么都不用配）、家里 / 小团队几个人共用一个 Key、给同事开个号让他也能用。

## 四档角色：超级管理员 / 管理员 / 审计员 / 成员

以前只有「管理员」和「成员」两档，于是有个大窟窿：**任何一个管理员都能把另一个管理员降成成员**，也能随手再造一个管理员出来。两个人吵一架，谁先点谁赢——那不是权限模型，是先手优势。

现在按 RBAC 来。整套规矩只有两条，剩下的全是这两条推出来的：

1. **角色分档，只能管比自己低的那一档。** 同档互相动不了：管理员对管理员，改角色、停用、删号、重置密码、办离职、解二次验证，一步也走不动。
2. **授角色 = 既要管得到这个人，也要够得着你要给的那个角色。** 于是管理员能把成员提成审计员，却永远造不出第二个管理员——发管理员是超管的事。

| | 超级管理员 | 管理员 | 审计员 | 成员 |
|---|---|---|---|---|
| 下任务、用技能连接器、看成果文件 | ✅ | ✅ | ✅ | ✅ |
| 自己的任务历史、改自己的昵称/头像/登录名/密码 | ✅ | ✅ | ✅ | ✅ |
| 看用量流水 | 全组织 | 全组织 | 全组织 | 只看**自己**的 |
| 进管理后台 | ✅ | ✅ | ✅ **只能看** | ❌ |
| 改额度 / 部门 / 邀请码 / 企业设置 | ✅ | ✅ | ❌ | ❌ |
| 管人：加人、改角色、停用、删号、重置密码 | ✅ | 只能管**比自己低的那一档** | ❌ | ❌ |
| 把人提成**管理员** | ✅ | ❌ | ❌ | ❌ |
| 转让超级管理员 | ✅ | ❌ | ❌ | ❌ |
| 新建组织、改别的组织的套餐席位 | 仅**平台**超管 | ❌ | ❌ | ❌ |

**超管每个组织只有一个，只能「转让」，不能增发、也不能罢免。** 为什么不许有两个：两个超管等于把第 1 条规矩在最高那一档上重新打开——要么允许互相罢免（先手优势原样回来），要么谁也罢免不了谁（点错一次就永远拿不下来）。一个 + 转让，这两种毛病都没有。日常分权用「管理员」，要几个有几个。

谁是超管：**开服第一个注册的人**就是平台超级管理员（默认组织那一个，也就是这台机器的主人）；**一个新组织里第一个管理员级别的人**，就是那个组织的超管。升级上来的老账本自动搬一次家：`owner` 那个布尔抬成角色，以前压根没有超管的分公司按建号顺序补上最早的那个在职管理员。

**「审计员」这一档代码里早就有**，只是一直没排进序列、也没写进这份文档，所以基本没人知道它在。现在它是正式的第三档：进得去后台、看得见全组织的用量和账单，一个字也改不了。给财务、给外部顾问、给那些要对账但不该碰权限的人。

发管理员这件事有四条路，四条全堵着同一道闸：改角色、直接建号、发邀请码、部门模板——少堵一条，「管理员发不了管理员」绕一步就没了。

### 人跑了怎么办：两条出口

同档动不了同档，所以「唯一的钥匙掉了」这件事必须留出口，留了两条：

- 分公司的超管不干了 → **平台超管**（默认组织那一个）可以跨组织把这个位子指给别人；
- 平台超管自己不干了 → 在**服务器本机**跑一句 `openworkbuddy owner <用户名>`（不给用户名就只是列一下各组织现在的超管是谁）。

第二条的理由跟 `openworkbuddy passwd` 一模一样：能读到 `data/users.json` 的人本来就已经是机主了（那份文件跟所有会话、所有记忆、`config.json` 里的 Key 躺在同一个目录下），再拦一道只剩下「钥匙掉了就永远进不去」这一个后果。所以这条口子**绝不接到 HTTP 上**——一接就变成人人可用的提权接口。

还有三条兜底，都是「办完这个组织就没主了」那一类：最后一个超管**删不得、停不得、办不了离职**（要换人只有先转让这一条路）；谁都不能对自己动手（手一抖就把自己锁在门外）；组织里最后一个在职管理员办不了离职。

角色记在 `data/users.json` 里，整套判断只有 `rbac.js` 一个文件说了算——一屏读得完。权限这种东西，读不完就没人敢信。

## 怎么把人加进来

三条路，按场景挑：

1. **管理员直接建号**（多数情况走这条）。管理后台 →「成员与部门」→ 添加成员，随机密码只显示一次，发给本人自己改。配了部门模板的话权限自动套好，见下一节。
2. **邀请码**。同一页生成，能限次数、设过期、预先指定角色和部门；撤销只影响还没用掉的那批人。适合一次拉进来几个、又不想一个个建号。码上能写的角色跟你手上能授的角色是同一套——管理员发不出管理员的码，谁也发不出超管的码。
3. **开放自助注册**。左下角头像 →「账号 · 用量」→ 勾上 **「允许别人自己注册账号」**，对方打开地址自己注册（注册入口这时候才出现），完事**把开关关回去**。

关着的时候登录页连注册入口都不给。**挂在公网上又长期开着注册 = 谁进来都能拿你的 Key 跑任务，还能用 `run_shell` 碰这台机器**，所以用完请关。管理后台「基础设置」里还有个 **「注册后需要审核」**，开了之后自助注册进来的人先挂成「待审核」——cookie 发了但一步也走不了，得管理员在「成员审核」里点头。公网部署建议两个都开，或者干脆只用邀请码。

## 入职：按部门模板开号，不用一个个记

管理后台 →「成员与部门」→ **添加成员**。填个登录名，部门选一下，角色和额度**留空**——留空就按这个部门存的**权限模板**开号。密码是随机生成的，只显示这一次，发给本人自己改。

模板在同一页的「部门」那块：每个部门一行，点「权限模板」设这个部门新人的默认角色和默认月额度，旁边直接写着当前模板长什么样。没存模板的部门按「成员 · 跟随团队额度」来。

为什么值得设一下：一个部门招到第三个人的时候，前两个人当初怎么配的早忘了——填出来三套不一样的权限，而且没人会发现。模板的意义就是**同一个部门进来的人权限长得一模一样**。

两条边界写清楚：

- 模板只影响**之后**进来的新人，改模板不会动任何已经建好的账号；
- 添加成员时角色/额度**填了具体值的以填的为准**。模板是默认值，不是强制。

加人还有另外两条路，看场景挑：**邀请码**（管理后台能限次数、设过期、预先指定角色和部门，撤销只影响还没用的那批）比开放注册安全得多；**开放自助注册**只在一次性拉一批人进来时开，开了记得关回去。

## 离职：一步关完，出一张能贴进交接单的回执

成员那一行点 **办离职**。它不是「点一下停用」——停用只删登录令牌，而一个用了半年的账号手上攥着的远不止一个 cookie。一次办完这些：

| 关掉 | 为什么非关不可 |
| --- | --- |
| 账号停用 | 他手上开着的那个页面下一次请求就走不动了，不是等 cookie 过期 |
| **全部**登录令牌 | 包括扫码连上来的手机 / 平板——那是另一类令牌，跟浏览器那条不是一码事 |
| 名下的定时任务 | **这条最要命**：人走了，他排的「每周一早八拉上月回款发给张总」照跑不误，花的是公司的额度，推到的是他自己的企业微信。定时任务走调度器，不过登录闸，停用账号一个字都拦不住它 |
| 他发出去、还活着的邀请码 | 还没到期、还没用完，谁捡到谁就能注册进来，角色还是他当初设的那个 |
| 绑在他手机上的二次验证 | 账号万一被谁重新启用，那把钥匙还在他兜里 |
| 正在跑的任务 | 不掐的话，他走出公司大门那一刻，屏幕上那个任务还在读文件 |

**定时任务可以指名交接给谁**（办离职的弹窗里就问这一次，问完就再没人会回头补）。交接过去的排期**仍然是关着的**——接手的人得先看清这条任务到底在干什么再自己打开。直接接着跑最容易出的事是：他根本不知道每周一早上那封邮件是自己发的。

**关权限，不删数据。** 他跑过的任务、花过的额度、写出来的文件、留下的审计，一律原样留着——人走了账还得能对，去年的报告还得能翻出来。真要删数据是另一件事（数据出境 / 个人信息删除请求），走的是另一个口子，不跟「办离职」混在一起：那是个按下去收不回来的按钮。

办完出一张回执，逐项写明**关了什么、留了什么、还要人做什么**（比如「有 2 条定时任务停了但没人接手」）。做成了能整段复制的纯文本，因为它的下一站是交接单 / 工单 / 群里那条消息。

三道防手滑：**不能给自己办**（手一抖就把自己锁在门外了），**不能把组织里最后一个在职管理员办掉**（办完谁都进不了后台，连「把他重新启用」这一步都做不到），**超管得先转让再走**（他一走这个位子就空在那儿，谁也发不出新的管理员了）。

## 各自看到什么、共用什么

**每个人自己的：**

- **任务历史**。侧边栏的任务列表按账号分开存（浏览器本地 `owb_sessions:<用户名>`），服务端的会话文件也记着归属。换个账号登录，看到的是他自己的列表。
- **用量账单**。每次任务的 tokens、耗时、模型、来源（网页/CLI/IM/定时任务）都记进 `data/usage/<年-月>.jsonl`（一笔一行、只追加，按月分片；老版本那个 `data/usage.json` 第一次被读到时自动拆开，原文件改名成 `.migrated` 留在原地对账用），成员在「账号 · 用量」里看自己的今日 / 本月 / 近 7 天 / 最近 50 条。
- **身份**。昵称、头像、登录名、密码，各改各的。

**全组共用的（任何登录用户都能看、能改）：**

- 模型和 API Key、搜索服务的 Key（`config.json`）
- 技能 `skills/`、专家 `experts.json`、MCP 连接器、已装插件
- 安全中心的所有闸门设置、审计日志
- 定时任务表
- **工作目录和成果文件**——所有人的产出落在同一个目录里，互相看得见

> 需要说明白的一点：会话**现在查归属**了——回放、插队、替它回答、停止这几条口子都过同一道闸，不是你的对话一律 `403 这条对话不属于你`；管理员看得到，但只限**本组织**的人。剩下的口子说清楚：**升级上来的老会话**里没记归属（那时候还不存这个字段），这批仍然是任何登录用户都调得出来的——不这么放行的话，升级完所有旧对话集体打不开。真在意这批的话，最稳妥的办法是把它们归档走。

> 还有一条别误会：产出文件是**全组共用一个工作目录**的，会话查归属拦不住这件事——他的文件你在成果面板里照样看得见。要分开就得按下面「真要硬隔离怎么办」来。

## IM 和定时任务算谁的

飞书/QQ/微信那些渠道进来的消息、以及 cron 定时任务，背后没有登录态，**统一记到管理员（第一个账号）名下**。

## 想给成员定额度：积分限额（默认关着）

**一个人本地部署，别开它。** 它拦不住任何真实开销——Key 是你自己的，账单在服务商那边，这本账只是个自己写给自己的数字。开着的唯一效果是：干到一半余额见底，任务被自己的应用掐了，然后你还得进后台给自己充值。

真正用得上的场景只有一个：**多人共用你的一个 Key，你要给成员定额度。** 管理员到「账号 · 用量」勾上「开启积分限额」，才开始按**每 1000 tokens 扣 1 积分**（每次任务至少 1 积分）算，余额 0 时拒跑；管理员可以给任何人充值。开关即时生效，不用重启，网页 / CLI / IM / 定时任务四个入口共用同一本账。

关着的时候整套积分 UI 都不出现——余额、充值、结果下面那行「扣 X 积分」，一个不显示。**用量流水跟这个开关无关，永远照记**：那是给你看花了多少 tokens 的账，不是闸。

## 名字、头像、登录名都能改

- 头像菜单 →「个人资料」：改**自己**的昵称和头像；设置 →「个性化」：改**助理**的名字和头像。两边都支持 emoji 或上传图片（自动裁方、压到 128px，硬上限 256KB）。
- 助理改名不只是换个界面标题：名字会同时进系统提示词，所以你喊它「小秘」它自己也认。
- **登录名也能改**（个人资料 → 登录名，要输一次当前密码，毕竟改的是身份本身）。挂在旧名字底下的东西会一起搬走：历史会话的归属、用量流水、充值记录里的「谁充的」、还有你手上那个登录令牌——所以改完不会被踢下线，也不会有一堆任务突然没了主。

## 几条默认就这么定的安全规矩

- **有了第一个账号之后，默认不许别人自己注册。**（上面说过，开了记得关回去）
- **登录有闸**：同一个账号连错 8 次、或同一个 IP 连错 30 次，停 15 分钟。只记在内存里，重启就清，这是防连打不是封号。
- **改完密码，别处的会话立刻下线**，只留你当前这一个。密码泄露了才改的密码，旧 cookie 还能用就等于没改。
- 走 https 进来时，会话 cookie 自动带 `Secure`。
- 账本 `data/users.json` 坏了会**直接报错停下**，不会当成「没有用户」——后者的下场是下次写盘把所有账号覆盖成空的，而且下一个注册的人自动变管理员。

## 真要硬隔离怎么办

**一人一个实例**：各自一份 `data/` 和 `config.json`，用不同端口跑，或者一人一个容器。这是唯一靠谱的隔离方式——因为 agent 有 shell，任何应用层的"权限"在它面前都不算数。
