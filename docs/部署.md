# 部署到服务器

一条命令（机器上得先有 Docker）：

```bash
git clone https://github.com/CatCatUncle/openworkbuddy.git && cd openworkbuddy
bash deploy.sh                              # 起在 127.0.0.1:3800
bash deploy.sh --domain buddy.example.com   # 或者：带自动 HTTPS，直接对外能用
bash deploy.sh --update                     # 拉最新代码，重建，重启
```

数据全在 `./openworkbuddy-data` 一个目录里（配置 / 账号 / 成果文件 / 技能 / 备份），容器随便删，那个目录别删。

想自己拼 compose 而不用这个脚本：

```bash
cp deploy/env.example .env                  # 端口、域名、数据目录都在这里改，不改也能起
docker compose up -d --build
docker compose logs -f app                  # 看它起来没（服务名叫 app，容器名叫 openworkbuddy）
```

不用 Docker 的话可以 PM2。`OPENWORKBUDDY_HOME` 指到代码目录外面，不然数据散在代码里，`git pull` 的时候碍事：

```bash
HOST=127.0.0.1 PORT=3800 OPENWORKBUDDY_HOME=$HOME/openworkbuddy-data pm2 start server.js --name openworkbuddy
```

反代配置样例、升级迁移、多租户、**以及安全须知**都在 [deploy/README.md](../deploy/README.md)。

起来之后怎么开第一个管理员、加人、办离职、密码丢了怎么找回、备份升级、给几家公司分别开组织——都在 [账号与部署运维](账号与部署运维.md)。

如果需要让 Agent 操作服务器上的 Chrome，请看[对标学习与服务器运行](对标学习与服务器运行.md)中的 CDP 小节。CDP 只连本机回环地址，不能也不应该直接暴露到公网。

> ⚠️ 这个 agent 手里有 `run_shell`。**把它挂到公网 = 把这台机器的 shell 挂到公网。**
> 起来之后**第一件事就是注册管理员账号**（空库对外挂着，等于谁先访问谁是管理员），
> 然后关掉开放注册、确认 设置 → 安全 里的「安全网关」开着、用低权限账号跑。别裸奔。

## Linux 系统沙箱

多人共用时，成员的命令和脚本必须在系统沙箱里跑。Linux 上用 bubblewrap：Key、账本、备份和别家组织的目录都看不见，`/proc` 里也看不到服务进程。

**Docker**：镜像已自带 bubblewrap，`docker-compose.yml` 已开放沙箱需要的三项权限（`SYS_ADMIN` 能力、`seccomp=unconfined`、`apparmor=unconfined`）。bubblewrap 进沙箱前会丢掉全部能力，agent 的命令拿不到这些权限。这三项放开的是容器这一层隔离，如果你的安全策略不允许，去掉后服务照常运行，但成员的命令会被拒绝。

**直接装在 Linux 上**：运行 `sudo apt install bubblewrap`。

在 设置 → 安全 里能看到沙箱状态。沙箱立不起来时，平台管理员自己的任务不受影响，成员的 `run_shell`、`run_node` 会报错并说明原因。

确实不需要隔离（比如内网单一团队，接受成员读到 Key 的风险），可以在 `config.json` 的 `security` 里写 `"allow_member_unsandboxed": true`。

和 macOS 相比，Linux 沙箱挡不住连接本服务自己的端口。接口仍要登录，没有登录凭证拿不到数据。
