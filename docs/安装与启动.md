# 安装与启动

## 下载安装包（最省事）

不想碰命令行就走这条：去 [Releases](https://github.com/CatCatUncle/openworkbuddy/releases) 下对应的包，装完打开，填个模型 API Key 就能用。

| 系统 | 下哪个 |
|---|---|
| macOS · Apple 芯片（M1/M2/M3/M4） | `OpenWorkBuddy-*-mac-arm64.dmg` |
| macOS · Intel | `OpenWorkBuddy-*-mac-x64.dmg` |
| Windows 10/11（x64 和 ARM 都用这一个） | `OpenWorkBuddy-*-win-setup.exe`（双击即装，装完自动启动，不需要管理员权限；骁龙 X / Surface Pro X 也是它，装的时候自动选架构） |
| Windows 免安装版（**只在装不了软件时才用**） | `OpenWorkBuddy-*-win-x64-portable.exe` / `-win-arm64-portable.exe`（不装、双击直接跑。代价见下面「双击了没反应？」——**第一次启动可能要等好几分钟，期间任务管理器里有进程、屏幕上什么都没有**。能装就装上面那个）|

**Windows 第一次打开会弹「Windows 已保护你的电脑」**（SmartScreen）。同样是因为没有代码签名证书（一年几千块，这是个免费开源项目）。点弹窗里的**「更多信息」→「仍要运行」**即可——那行「更多信息」是灰色小字，很多人没看见就以为装不了。

**macOS 第一次打开会被拦**，提示「无法打开，因为无法验证开发者」。这个包没有 Apple 的付费开发者证书签名（一年 99 美元，这是个免费开源项目），不是它有毒。放行方式二选一：

- 右键点应用图标 → 打开 → 弹窗里再点一次「打开」
- 或者终端跑：`xattr -cr /Applications/OpenWorkBuddy.app`

**你的东西都在 `~/OpenWorkBuddy`**（Windows 是 `C:\Users\你\OpenWorkBuddy`）：配置、账号、聊天记录、工作区成果文件、装的技能和插件，全在这一个文件夹里。

- 想换地方：设环境变量 `OPENWORKBUDDY_HOME=/你想放的路径`
- 备份就是把这个文件夹拷走；换电脑把它拷过去就行
- **卸载不会删它**——里面是你的 PPT 和 Word，卸个软件不该顺手删掉。真要清干净就手动删这个文件夹

> Windows 的包是在 GitHub Actions 上打的，作者本机只有 Mac、没法运行验证。Mac 的包是本机装起来跑通过的。Windows 上遇到问题请开 issue。

## 双击了没反应？

这是收到最多的一类反馈（[issue #1](https://github.com/CatCatUncle/openworkbuddy/issues/1)）。按下面的顺序排查，多半第一条就是。

**先看启动日志。** 从 v0.1.5 起，每次启动都会往这里写一份：

```
~/OpenWorkBuddy/logs/boot.log            # Windows: C:\Users\你\OpenWorkBuddy\logs\boot.log
```

连这个文件夹都建不出来时，它会退到系统临时目录写 `OpenWorkBuddy-boot.log`。日志最后一行停在哪儿，问题就在哪儿。开 issue 时把它贴上来，比任何描述都管用。

**源码跑的，先跑一句体检。** Node 版本、依赖、数据目录、配置文件、模型渠道、端口、工作区、底层引擎，一次查完，每条不合格的都跟一句「怎么修」：

```bash
node cli.js doctor        # npm link 过的话直接 wb doctor
```

有要处理的它退出码给 1，所以能写成 `wb doctor && npm start`——查不过就不启动。报告里**只报数不报值**，一个 Key 都不会带出来，可以整段贴进 issue。


| 现象 | 为什么 | 怎么办 |
|---|---|---|
| **免安装版**：双击后任务管理器里有 `OpenWorkBuddy.exe`，屏幕上几分钟没动静 | 免安装版的原理是「自解压」：每次启动都要把整个应用（一万多个文件）解压到 `%TEMP%`，Windows Defender 还会逐个扫一遍。机械硬盘或公司电脑上第一次可能要好几分钟 | **改用 `-win-setup.exe` 安装版**，它只解压一次。免安装版只在公司电脑不让装软件时才值得忍 |
| 弹「Windows 已保护你的电脑」，没有「运行」按钮 | SmartScreen 对没有代码签名证书的程序默认拦截 | 点灰色小字**「更多信息」**，下面就会出现**「仍要运行」** |
| macOS 提示「无法验证开发者」 | 同上，没买苹果证书 | 右键图标 → 打开 → 再点一次「打开」；或终端 `xattr -cr /Applications/OpenWorkBuddy.app` |
| 窗口一直不出现，或者出来是一整片黑 | 显卡驱动画不出来（虚拟机、远程桌面、老显卡上常见） | 在 `~/OpenWorkBuddy/config.json` 的 `server` 里加一行 `"disable_gpu": true`；或启动前设环境变量 `OPENWORKBUDDY_DISABLE_GPU=1` |
| 弹框说「放数据的文件夹建不起来」 | 公司电脑常把用户目录重定向到网络盘，离线时就写不了；也可能是磁盘满了 | 设环境变量 `OPENWORKBUDDY_HOME` 指到本机一个能写的文件夹，比如 `D:\OpenWorkBuddy` |
| 弹框说「已经在运行了，但窗口没出来」 | 上一次启动卡在半路，进程没退，占着单实例锁 | 任务管理器（macOS 活动监视器）里结束 OpenWorkBuddy，再打开 |
| 弹框说端口用不了 | Windows 上 Hyper-V / WSL 会预留成段的端口。命令行 `netsh interface ipv4 show excludedportrange protocol=tcp` 能看到保留段 | 把 `~/OpenWorkBuddy/config.json` 里的 `server.port` 换一个没被预留的，比如 `3810` |

无论哪种失败，程序都会弹一个写着原因和解法的窗口——**如果你什么都没看到，那本身就值得开一个 issue**，并把上面那份 `boot.log` 带上。

## 有新版了怎么升

**设置 → 关于 → 检查更新**（也可以直接看 [Releases](https://github.com/CatCatUncle/openworkbuddy/releases)）。它会去 GitHub 查最新的 tag 和你本机版本比一比，然后按**你这种装法**告诉你怎么升：

| 你怎么装的 | 怎么升 | 数据会不会丢 |
|---|---|---|
| 源码跑的（`npm start` / `npm run app`） | `git pull && npm install`，重启就是新版 | 不会，**不用重装** |
| 安装包装的（dmg / setup.exe） | 下新的包覆盖装一次 | 不会，配置和成果都在 `~/OpenWorkBuddy`，覆盖安装不动它 |

> **为什么没有「点一下自动更新」**：这两个包都没有签名（Apple 开发者证书一年 99 美元，Windows 代码签名证书也要钱，这是个免费开源项目）。electron-updater 在 macOS 上走 Squirrel.Mac，会校验代码签名，未签名的包必然失败——硬做出来只会是一颗永远报错的按钮。所以这里做的是「如实告诉你有没有新版、新版在哪、你这种装法怎么升」。哪天真买了证书，换成 electron-updater 就行，接口形状是照着它对齐的。
>
> 查不到的时候会明说「查不到最新版本」，**不会**因为网络不通就装作「已是最新」——那种假绿最坑人。

**多久发一个版本**：没有固定日程，攒够一批**用户真能感知的改动**就发一个（tag `vX.Y.Z` 一推，GitHub Actions 自动打 mac/win 四个包挂上 Release）。经验节奏是**一两周一个小版本**（0.1.x：修 bug、补渠道、改交互），破坏性的改动才进中位号。想追最新的直接跑源码，`git pull` 就是最新；只想要稳的就等 Release 里的包。急着修的线上问题会当天发补丁版，不攒。

## 从源码启动（开发者）

### 0. 先准备

| 要什么 | 说明 |
|---|---|
| **Node.js 18 或更高** | [nodejs.org](https://nodejs.org) 下载即可；macOS 有 Homebrew 的话 `brew install node` |
| **git** | 用来拉代码 |
| **一个大模型的 API Key** | DeepSeek / 通义 / 智谱 / Kimi / OpenRouter 都行，哪个都只要一个。不想花钱就装 [Ollama](https://ollama.com) 跑本地模型，不用 Key |

检查一下 Node 装好没：

```bash
node -v      # 要 v18.0.0 以上
```

低于 v18 也不用自己对着版本号猜：直接启动会当场拦下来，把你机器上是哪个版本、该怎么升写清楚再退出——不会让你跑到一半才撞上一句 `fetch is not defined`。


### 1. 拿代码、装依赖

```bash
git clone https://github.com/CatCatUncle/openworkbuddy.git
cd openworkbuddy
npm install
```

> 国内装 Electron 卡住的话，先设个镜像再 `npm install`：
> `export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`

**嫌麻烦？** macOS / Linux 上有一键脚本，上面这些它全包了（查环境 → 装依赖 → 生成配置 → 起服务）：

```bash
bash install.sh
```

### 2. 启动

三种跑法，挑一个：

```bash
npm run app                          # 桌面版（Electron 窗口）—— 自己用推荐这个
npm start                            # 纯服务端，浏览器打开 http://localhost:3800
npm run cli -- "帮我写一份本周周报"     # 命令行，适合脚本里调
```

桌面版和 `npm start` 的区别只有一层外壳：桌面版多了独立窗口、全局快捷键和内置浏览器渲染，服务端和界面是同一套。

CLI 跟它俩共用同一份配置、技能和 MCP 连接器，只是没有窗口——答案直接走 stdout，能塞进管道、脚本和 cron。参数、`--json` 事件格式和几条现成的用法见 [命令行用法](命令行用法.md)。

macOS 想双击图标打开（不碰终端）的话，跑一次 `bash scripts/make-mac-app.sh`，会在 `~/Applications` 生成 OpenWorkBuddy.app——它启动的永远是本仓库的最新代码，改完代码重开 App 就生效；重复打开会聚焦已有窗口，不会叠第二个实例。

Windows 也能直接跑：装好 Node.js 后同样 `npm install` + `npm run app` 即可。`run_shell` 会自动走 cmd（macOS/Linux 走 zsh/bash），数据备份用的是系统自带 tar（Windows 10 1803+ 就有），图表/图文卡片渲染走 Electron 内置浏览器，都不用额外装东西。

端口被占了就换一个：`PORT=3801 npm start`（Windows cmd 写法：`set PORT=3801 && npm start`）。

### 3. 第一次打开，两步就能用

1. **注册第一个账号。** 界面会让你注册——**第一个注册的账号自动是管理员**。注册完之后默认就不许别人自己注册了，别人要用得管理员去开（见[多人一起用](多人协作.md)）。
2. **填 API Key。** 登录后会弹引导页，选服务商、粘 Key。它会**当场发一条真实请求验活**，通过了才保存——不会让你等到发第一条消息才发现 Key 是错的。

Key 不用手动写进配置文件。以后想改，去 **设置 → 模型**，保存即生效。

### 4. 下第一条任务

在输入框里说人话就行，比如「帮我做一份介绍 OpenWorkBuddy 的 PPT」。左边能看到它一步步在干什么，做完的文件在右边「成果文件」里点开预览。

**文件存在哪**：默认是项目目录下的 `workspace/`。想换地方，去 **设置 → 工作目录**，或者在左上角「项目」里建一个新项目并指定目录——每个项目一个目录，切项目就是切目录。

### 启动时容易卡住的几件事

| 现象 | 原因和解法 |
|---|---|
| `npm install` 卡在 electron | 设镜像：`export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` |
| `EADDRINUSE` 端口被占 | `PORT=3801 npm start`；桌面版遇到这个会直接连已经在跑的那个实例 |
| 发消息报上游错误 | Key 或 base_url 不对，去 设置 → 模型 里改，那里会当场验活 |
| 界面一直转圈（服务器部署） | 反代没关缓冲，SSE 流被攒住了。nginx 加 `proxy_buffering off` |
| 生成的 Word/PPT 中文变方块 | 缺中文字体（自己精简过 Docker 镜像的话补 `fonts-noto-cjk`） |
| 改了技能要不要重启 | 不用。`skills/` 每次任务重读磁盘。改 `config.json` 才要重启（界面里改是热生效的） |
