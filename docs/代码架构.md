# 代码架构

[参与贡献](../CONTRIBUTING.md#项目结构) 里那张目录图是短版，这一篇是展开版：代码分几层、每层放什么、谁能 require 谁，
以及新加一个 IM 渠道、一个工具、一组路由时文件该放哪、要改哪几处。
规矩后面写了「为什么」。要改规矩，先看懂当初躲的是什么。

---

## 一、七层一张图

仓库根只留入口文件，其余运行时源码都在 `src/` 下。按「谁依赖谁」分成七层，**只许 require 同层或更低的层**：

```
L6 入口    server.js  cli.js  electron-main.js  server-host.js
           electron-builder.config.js  eslint.config.js  eval/  scripts/
             │  随便 require
             ▼
L5 应用    src/server（含 routes/）   src/cli   src/im   src/desktop
             │  四块之间不许横向 require
             ▼
L4 智能体  src/agent（含 gates/）   src/tools   src/engines
             ▼
L3 业务域  src/domains/{account, media, content, library}
             ▼
L2 核心    src/core/{config, model, billing, safety, judge, memory, ext, obs, automation}
             ▼
L1 平台    src/platform（含 render/）
             ▼
L0 工具    src/util
```

箭头只往下走。层是按文件的真实路径算的：放进哪个目录，就是哪一层。

为什么要分层：一百六十多个模块平铺在仓库根和三个老目录里的时候，底层模块会顺手 require 上层（比如媒体探测、合成任务去引命令行体检的部件），
改一个底层文件要连带想全仓的事。分了层以后，读一个文件只需要往下看，改一个文件只会影响往上的那些。

## 二、每层放什么

| 层 | 目录 | 放什么 | 例子 |
|---|---|---|---|
| L0 工具 | `src/util/` | 小工具函数。只依赖 Node 内置模块和同层文件，不读配置 | `text-width.js` 算显示宽度、`totp.js`、`winname.js` |
| L1 平台 | `src/platform/` | 跟运行环境打交道的底座，不懂业务：路径、落盘、日志、找外部命令、Windows 差异、截图和缩略图 | `paths.js`（`dataPath()` / `appPath()`）、`store.js`（原子写 + `.bak`）、`log.js`、`render/` |
| L2 核心 | `src/core/` | 不分业务、大家都要用的能力，按子目录归类 | `model/llm.js` 模型适配、`safety/security.js` 安全中心、`ext/skills.js` 技能、`memory/memory.js`、`billing/quota.js`、`automation/scheduler.js`、`obs/trace.js` |
| L3 业务域 | `src/domains/` | 有业务语义的一块一块：账号与组织、媒体合成、内容交付、资料库 | `account/`（账号、组织、权限、商业授权）、`media/`（时间线合成、短剧流水线）、`content/`、`library/` |
| L4 智能体 | `src/agent/` `src/tools/` `src/engines/` | Agent 主循环、内置工具、外部引擎 | `agent/agent.js` 主循环、`agent/tools.js` 工具门面、`agent/gates/` 四道闸、`tools/` 拆出来的大块工具实现、`engines/` 接 Claude Code / Codex |
| L5 应用 | `src/server/` `src/cli/` `src/im/` `src/desktop/` | 某一个应用自己的部件，别的应用用不上 | `server/routes/` 五组路由、`cli/` REPL 部件、`im/` IM 总线和各渠道、`desktop/` 宠物窗和服务子进程看护 |
| L6 入口 | 仓库根的入口文件、`eval/`、`scripts/` | 把下面各层拼起来跑：建 express、开窗口、解析命令行 | `server.js`、`electron-main.js`、`cli.js` |

数据文件不进层：`experts.json`、`config.example.json` 在仓库根，`skills/` `plugins/` `public/` 各管各的。
`src/` 下被 require 的 `.json`（比如 `src/platform/builtin-skill-hashes.json`）按它所在的目录算层。

## 三、依赖规矩

`test/layers.js` 从源码的语法树里把依赖边抠出来，逐条判。下面每一条破一处就红：

1. **只许往下或同层 require。** 上行（比如 `src/util/` 去 require `src/agent/`）一律不行。
   函数体里的懒加载 `require` 也算——写在函数里只是推迟了加载，依赖关系一点没少。
2. **L5 的四块互不 require。** `src/server/` 不引 `src/im/`，`src/cli/` 不引 `src/desktop/`，以此类推。
   两个应用都要用的东西，说明它不属于任何一个应用，往下挪到 L4 或更低。
3. **非入口文件不许 require 入口。** 路由要用 `server.js` 里的东西（鉴权、会话、配置读写），由 `server.js` 挂载时当参数传进去，
   不回头 `require("../../../server")`：入口一 require 就是整台服务器跟着起，测试也没法单独加载这个文件。
4. **不许有环。** 同层也不行。环只算模块依赖（`require` / `require.resolve` / `tryRequire`），Worker 和子进程不算。
   两个模块互相 require 时，先加载的那个拿到的是半截 `exports`，而且这种错只在特定加载顺序下才冒出来。
5. **按路径加载的脚本别再 require。** 一个文件要是被 `spawn` / `fork` / `new Worker` / preload 按路径跑起来，
   就别再被别人 `require`：它既当模块又当进程入口，顶层代码在 require 时也会跑，改一边容易伤另一边。
6. **每条本地依赖都得解析到文件。** `require`、`require.resolve`、`tryRequire`、`new Worker(…)`、`fork(…)`、
   `path.join(__dirname, …"x.js")`、`appPath(…"x.js")` 这几种写法都会被认出来。
   `tryRequire` 吞错、Worker 路径写错，平时谁都看不见，搬一次家就静悄悄坏了，所以这里逐条核。

下层确实要用上层的东西怎么办：**别 require 上去，让上层传下来。** 两种现成写法：

- 路由文件导出 `createXxxRouter(deps)`，`server.js` 挂载时把要用的函数塞进 `deps`（见 `src/server/routes/prompt-tpls.js`）。
- `src/tools/media.js` 要用 `tools.js` 的工作目录，由 `tools.js` 加载时经 `bindWorkspace` 递过去，不反过来 require。

## 四、白名单：只减不增

目录重整时有几处依赖一下子拆不干净，先记在 `test/layers.js` 的两张白名单里。**条数写死了，只许变少**；
名单里的某一项已经修好、不存在了，闸门也会红，提醒你把它从名单里删掉。

| 名单 | 条目 | 打算怎么拆 |
|---|---|---|
| `CYCLE_ALLOW`（同层的懒加载环，3 个） | `src/domains/account/account.js` ⇄ `license.js` | `license.gather` 改成把账号数据注入进去 |
| | `src/core/ext/plugins.js` ⇄ `skills.js` | `parseFrontmatter` 抽到 `src/util/` |
| | `src/agent/mcp.js` ⇄ `tools.js` | 工作目录那套 AsyncLocalStorage 从 `tools.js` 里抽出来 |
| `SPAWN_ALLOW`（require 一个也会被 spawn 的脚本，2 条） | `src/agent/agent.js` → `src/engines/tool-bridge.js` | `tool-bridge.js` 有 `require.main` 守卫，require 进来只拿工具表；以后把表抽成纯数据模块 |
| | `src/engines/bridge.js` → `src/engines/tool-bridge.js` | 同上 |

新代码不该往名单里加东西。真碰上了，先按第三节最后那两种写法改成「传下来」。

## 五、谁在盯着

| 闸门 | 管什么 | 怎么单独跑 |
|---|---|---|
| `test/layers.js` | 上面第三、四节的全部规矩；每个代码文件都得有层；老布局的 `lib/` `engines/` `routes/` 不许再长出来 | `node test/layers.js` |
| `scripts/check-package-files.js` | 打包后核真包：从入口顺着 require 爬一遍，再把 `src/` 整棵树（`SOURCE_DIRS`）逐个文件对一遍，盘上有的运行时文件包里一个都不许少 | `npm run pack` 时自动跑 |
| `electron-builder.config.js` | `files` 白名单里 `"src/**/*"` 一条带上全部源码；`"*.js"` 只匹配仓库根的入口 | — |
| `tsconfig.check.json` | 类型闸门扫 `src/**/*.js` | `npm run typecheck` |
| `test/lib/mod.js` | 测试找源码的唯一读法：名字 → 路径（`mod("agent")`、`mod("routes/canvas")`）。入口走 `test/lib/entry.js` | — |
| `test/lib/src.js` | `src("server")` 拼服务端源码给几十个测试扫；建 express 路由的模块要在 `SERVER_PARTS` 里点名 | `node test/layout-invariants.js` |

这几道都在 `npm test` 里。只想快速过一遍布局相关的：

```bash
node test/all.js --only layers,layout-invariants,repo-hygiene,lint,typecheck
```

## 六、新代码放哪

先问它依赖谁，再放进**能满足它全部依赖的最低那一层**：

1. 只依赖 Node 内置模块、不读配置的小工具函数 → `src/util/`
2. 碰运行环境（路径、落盘、子进程、渲染），但不懂业务 → `src/platform/`
3. 各块业务都要用的能力 → `src/core/` 下对应的子目录
4. 属于某一块业务 → `src/domains/` 下对应的子目录（新业务就新开一个子目录）
5. Agent 循环、工具、外部引擎 → L4
6. 只有一个应用用得上 → 那个应用自己的目录

几条容易踩的：

- **别在 `src/` 下新开顶层目录。** 层是按目录前缀认的，`src/foo/` 不在七层名单里，`test/layers.js` 的第②节会红。
  层里面新开子目录没问题（`src/core/foo/`、`src/domains/foo/`）。
- **别在仓库根新开放代码的目录。** 打包白名单只认 `src/**`，根上的新目录进不了装机包。
- 测试要引新文件，在 `test/lib/mod.js` 的 `TABLE` 里加一行。名字是文件名去掉扩展名，同名时带前缀区分（路由带 `routes/`）。

## 七、照着做

### 加一个 IM 渠道

1. 新建 `src/im/im-xxx.js`，导出一个 `createXxxConnection({ getConfig, log, onMessage })`。
   主动拨出的长连接照 `src/im/im-qq.js` 写，平台回调型的照 `src/im/im-wechat.js` 写。
2. 在 `src/im/im.js` 里 `require("./im-xxx")`，跟 QQ、企微那几段并列接上：收到消息交给 `onMessage`，回复走它给的 `reply`。
3. 渠道文件在 L5 的 `im` 这一块：可以引 `src/im/` 自己和 L0–L4，**不许** require `src/server/`、`src/cli/`、`src/desktop/`，也不许 require `server.js`。
   要服务端的东西，由 `im.js` 创建连接时传进去。
4. 可有可无的第三方包照 `im-qq.js` 的 `getWS()` 在用到时再加载，加载不到就报一句人话，说清缺的是什么。

### 加一个内置工具

1. 在 `src/agent/tools.js` 的 `TOOL_DEFS` 里加定义（`name`、`description`、`input_schema`），`executeToolCore` 的 `switch` 里接上。
2. 实现超过几十行，放进 `src/tools/xxx.js`，`tools.js` 里 `require("../tools/xxx")` 去调。
   `src/tools/` 的文件**不许** require 回 `tools.js`（同层环，白名单只减不增），要用工作目录这类东西照 `media.js` 的 `bindWorkspace` 传过来。
   `src/tools/` 下的新文件会自动拼进 `src("tools")`，测试扫得到。
3. 写文件、跑命令、联网、花钱的工具，先过安全闸：拿 `security` 的判定走 `passGate`，该拦就拦，该问就等用户点头。
4. 改了工具的 `description` 要跑评测，见 [改了提示词或工具描述，得跑一遍评测](../CONTRIBUTING.md#改了提示词或工具描述得跑一遍评测)。

### 加一组路由

1. 新建 `src/server/routes/xxx.js`：路由写在模块顶层，导出 `createXxxRouter(deps)` 返回一个 `express.Router()`。
   照 `src/server/routes/prompt-tpls.js` 或 `library.js` 的样子写。
2. 在 `server.js` 顶部 require 它，跟画布、短剧、合成那几组挂在一起：`app.use(createXxxRouter({ … }))`。
   要用 `server.js` 里的函数，就放进这个参数里传过去。
3. 在 `test/lib/mod.js` 的 `TABLE` 里加 `"routes/xxx": "src/server/routes/xxx.js"`，在 `test/lib/src.js` 的 `SERVER_PARTS` 里点名 `"routes/xxx"`。
   `test/layout-invariants.js` 第⑦节会查：凡是建 express 路由的模块，都得在这张名单里。
4. 路由文件在 L5 的 `server` 这一块：可以引 `src/server/` 自己和 L0–L4，不许 require `src/im/`、`src/cli/`、`src/desktop/`。

## 八、闸门红了怎么读

`node test/layers.js` 的输出分四节，红的那一行后面会列出具体是哪条边：

| 红的是 | 意思 | 怎么改 |
|---|---|---|
| ① 有边解析不到 | `require` 或 Worker / preload / spawn 的路径写错了，或者文件挪了没跟着改 | 按列出的 `文件:行号` 改路径 |
| ② 有文件没有层 | 文件放在了七层以外的目录 | 挪进第六节说的那一层 |
| ② 老目录又出现了 | 有人建回了 `lib/` `engines/` `routes/` | 挪进 `src/` 对应的层 |
| ③ 白名单里的项不在了 | 那个环或那条 require-spawn 已经拆掉 | 从名单里删掉这一项 |
| ④ 上行 / L5 横向 / 非入口 require 入口 | 依赖方向反了 | 把被依赖的东西往下挪，或改成由上层传下来 |
| ④ 白名单外的环 | 新长出一个环 | 抽出两边共用的那部分放到更低一层，或改成传参 |
