# 安全（这个 agent 手里有 shell）

先选档位（输入框旁一键切，参考 Claude Code）：**只看不动**（只读，不写文件不跑命令）→ **每步都问** → **自动改文件**（默认：工作目录随便改，删除、sudo 这类命令照样问）→ **全自动**（只剩文件黑名单和审计兜底）。

设置 → 安全中心。每一项都是真闸门：文件黑名单、命令审批、网络白名单、运行时开关、审计日志（`data/audit.json`，环形 1000 条）。审批弹在输入框上方，批准 / 拒绝都行；超时（默认 120 秒）或者点停止都按拒绝算。

命令闸拆命令的时候，下面这些都算**同一条命令里的一段**，会逐段核对：

```bash
rm -rf ~/x                 # 直接写
echo hi; rm -rf ~/x        # ; && || | & 串起来
echo hi
rm -rf ~/x                 # 换行——agent 写的多行脚本
echo $(rm -rf ~/x)         # 命令替换
echo `rm -rf ~/x`          # 反引号
( rm -rf ~/x )             # 子 shell
FOO=1 rm -rf ~/x           # 前面挂环境变量
/bin/rm -rf ~/x            # 写全路径
nohup rm -rf ~/x           # 套个壳
find . -name "*.log" -delete
```

引号里的分隔符不当分隔符（`grep "a|b"` 不会被拆开），`echo "记得 rm 掉旧文件"` 也不会误弹审批。

两条跟直觉不太一样、但故意这么定的：

- **文件黑名单排在命令放行名单前面。** 黑名单是「永远拦」——不能因为你放行了 `cat `，`cat ~/.ssh/id_rsa` 就跟着过去。这几道闸拦得住的是「顺手」，不是「刻意绕」——刻意绕的那种，交给下面的[系统沙箱](#系统沙箱macoswindows)。
- **`open` / `xdg-open` / `start` / `explorer` 也在「先问」那张表里。** 它们不删东西，进这张表不是因为危险，是因为烦：agent 做完一份文件顺手 `open` 一下，你桌面上就弹一个窗口，而对话里本来就会自动出预览卡。用户明确说「打开」才开，没说的话交付只报路径；全自动档也会弹一次确认。
- **`run_node` 的代码也过闸。** 只守 `run_shell` 那扇门是守不住的，一句 `require("child_process").execSync(...)` 就从旁边过去了。

## 系统沙箱（macOS、Windows）

上面那些闸是看命令原文判的。可一条命令能换出无数种写法，靠读原文判它会不会去碰 `config.json`，是判不完的。所以 `run_shell`、`run_node`、后台命令再套一层**操作系统自己的隔离**：不管命令怎么写，系统按真实路径拦。

| | macOS | Windows |
| --- | --- | --- |
| 靠什么 | 系统自带的 `sandbox-exec` | 系统自带的「完整性级别」：命令降到低级别跑（小助手 `native/owb-sandbox`，随安装包带） |
| 读不到 | Key（`config.json` 那几份）、账本、备份 | 同左 |
| 写不进 | 应用自己的目录、数据目录 | 工作区和临时目录以外**一律写不进**：应用目录、数据目录、主目录、注册表都不行 |
| 连不上 | OpenWorkBuddy 自己的端口 | 挡不住（见下） |
| 每条命令多花 | 约 7 ms | 约 13–16 ms（CI 上真 Windows 实测；第一次起来预检约 90 ms，之后不再走） |

**开关**在 设置 → 安全 → 系统沙箱，四档：

- **默认**（不动它就是这档）：多人用的 Mac 按「必须」，其余按「自动」。
- **自动**：立不起来照常跑，原因记下来，设置页那一栏看得到。
- **必须**：立不起来就不跑，告诉你命令没有执行。
- **关闭**：不隔离。某个工具在沙箱里不正常、你又确定要跑它，才关。

命令被沙箱拦下时，输出里会多一句「这条命令在系统沙箱里跑……开关在 设置 → 安全 → 系统沙箱」——让模型别换着写法反复去撞，也让你知道去哪儿关。

**Windows 那层做不到的，说在前头：**

- **挡不住连本机端口。** 完整性级别管的是文件和注册表，不管网络。OpenWorkBuddy 自己的接口照样要登录鉴权，Key 也不放进任何子进程的启动环境，所以连上了也拿不到东西。
- **多人共用时，各组织的工作区彼此读得到。** macOS 那层会把别家组织的目录藏起来，Windows 这层只管「写」不管「读」。多组织共用一台 Windows 机器，别指望靠它隔开。
- **工作区会留一个「低级别能写」的标记。** 打在工作区目录上、往下继承，删工作区就跟着没了。整块盘、主目录、系统目录不许当工作区——给这些地方打标记等于把大门拆了，直接拒绝。
- **从外面「剪切」进工作区的文件，带着原来的标记。** 沙箱里的命令改不了它；复制进来就没这个问题。
- **不是机密的文件照样读得到**，跟 macOS 一样：沙箱守的是 Key 和账本，不是把整台电脑藏起来。

Linux 上没有这一层，档位怎么设都是不套。外部引擎（codex、claude）自带沙箱，套娃起不来，所以不包它们——codex 默认就只写得进工作区、不联网。

## 本机引擎（Claude Code、Codex）

换成本机的 Claude Code 或 Codex 跑，命令和改文件由那个 CLI 自己执行，**不经过**上面那几道闸，也不套系统沙箱（见上一节最后一段），守门的是它自带的权限和沙箱。这边能做的是这几件：

- **档位翻成它们自己的开关。** 只看不动 → claude 的 plan、codex 的 read-only；每步都问 → claude 的 default、codex 的 read-only（这条路没人能当场点同意，要写要跑的会被拒）；自动改文件 → acceptEdits / workspace-write，「先问」名单里的命令和删除直接禁；全自动 → bypassPermissions / workspace-write。属主在引擎设置里手填了档位、沙箱的，以手填的为准。
- **问答、计划一律只读。** 不管档位是哪档，claude 按 plan、codex 按 read-only 跑；属主手填的档位、沙箱、放宽权限的附加参数，这一趟不用，运行页上会说一句。只借读的工具，你配的连接器一个不挂，命令行里也没有 owb。
- **要审批的动作交给安全中心判**（只有 Claude Code；属主在 设置 → 智能体 → 底层引擎 那张卡上勾，默认关）。名单外的命令、工作目录外的文件、抓网页，照安全中心的规则判：名单放行的照跑；要人点头的、不认得的、判的时候出错的一律拒——这条路上没人能当场点「允许」。放行的命令由 Claude Code 自己跑，**不套系统沙箱**。用的是 claude 没写进文档的参数。
- **借给它的工具在这边执行**（两个引擎都有；属主勾，默认关）。生图、配音、资料库这些借出去的工具，每一单都交回主程序、在这一趟的上下文里跑：审批卡在网页、终端、手机上都看得到，账记在发起这一趟的人名下，组织规矩、档位都按这一趟的。
  - 一趟一张凭据，跑完就作废；凭据文件放在临时目录下单独一个文件夹里（macOS、Linux 上文件夹 0700、文件 0600；Windows 上在本人的临时目录）。名单外的、叫停之后来的一律拒。
  - 开跑时口子没开起来，运行页上说一句，这一趟照老样子由桥自己跑；开起来以后哪一单交不回去，就明说这一步没做成，不悄悄改到桥那头跑。
  - Codex 的命令沙箱连不了本机套接字，它命令行里敲的 owb 照旧自己跑，只有 MCP 那条交回来。
  - Windows 上走命名管道，这一套在 CI 的真 Windows 上跑过。
- **不勾的时候**，借出去的工具在 CLI 拉起的那个小进程（桥）里跑：读的是同一份设置，要人点头的一律拒（那个进程里没人能点），账照记。

## 装技能这件事，是另一扇门

上面那些闸守的是「agent 跑的时候想干什么」。技能守的是另一头：**它照着谁写的指令跑**。

一个技能就是一个目录，里头一份 `skill.md` 是给 agent 看的操作说明书。所以装一个技能等于把陌生人写的指令接进来，而装完之后**没有第二道门**——上面那几档权限管的是执行，管不了「谁在下指令」。

所以 `src/core/safety/skill-guard.js` 卡在安装路径上，34 条规则，三档结论：

| 结论 | 条数 | 装不装 |
| --- | --- | --- |
| **block** | 10 | 默认不装。平台管理员可以显式强装，那一下写日志 + 写 `.install.json` |
| **warn** | 24 | 摊开给你看，点一次「我看过了」才装 |
| ok | — | 直接装 |

覆盖的四条路一条不漏：GitHub 整仓 / 子目录、GitHub 单个 `.md`、界面上手写粘贴、启动时自动补的默认技能。闸卡在 `copySkillFolder` **之前**——装完再扫等于没扫，文件一落进 `skills/`，`loadSkills()` 下一条任务就把它带上了。

几个这个项目特有的判断，不是通用规则表抄来的：

- **frontmatter 里那句 `description` 命中会升一级。** 它每一条任务都会进系统提示词（`src/agent/agent.js` 里那份技能清单），不管这次用不用得上这个技能。写在正文里的注入还得等技能被加载，写在这儿的是常驻。
- **`allowed-tools` 只 warn 不 block。** 我们的 frontmatter 解析器只认 `name` 和 `description`（`src/core/ext/skills.js`），所以这个键在本机**不生效**；但同一份文件被人拷去 Claude Code / Cowork 就生效了，所以留着提醒，不拦。
- **自带的 `node_modules` / `.venv` 不逐个文件扫**，只报「它带了一整棵依赖树」——那里头一条都不是技能作者写的，逐个扫只会把真该看的几行淹掉（实测一个 `.venv` 一家贡献 60 多条假命中）。
- **技能是整台机器一份的**（`skills/` 只有一个目录，不分组织），所以增删改装全部锁平台管理员。加这道闸之前，任何一个登录用户都能给所有人的 agent 递指令。

**它的上限在哪：** 定位是「装之前把话说清楚」，不是查毒。公开标注集上纯静态规则检出率约 74.9%，**四个漏一个**。反过来拿本仓库 34 个真技能量，误拦 2 个（5.9%），且都是真命中——其中一个是资讯技能缓存的博客正文里有一句在**讲解**「让 Claude 去读 `~/.aws/credentials` 再 POST 出去」。同一句话在指令里是攻击、在抓回来的资讯里是新闻，正则分不出来。这就是为什么 block 必须能被人显式放行：一道人绕不过去的闸，人就会绕过整个工具（直接把目录拷进 `skills/`，什么也拦不住）。

### 想多一把尺子：外挂 toolward

上面那个上限是静态规则本身的上限，不是「把规则表写厚一点」能补上的。真要多一层，办法是多一个**独立作者、独立规则表**的扫描器：两把尺子量同一份文件，漏的概率是各自漏的概率相乘。

[toolward](https://github.com/CatCatUncle/toolward) 是同一个作者的另一个项目，专做 agent 技能和 MCP 连接器的静态安检：37 条规则分六族——TW1xx 提示词注入与工具投毒、TW2xx 供应链、TW3xx 密钥、TW4xx 执行与权限、TW5xx 网络与外传、TW6xx 治理。本机装了它（`npm i -g toolward`），下面三件事自动发生：

- **装技能时多扫一遍**（目录 / GitHub 单个 `.md` / 界面粘贴三条路都算），结论跟 `skill-guard` 的合进同一张清单，每条前面标着是 `〔toolward TW101·严重〕` 还是本地规则。`.install.json`、强装留痕、解释文案都没改——外挂报告被做成了跟自带扫描器**一模一样的形状**，所以闸门、解释、落盘三处代码一个字没动，只在三个安装入口各加一句 `merge()`。
- **存 MCP 连接器时扫一遍配置**，**只提醒、从不拦**——连接器配错了拦下来人就没法干活了，而这里真正值钱的是「你接的这个 npx 包没锁版本」这类话。
- **`openworkbuddy doctor` 里多一行**：它在不在、哪个版本、这会儿用不用得上。

合的规矩是**只会更严不会更松**：它说 block 就 block，它没说的按 `skill-guard` 原来的判。所以挂上它之后，本来拦得住的不可能变成放行（`test/toolward.js` 里有一条反向断言专门盯这个）。

**几条边界，都是故意划的：**

- **它不在 `package.json` 里。** toolward 是 PolyForm Noncommercial 1.0.0 授权：个人、教学、学术、公益、政府免费，**公司里用要单独授权**（条款见 toolward 仓库的 LICENSE）。写进依赖等于替每一个商业用户默默添一条授权义务，这个主不能替人做。装不装、要不要买授权，你自己定。
- **不 `npx` 现拉。** `npx -y toolward` 每次都会从网上拉一个没审过的版本下来跑，而这恰好是它自己 TW2xx 那族要拦的行为——一边查供应链一边干这个说不过去。所以只认你自己装到 PATH 上的那一个；Electron 里 PATH 是残的，另外找了 `/usr/local/bin`、`/opt/homebrew/bin`、`~/.volta/bin`、`~/.bun/bin`、`~/.local/bin` 这几个常见目录。设置里也能指死一个绝对路径，**指死了就不回退到 PATH**——不然会出现「我以为跑的是我自己编译那份」。
- **崩了不算拦，也不算放行。** 超时（20 秒）、退出码不对、吐出来不是 JSON，一律当「它没跑过」，绝不返回一份空报告——空报告会让界面上写「没扫出问题」，那是句谎话。连着失败还会歇 5 分钟，免得一个坏掉的二进制让每次装技能白等 20 秒。
- **连接器的密钥不出门。** 递给它的那份临时 `.mcp.json` 里，`env` 和 `headers` 的**值**全换成 `***`，键名留着——留着它才认得出「这儿有个 token 字段」，连键名一起抹掉反而会让每个配好的连接器都被报成明文密钥。URL 只保留到路径，问号后面一律剪掉。`command` 和 `args` 原样过去：那两个字段才是真会露出「拉了个没锁版本的包」「命令里串了个分号」的地方。这条不是嘴上说说——测试里放了一个假的 toolward，把收到的临时文件原样吐回来，逐字对过真 Key 没进去。
- **开关在你手里。** 设置 → 安全里三档：`auto`（装了就用）/ `advisory`（只提醒不拦，它的 block 降成 warn）/ `off`（完全不调，一个子进程都不起）。环境变量 `OPENWORKBUDDY_TOOLWARD=off|advisory|auto` 压过设置项，`OPENWORKBUDDY_TOOLWARD_BIN` 指死路径。测试里默认 `off`：不然开发机上装没装 toolward 会改变 `skill-guard` 那 76 条断言的结果，绿不绿取决于机器上装了什么。

装之前自己读一眼 `skill.md`。它是 Markdown，不是二进制。
