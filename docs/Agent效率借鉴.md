# Agent 效率设计借鉴

这份文档记录从 Codex、Claude Projects/Cowork、Mosoo、Multica 和 YouMind 中吸收的设计方向。它不是功能承诺，具体是否完成以代码和变更记录为准。

## 值得吸收的机制

| 机制 | 对 OpenWorkBuddy 的落地方式 |
|---|---|
| 项目上下文 | 一个项目绑定工作目录、资料、技能、模型偏好、对话和产出；内容创作与短剧画布都以项目为边界 |
| Ask / Agent 双模式 | Ask 只理解、总结、比较和给方案；Agent 才执行写文件、改稿、生成媒体、发消息和操作浏览器 |
| 任务队列 | 长任务进入后台队列，显示排队/运行/等待确认/失败/完成；用户可继续聊天，不必盯住一个窗口 |
| 可恢复运行 | 保存 run、事件、工具调用、产物和 checkpoint；超时或重启后支持继续，不重复执行已经确认成功的步骤 |
| Review gate | 代码、批量改文件、对外发送、发布草稿、删除文件等高影响动作进入确认或审查，不把“模型说完成”当成完成 |
| 版本与差异 | 文档、内容稿、画布节点和生成媒体都能查看上一版、差异和回滚；AI 改动与人工改动可区分 |
| 多 Agent 隔离 | 并行开发任务使用独立 workspace/worktree；内容创作的派生稿使用独立文件，保留母稿关系 |
| 来源引用 | 外部网页、飞书文档、上传文件和节点成为可引用来源，输出中保留来源和待核实标记 |
| 运行可观测 | Trace 展示工具、模型、耗时、Token、输入输出、错误、产物和成本估算；支持从结果跳回执行现场 |

## 不直接照搬

- Codex 的云端 sandbox、Claude 的托管服务、Mosoo 的 Cloudflare/D1/沙箱和 Multica 的 Go/Postgres 多服务架构，不是当前项目的必要前提。
- OpenWorkBuddy 的优势是本地文件交付、零构建入口、Markdown Skill、多渠道和媒体/短剧画布；效率改造必须继续保持本地优先和可读源码。

## 推荐交付顺序

1. **统一 Run 状态**：把 Web、CLI、飞书、微信和画布 Agent 的任务都记录为可恢复的 run，统一状态、取消、重试和结果链接。
2. **项目上下文**：项目绑定工作目录、素材索引、默认模型、技能和共享提示词；新对话自动显示当前项目上下文，并允许显式切换。
3. **内容工作台**：素材→摘录/笔记→母稿→派生稿；每个派生文件保留来源和母稿，不覆盖用户手稿。
4. **审查队列**：集中展示待确认的命令、外发消息、发布动作和生成结果，完成后才标记交付。
5. **并行与隔离**：在安全策略允许时为多个 Agent 分配独立成果目录；合并前自动跑测试和产物检查。

## 用户能马上用的约定

- 想问问题、读材料：说“分析/总结/比较”，使用 Ask 思路。
- 想让 Agent 改文件或生成结果：说“执行/生成/改写/导出”，使用 Agent 思路。
- 想继续上次工作：使用已有会话续接，不新开一条描述相同的任务。
- 想批量派生内容：先指定母稿、平台、受众、语气和输出目录，再生成多个可编辑版本。
