# 编码规范

[参与贡献](../CONTRIBUTING.md#代码约定) 里的「代码约定」是短版，这一篇是展开版：每条规矩写了怎么做，也写了为什么这么定。
规矩后面的「为什么」多半是踩过的坑。它比规矩本身值钱，要改规矩，先看懂当初躲的是什么。

---

## 一、CommonJS，不加构建步骤

- 后端一律 `require` / `module.exports`，文件头写 `"use strict";`。Node 18+ 直接跑，clone 下来就能改，中间没有编译这一步。
- 前端 `public/js/*.js` 是经典 `<script>`，十来个文件共用一个全局作用域：A 文件定义的函数，B 文件直接调。
  不写 `import` / `export`，也不引打包器和前端框架。这是产品决定，不是还没来得及做。
- 新依赖默认不加。确实要加，在 PR 里写清楚：它替掉了多少行自己写的代码，装机包因此大了多少。
- 落盘走 `store.js`（原子写 + `.bak` 兜底），路径走 `paths.js`：会被写的东西用 `dataPath()`，包里的只读资源用 `appPath()`。
  别拿 `__dirname` 自己拼数据路径。开发态看不出问题，装机态那是只读的应用包：macOS 上写进去会破坏签名，Windows 装在 Program Files 下普通用户根本没有写权限。

## 二、类型：JSDoc + `// @ts-check`，不改成 .ts

类型检查只**检查**，不产出文件：tsc 跑的是 `noEmit`，代码照旧是 .js，运行时一个字节都不变。
这样类型能兜住一部分错，又不用加编译步骤。

### 新文件第一行写 `// @ts-check`

```js
// @ts-check
"use strict";
/**
 * 这个文件是干什么的，为什么要单独成一个文件。
 */
```

- 放在 `"use strict";` **上面**。注释不影响 `"use strict"` 生效：指令前面只要没有语句就行。
- 老文件：零错误的才加。加上以后，这个文件的**全部**报错都会让闸门变红，所以别给一个还有一百条报错的文件加上再去忽略。
- 闸门：`npm run typecheck`（也就是 `node test/typecheck.js`）。后端一趟，前端按页面各一趟（主界面、后台）。
  全仓只有三种高信号错误会报红：TS2304 / TS2552（名字找不到，多半是拼错了、删了函数还有人在调）和 TS1117（对象里同一个键写了两遍）。
  带 `// @ts-check` 的文件则是任何报错都红。
- 只用这条命令，别自己拼 `tsc` 参数，也别给 tsconfig 开 `composite` / `incremental`。
  这两个选项要往盘上写 .tsbuildinfo 或声明文件，配错一次，源码目录里就冒出几百个不该提交的产物。

### JSDoc 怎么写

类型写在花括号里，放在参数名**前面**：

```js
/**
 * 查一路按量价。
 * @param {string} cap            search / image / video / tts / asr
 * @param {unknown} model         型号名，可能带聚合商前缀
 * @param {PriceOpts} [opts]      方括号 = 可以不传
 * @returns {PriceHit<UnitRow>|null}  null = 不知道，不是 0
 */
```

下面这种写法**不行**。它读起来像类型，tsc 却会把 `{ cap, model }` 当成一个叫 `cap` 的类型去找，报 TS2304：

```js
/** @param call { cap, model, units }  ← 错：花括号在名字后面，里面也不是类型 */
```

原来的 `pricing.js` 就是这么写的。全仓那一趟认得出它在注释里，会放过；可这个文件一加 `// @ts-check`，这几行就全红了。形状照样写，只是要写成类型：

```js
/** @param {{ cap?: string, model?: string, units?: number }} [call] */
```

几条常用写法：

| 要表达什么 | 写法 |
| --- | --- |
| 解构参数带默认值 `({ config } = {})` | `@param {{ config?: any }} [opts]`：名字随便起，按位置对上 |
| 形状在一个文件里用好几次 | 文件顶上 `@typedef`，见 `pricing.js` 的 `PriceRow` / `PriceOpts` |
| 跨文件共用的形状 | 放 `types/*.d.ts`，用的地方写 `/** @typedef {import("./types/drama").Shot} Shot */` |
| 空数组 / 空 Map 先标类型 | `/** @type {Blocker[]} */ const blockers = [];`：标了，往里 push 的东西才会被检查 |
| 类型断言 | `/** @type {Partial<AssetHit>} */ (locate(ref) \|\| {})`：**括号不能省**，省了断言就不生效 |
| 什么都可能传进来 | 用 `any`，在描述里写清楚接受什么。`unknown` 要先用 `typeof x === "number"` 这类判断收窄；`Number.isFinite(x)` 收不窄，后面的 `x >= 0`、算术照样报错 |

两个容易踩的坑：

- **`x || {}` 的类型是 `X | {}`**。接着取 `.rel` 就报「`{}` 上没有这个属性」。用上面的断言写法包一层。
- **对象字面量里的 `"todo"` 会被放宽成 `string`**。没有上下文类型时，tsc 不知道你想要联合类型。
  要么给整个数组标类型（`/** @type {ProgressStage[]} */`），要么把 .d.ts 里那一格放宽成 `string`，并在注释里列出可能的取值。

别用 `// @ts-ignore` 消红。它会把这一行以后的新错也一起吞掉。真的是 tsc 看错了，用 `// @ts-expect-error 原因`：哪天它不再报了，这行自己会红，提醒你删掉。

### `types/drama.d.ts` 和 schema 的关系

短剧分镜表的真源是 `skills/short-drama/references/分镜表.schema.json`，`types/drama.d.ts` 是它的 TypeScript 抄本。
**改 schema 必须同步改这里。** 反过来不行：只改 .d.ts 不改 schema，模型照旧按老 schema 出分镜，校验也照旧按老的判。

画布那半边（`CanvasState` / `CanvasNode`）没有 schema，真源是 `src/tools/canvas.js` 的 `canvasNormalizeState` 和 `public/js/app-07-canvas-nodes.js`，改形状时这三处一起改。
`.d.ts` 里只放 `type` / `interface`，不放任何值。它从来不会被 `require`，放了值也只是一个跑不到的假象。

## 三、测试锚点：测试在读你的源码

很多测试不是调函数看结果，而是**拿正则读源码**，钉住「某个函数里还有没有那一句」。这类测试挡的是运行时测不出来的退步，
比如某个开关的默认值、某个报错一定带着原话。代价是：改名、挪位置、换写法，都可能让它们红一片，更坏的是让它们切到空串、悄悄变绿。

- **改名前先查**：`grep -rn 旧名字 test/`。被钉住的函数名、导出名、错误文案、前端元素 id，要改就在同一次提交里把测试一起改掉，并说明为什么改。
- **读源码走 `test/lib/src.js`**：写 `src("server")`，不写 `fs.readFileSync(".../server.js")`。
  大文件按职责拆开时只改 `src.js` 一处，不用回头改几十个测试——画布（`app-07-canvas-*.js` 八个文件）、`tools.js`（媒体/画布搬进 `src/tools/`）、`server.js`（画布/短剧/合成搬进 `routes/`）都是这么拆的。
- **测内部函数用 `_internals`**：模块导出 `_internals: { ... }` 给测试直接调，别在测试里用正则抠函数体再 `eval`。
- **`test/e2e.js` 的用例是顶层 `function testXxx()`**，函数名就是 `E2E_ONLY` 的键：
  `E2E_ONLY=testDramaCompose,testI18n node test/e2e.js`。名字对不上会直接报「没有这个测试」。改名等于让别人手里的命令失效。
- **新套件登记进 `test/all.js` 的 `SUITES`**，每一项以 `["名字"` 开头（`repo-hygiene` 按这个正则解析）。要开 Electron 的套件标上 electron。
- **闸门都要带反向断言**：故意喂一个坏样本，证明它会红。不会红的闸门永远是绿的，却什么都没在看。
- **不格式化整个文件**。实测对全仓跑一次 Prettier，58 个套件有 15 个变红：换行和引号一动，正则就切空了。
- **测试一律 mock，不花钱**：不调任何真实付费接口。临时文件放 `fs.mkdtempSync(path.join(os.tmpdir(), "owb-xxx-"))` 自己的目录，
  跑完删掉。`workspace/`、`projects/` 是用户数据，测试绝不碰；也别去连 3800 端口上正在用的那一台。

## 四、界面文案

- **一句不超过 70 字，争取 40 字以内。** 70 不是拍脑袋定的：通知和报错的第一行超过这个长度，界面上就会被截成半截话。
  闸门是 `test/ui-copy-length.js`：扫 `public/js/*.js`（`i18n.js` 除外）和 `public/*.html` 里每一段看得见的文字，超 70 个汉字就红。
  真有非长不可的（发给模型的提示词、法律声明），加进它的 `ALLOW` 并写明理由。另有几处单独钉住（画布成片通知、坏参数报错的第一行）。
- **说动作和后果，不说功能名。** 写这个按钮按下去会发生什么、不按的话默认是什么。
  举个例子：✗「启用自动续跑」 ✓「撞到步数上限时自动接着跑，最多 3 轮」
- **写明花不花钱。** 会调模型、会调付费接口的，写出大概多少（「每次约 0.02 元」）；不花钱的也说一声（「只在本机算，不调模型」）。
  用户最怕的是点了以后才发现在烧钱。
- **能点的给真按钮。** 「去设置里打开 xx」不如直接放一个按钮：开关找不到，就等于没有。
- **报错不替人下结论。** 只写看得见的事实：状态码、上游原话、哪一步停的。别猜「可能是网络不好」。
  猜错的原因比不写原因更贵，用户会照着错的方向修半天。
- **新加的中文文案要进 `public/js/i18n.js` 的 `DICT.en`。** 只加条目，不改已有的键。`testI18n` 有覆盖率闸门，漏了会红。
- **中文不加字距**（`letter-spacing`）。英文小字加一点字距好读，汉字加了只会显得散。

## 五、单文件软上限：1000 行

新写的 .js 文件，软上限 1000 行。超过了不是不许合，而是要在 PR 里说一句为什么不拆。
不设硬上限，是因为硬卡行数会逼出一堆为拆而拆的碎文件，每个都得跳来跳去才读得懂。

已经超过的老文件（`server.js`、`tools.js`、`agent.js` 等；`app-07-canvas.js` 已拆成 `app-07-canvas-*.js`）：

- 只修 bug、做小改动。**新功能另开文件**：新路由放 `routes/`，公共逻辑放 `lib/`，新工具放 `src/tools/`，画布的新功能放 `app-07-canvas-*.js`。
- 拆的时候是纯搬家：URL、导出名、函数名一律不变，测试断言条数不变。
- 顶层新开的子目录要写进 `electron-builder.config.js` 的 `files` 白名单。`"*.js"` 只匹配顶层，漏了装机包就少文件，应用打不开。
  打包后有一道完整性闸门（`scripts/check-package-files.js`）会拦下来，但那时已经在打包了。

看一眼现在谁最大：

```bash
wc -l *.js engines/*.js public/js/*.js | sort -rn | head
```

## 六、注释

- 中文注释，写**为什么**，不写是什么。代码本身说得清做了什么，值钱的是当初为什么这么选、绕开了什么坑、试过哪条路没走通。
- 踩过的坑写进注释时带上现象（「装机后双击没反应」），不光写结论。以后的人是拿现象来搜的。
- 数字要有出处：写「实测 170MB / 次」，不写「很大」。

## 七、提交前自查

```bash
npm run lint                                  # 只对新增的违规报红
npm run typecheck                             # 约 4 秒
E2E_ONLY=testXxx node test/e2e.js             # 先跑你动到的那几条
npm test                                      # 提交前还是要跑一遍完整的
```
