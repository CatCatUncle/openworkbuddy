# 数据安全基线（「别漏出去」这一面）

这个项目有两篇安全文档，讲的是**相反**的两个方向，别看串了：

| | 防的是什么 | 在哪 |
| --- | --- | --- |
| [安全](./安全.md) | agent 手里有 shell，**别让它把你的机器搞坏** | 审批闸门、文件黑名单、命令拆解、运行档位 |
| 这一篇 | 这台机器上的东西，**别漏出去** | 盘上的权限、监听地址、登录与会话、多人之间的墙、往外发的那几条口子 |

下面每一条都能在代码里指到具体位置。**说不清的地方一律写「没做」**，别让一份文档把用户哄到公网上去。

---

## 一、先回答一句：数据到底在哪

**全都在跑这个服务的那台机器的硬盘上，没有云端，没有回传。** 一份，不是两份。

| 文件 / 目录 | 里面是什么 | 敏感度 |
| --- | --- | --- |
| `config.json` | **全部模型 API Key**、搜索 Key、IM 应用密钥、Langfuse 私钥 | 最高 |
| `data/users.json` | **所有还活着的会话令牌**、密码哈希与盐、TOTP 密钥、一次性找回码 | 最高 |
| `data/orgs.json` | **还没用完的邀请码**、组织设置、整本审计流水（环形 1000 条） | 最高 |
| `data/sessions/` | 每一趟对话的正文：提示词、模型回复、工具参数 | 高 |
| `data/memories.json`、`memory.md`、`memory_vectors.json` | 长期记忆（按登录名分作用域） | 高 |
| `data/im-log.json`、`data/im-sessions/` | 飞书 / 企微 / 钉钉那边收发的消息 | 高 |
| `data/audit.json` | 安全决定流水（哪条命令放行了、哪个域名拦了） | 中 |
| `data/library/`、`inspirations.json` | 资料库文件与灵感笔记（**全局一份，不按人分**） | 中 |
| `data/api-usage.json`、`data/metrics/` | 每个人的 token 花销与任务量 | 中 |
| `data/tenants/<组织 id>/` | 多租户部署下各组织的成果根 | 看内容 |
| `logs/app-<日期>.jsonl` | 谁在什么时候登录了、会话 id、报错原文（留 14 天） | 中 |
| `workspace/`、`projects/` | agent 产出的文件本身 | 看内容 |
| `workspace/.openworkbuddy/traces.jsonl` | 本地执行追踪：**提示词原文 + 工具参数** | 高 |
| `backups/` | 上面这些打的包 | 跟正本一样 |

换机器怎么整个搬走 → [数据同步与搬家](./数据同步与搬家.md)。

这些目录**一个都不在 git 里**（`.gitignore` 里逐条列着）。`.openworkbuddy/` 尤其要注意：工作目录被设成某个代码仓库的根时，追踪账本就落在那个仓库里，里面是提示词原文。

## 二、盘上的权限：0600 和 0700

同一台 VPS、同一台办公电脑上常常不止一个本地账号。默认 umask 给的是 `0644`——**别的账号一句 `cat` 就把上面那几本全拿走，而且这事在任何日志里都不留痕迹**。所以：

- `config.json`、`data/users.json`、`data/orgs.json` 以及各自的 `.bak`：**0600**。
  写盘那一刻就带上（`store.writeJsonAtomic` 的 `mode`，权限给在 `writeFileSync` 里而不是写完再 `chmod`——否则中间那一瞬文件是 0644，够 `cat` 一次了），开机再收一次（`server.js` 顶部），把装了半年的老机器一并修好。
- `data/`：**0700**。这是上面那几条的兜底。逐个文件收权限有个绕不过去的毛病——**这个目录还在长**：今天列全了，下一个功能加一本新账，忘了带 `mode` 就又是一个 0644。目录没有执行位，别的本地账号连 `ls` 都进不来。
- `logs/`：**0700**，收在 `log.js` 建目录那一处（写日志的不止服务端，CLI 和桌面壳也写）。

**做不到的时候不报错**：Windows 上 `chmod` 基本是空操作，容器挂载卷也可能不让改。这一层是「能收就收」，不是安全边界本身。

**不收上一层目录。** 开发态下数据根就是仓库根（见 `paths.js`），把源码目录改成 0700 是件没人预期的事，而真正要护的东西一件都不在那儿。

## 三、网络这一面：默认只听本机

```js
const host = process.env.HOST || srvCfg.host || "127.0.0.1";
```

**默认 `127.0.0.1`。** 这个进程手里有 `run_shell` 和整个文件系统，绑 `0.0.0.0` 等于把一台机器的 shell 挂到公网上。要放出去必须显式写 `HOST=0.0.0.0`，而且一绑非本机地址，启动日志里就会有这一行：

> ▲ 正在监听 …（非本机）。请确认前面有反向代理 + HTTPS，且已经注册了管理员账号——否则任何人都能拿到这台机器的 shell。

挂到公网前必须做的几件事、以及现成的 nginx 配置（HTTP/2、TLS 会话复用、到后端保持长连接）→ [远程访问](./远程访问.md)、[部署](./部署.md)。

几条相关的：

- **TLS 不在这个进程里。** 前面挂 nginx / Caddy，真正的证书在它那一层。所以 `Secure` 这个 cookie 属性是按 `req.secure` 或 `X-Forwarded-Proto` 判出来的。
- **`X-Forwarded-For` 默认不认。** 那个头谁都能伪造，认了就等于把 IP 闸拆了（换一行头就是一个新 IP）。挂了反代要显式开 `OPENWORKBUDDY_TRUST_PROXY=<信任几层>`，而且是**从右往左**数第 N 跳——最左边那个正好是唯一能被客户端伪造的。不开的后果是另一个方向的麻烦：全公司共用代理那一个地址，登录闸从「防连打」变成「互相锁死」。
- **桌面版走的是另一套判据。** Electron 壳 + 只听回环 = 屏幕前就一个人，服务器级的那道闸和凭证脱敏一起关掉（`admin.setDeployment`）；只要绑到别的地址，两道全部照旧。

## 四、登录、会话、密码

| 做了什么 | 在哪 |
| --- | --- |
| 令牌放 cookie，`HttpOnly; SameSite=Lax`，https 下补 `Secure` | `account.js` `setTokenCookie` |
| 密码 `scrypt` + 每人一个 16 字节随机盐；比对走 `timingSafeEqual` | `account.js` |
| 弱密码表、纯重复（`aaaaaa`）、纯连号（`123456`/`abcdef`，含倒着来的）、和用户名相同、前后带空格——一律挡 | `account.js` |
| 密码长度可配（`password_min` 6–64），可要求大小写/数字/符号凑够三类（`password_strong`） | 管理后台 → 组织设置 |
| 登录失败闸：盯一个账号打 8 次、换着账号打 30 次（15 分钟窗口）。**先看闸再算密码**——`scrypt` 是重活，让它连打就等于替对方把 CPU 也占了 | `account.js` |
| 二次验证 TOTP（对着 RFC 4226 / 6238 的标准向量测过），含一次性恢复码、`last_step` 防重放 | `totp.js` + `account.js` |
| 组织可以强制全员二次验证（`require_2fa`） | 管理后台 |
| 登录有效期可配（`session_days` 1–365），**每次请求现算**——调小了，已经发出去的 cookie 立刻作废 | `account.js` `ttlMsFor` |
| 停用 / 待审核的账号当场走不动，不是等 cookie 过期 | `account.js` `authGuard` |

两条容易被做成「假开关」、这里特意没那么做的：

- **强制二次验证对已经登录的人也生效。** 只在登录时判的话，管理员今天打开开关，昨天登录的人手上那个页面还能照常用到 cookie 过期——那就成了「只对新登录的人强制」。
- **`authGuard` 先把路径小写化再判。** Express 路由默认大小写不敏感，`/API/settings` 照样命中 `/api/settings` 的处理器；拿原样路径做 `startsWith` 的话，一个大写前缀就把整个 `/api` 判成「不需要登录」。同一个坑在平台读写表和脱敏那两道上也各堵了一次。

**忘了密码怎么办。** 这套东西默认装在自己机器上，没有邮件服务器可用，所以走的是「在服务器上敲一句命令」：

```bash
openworkbuddy passwd <用户名>          # 打印一串新密码
openworkbuddy 2fa <用户名> --off        # 手机丢了、二次验证进不去
```

用的是别人的服务器，就找管理员在后台「成员」里重置。登录页的「忘了密码」里写的就是这两句。

## 五、多人共用一台服务器：墙在哪几处

单机个人版**这一节一行都不生效**（默认组织一律直通，行为跟以前一字不差）。真分了租户之后：

1. **工作目录按组织分。** `admin.tenantScope` 把整条请求的异步链绑到调用者所属组织的成果根上。绑在中间件这一层而不是每个接口各自判——文件相关的入口有十几个（列表/下载/预览/删除/整理/保存/打开/上传，还有任务本身写出去的每一个文件），漏判一个就是一个跨租户读文件的洞。
2. **按相对路径取文件也按租户过滤。** 成果卡片上记的是相对路径，找不到时会去「这台机器见过的所有根」里兜底扫一遍——那张表跟「谁在请求」没关系。于是 B 公司的报告叫「季度报告.html」，A 公司的人照着这个相对路径请求一次就翻出来了：列表里一个字看不见，下载却是 200。现在有租户根的时候，候选根一律只认这个根底下的（`server.js` `tenantRootOf`）。**个人版不受影响**——判据是「属不属于默认组织」，不是「工作目录变没变」，后者会把这个功能存在的全部意义一并掐掉。
3. **API Key 对非平台管理员一律脱敏。** `admin.redactGuard` 在返回前把所有 `*_key / *_secret / *_token / *_webhook / *_password` 字段抹成空串。
4. **服务器级的设置归平台管理员。** 引擎、密钥、MCP、全局工作目录、定时任务、备份、资料库上传、在服务器桌面上起进程（「用系统程序打开」「在访达里显示」）——两张前缀表（`PLATFORM_WRITE` / `PLATFORM_READ`）。
5. **会话归属。** 知道一个会话 id，不等于能读它、能往里插话、能把它掐掉。会话 id 会出现在链接、日志、截图里，不是秘密，更不该当权限用（`sessionAllowed`）。定时任务同理（`schedViewer`）。
6. **执行追踪、系统日志、运行指标，一律只给平台管理员。** 这几本账都是**整台机器一份**的，不带账号维度：trace 里是全服务器每一趟任务的提示词原文和工具参数，日志里是别人的登录名和报错原文，指标里是别人的 token 花销。多人服务器上放开给成员看，等于把同事干了什么摊开（`traceOwnerOnly` / `opsOwnerOnly`）。
7. **审计流水。** 谁什么时候放行了哪条命令、发了哪张邀请码、改了哪项设置——环形 1000 条，管理后台可查、可按时间/关键词翻页，**且不许越过组织墙**。

**一条要说在前面的：资料库是全局一份的。** `data/library/` 不按人分，每个人的 agent 都带着 `library_list` / `library_read`，一句「翻一下资料库」就能把文件清单、灵感笔记乃至正文念出来。所以界面上也是读放行、写照拦——拦住 HTTP GET 只能保住一句瞎话（「还没有参考资料」），保不住那些字节。**别往资料库里放只给一部分人看的东西。**

## 六、真正容易泄漏的那一面：往外发的口子

被人攻进来是少数，**自己把东西发出去**才是多数。这个项目会主动出网的只有下面几处，逐条说清：

| 口子 | 什么时候发 | 发出去的是什么 | 怎么管 |
| --- | --- | --- | --- |
| 模型 API | 每一轮对话 | 系统提示词、对话历史、工具返回的内容（含你让它读的文件正文） | 换成内网/本地模型（Ollama、vLLM、自建网关）→ [配置模型](./配置模型.md) |
| 搜索 | agent 用 `web_search` 时 | 搜索词 | 设置 → 不配搜索 Key 就整个用不了 |
| `fetch_url` / `render_page` | agent 抓网页时 | 目标地址 | 组织设置里的 `net_allow` / `net_deny`（黑名单优先于白名单） |
| IM 推送 | 任务完成、告警触发 | 任务摘要、告警正文 | 不配机器人就不发 |
| Langfuse | 只在你自己填了地址和 Key 之后 | 跟本地 trace 同样的东西：提示词原文、工具参数 | **默认关**。本地追踪不依赖它 |
| 更新检查 / 技能市场 | 手动点的时候 | 版本号 | 不点就不发 |

两句真话：

- **模型那一跳没法绕过。** 用云端模型，你的提示词和它读到的文件内容就到了模型厂商那里，他们那边怎么留存不归这个项目管。**真要「一个字节都不出内网」，只有本地/内网模型这一条路。**
- **trace 默认只写本地。** `workspace/.openworkbuddy/traces.jsonl`，不依赖 Langfuse，也不自动外发。

## 七、远程接入的两个开关（默认都是关的）

| 开关 | 管住什么 | 默认 |
| --- | --- | --- |
| `remote_devices` | 允不允许扫码把手机 / 另一台电脑加进来 | **关** |
| `remote_control` | 允不允许从网页 / 手机操控终端里正在跑的任务 | **关** |

`remote_devices` 关掉时**已经连上的那些也会当场断掉**（`authGuard` 里按令牌种类判）。只拦新配对的话这个开关是假的：管理员在后台关了，以为丢在公司的那台手机已经进不来了，其实它手上的令牌还能用到过期。详见 [远程访问](./远程访问.md)。

## 八、人进来和人走了

- **入职**：按部门模板一次配好角色和月度额度，不用一项项点。
- **离职**：一次关完——停用账号、删光他所有会话令牌（含扫码连上的设备）、作废他发出去还没用的邀请码、关掉二次验证绑定、掐掉他正在跑的任务、把他名下的定时任务停掉（可以指定交接给谁，交接过去仍然是**关着**的，接手的人确认内容之后自己打开），最后给一张「关了什么、留了什么、为什么」的回执。
- 两条护栏：不能给自己办离职（手一抖就把自己锁在门外），组织里最后一个在职管理员不能办（办完谁都进不了后台）。

在 `lifecycle.js`，管理后台 → 成员里点。

## 九、这份基线**没有**做到的（说实话的部分）

1. **这不是沙箱。** 文件黑名单和命令闸拦得住「顺手」，拦不住「刻意绕」。真要跑不受信任的任务，用容器或者一台专门的机器。
2. **同机器上的 root 照样全读得到。** 0600/0700 防的是同机器上**别的普通账号**，不防 root，也不防物理接触。
3. **盘上没有加密。** 没有主密码，没有静态加密——硬盘拿走就等于全拿走。要加密用系统层的（FileVault / LUKS / BitLocker）。
4. **`backups/` 跟正本一样敏感。** 别扔进任何云盘同步目录。
5. **审计只有 1000 条。** 环形，满了就顶掉最旧的。要长期留存自己往外导。
6. **日志只留 14 天**，按天滚。
7. **模型厂商那一跳不归这里管**（见第六节）。
8. **`chmod` 在 Windows 上基本是空操作**，容器挂载卷也可能不让改。
9. **资料库是全局一份的**（见第五节末尾）。
10. **没有做防 CSRF 的 token。** 挡在前面的是 `SameSite=Lax` + 所有写操作都是 `POST`/`DELETE` + JSON body。跨站发 JSON 请求会被预检拦下，但这是浏览器给的保护，不是这个项目自己实现的一道闸。
11. **没有端到端加密，没有多因素之外的设备指纹，没有异地登录告警。**

## 十、上线前自己过一遍

```bash
# 1. 那几本账是不是 0600、data/ 和 logs/ 是不是 0700
ls -l  ~/OpenWorkBuddy/config.json ~/OpenWorkBuddy/data/users.json ~/OpenWorkBuddy/data/orgs.json
ls -ld ~/OpenWorkBuddy/data ~/OpenWorkBuddy/logs

# 2. 监听在哪（挂公网的话，这里应该只看到反代在听 443，本服务在 127.0.0.1）
lsof -nP -iTCP -sTCP:LISTEN | grep -i node

# 3. 有没有把敏感东西带进 git
git status --porcelain --ignored | grep -E 'config\.json|data/|logs/|\.openworkbuddy'

# 4. 体检
npx openworkbuddy doctor
```

再加四件事，比上面任何一条都管用：

- **第一个账号立刻注册掉。** 第一个注册的就是超级管理员——挂在公网上而没有这个账号 = 谁先访问谁是超管。
- **关掉自助注册**，或者打开「需要审核」，用邀请码进人。
- **组织设置里把 `password_min` 调到 12、打开 `password_strong` 和 `require_2fa`。**
- **别用真业务数据试新东西。** 先拿一份假的跑通。
