```
OpenWorkBuddy is an open-source, self-hosted "office agent": you type a task in
plain language ("build a Q3 review deck from this spreadsheet"), and it plans,
runs tools, and hands back an actual file – .pptx / .docx / .xlsx / an HTML page –

- Files, not chat. Every "I wrote the file" claim from the model is checked
  against the disk. If the file isn't there, the run is stopped and redone.

  live on the next task. MCP connectors and the Agent Plugins standard work too.

It's plain Node.js + vanilla JS, no build step, no framework – the agent loop is
hand-written and readable in an afternoon. There is a CLI (`wb "..."`) that shares
the same config/skills/memory, so it drops into pipes and cron.

Demo (real run, unedited): <DEMO>
Repo: https://github.com/CatCatUncle/openworkbuddy

Honest caveats: the UI and docs are Chinese-first (English README exists, more
coming); macOS builds aren't notarized (no paid Apple cert), so first launch needs
a right-click → Open; the license is PolyForm Noncommercial (free for personal /
non-profit use, commercial use needs a license) – I know that's a trade-off and
happy to discuss it.

Would love feedback on the "verify the file exists" gate and on what people
actually want an office agent to produce.
```

```
Sharing an open-source project: a self-hosted "office agent". You give it a task
in plain language and it produces actual files – slides, Word docs, spreadsheets,
HTML pages – instead of a chat answer.

Self-hosting details, since that's what this sub cares about:

- Node.js 18+, no database server, no build step. `npm install && npm start`, or
  Docker (compose file in the repo).
- Binds to 127.0.0.1 by default. There's a permissions model (four tiers), a
  command-approval gate, a file blocklist, a URL allowlist and an audit log,
  because the agent does have a shell. Docs say plainly: read the security page
  before exposing it.

  If you have Claude Code or Codex installed locally it can drive that instead.
- All state (sessions, generated files, keys) is on disk under one directory,
  atomic writes with .bak fallback.
- Multi-user with per-account quotas if you want to run it for a small team.
- Optional: hook it up to Feishu/Lark, QQ, WeChat so you can send tasks from your
  phone and get files pushed back. Cron-style scheduled tasks catch up if a run
  was missed.

License is PolyForm Noncommercial (free for personal use; companies need a
license). Repo: https://github.com/CatCatUncle/openworkbuddy

Happy to answer questions about the sandboxing / approval gates – that part had
the most iterations.
```

```
开源了一个本地跑的 AI 办公 agent：OpenWorkBuddy。你说「帮我出一份 Q3 复盘 PPT，数据用这个 Excel」，
它自己读表、算数、生成一个能直接放的 .pptx。不是给你一段「建议您第一页放……」的聊天记录。

仓库：https://github.com/CatCatUncle/openworkbuddy
一段真实运行的录屏（没剪）：<DEMO>

三句话说清它跟市面上「AI 办公助手」的区别：

1. 交付的是文件。PPT / Word / Excel / 网页都是真生成的，成果面板里点开验收。
2. 不绑模型，数据在你自己机器上。DeepSeek / 通义 / 智谱 / Kimi / Ollama 点一下就切；本机装了 Claude Code 或 Codex 的，
   一键拿它当发动机，不用再买 token。默认只监听 127.0.0.1。
3. 加一个能力 = 丢一个 Markdown 文件进 skills/，存盘就生效。

下面是干货，做到第 48 轮才想明白的 4 件事，每一件都有真实数据兜底：

## 一、模型「说」写了文件，跟文件「在」磁盘上，是两件事

早期最多的投诉是「它说做好了，但我打不开」。翻日志发现模型会在最后一轮直接输出「文件已生成」然后收工，
而工具调用根本没执行。现在每一次任务结束前都会对照磁盘：声称产出的文件不在，这一轮判红，自动重做。
这条规则上线后「假完成」投诉归零。教训：agent 的验收不能信模型的自述，要看副作用。

## 二、zsh 通配符没匹配上会拒绝执行整条命令

统计近 30 天 227 个回合，有 10 次是因为模型写了 `ls *.png` 这种命令，目录里没有 png，zsh 直接报 no matches found，
整条命令不执行。模型看到报错会换三四种写法重试，一次任务白烧几百 token。修法很土：命令先过一遍检查，
通配符没命中就用 setopt null_glob 兜住。教训：别只看「模型失败率」，把失败按死因归类，最大的一类往往是环境问题。

## 三、定时任务「没抛异常」不等于「干成了」

定时任务的成功率一度是 100%，直到有人发现某个晨报任务连续一周推送的是空文件。它确实没抛异常。
现在每个定时任务跑完要过一道「裁定」：产出是不是空的、有没有真正调用过工具、结论有没有落到文件。
不过关就标「假绿」，进晨报。教训：后台飞轮吞掉的异常，是最贵的异常。

## 四、自进化系统自己有个时间口径 bug

它会挖自己的失败日志，提改进提案，人点头才生效，规则还会被打分、低分自动下架。
上线后发现一条明明有效的规则被反复砍掉。原因：一个会话里几个月前的失败，被算成了「规则生效之后」的失败。
规则越早上线、被用得越多，背的历史锅越多，越容易被自己下架。修掉时间口径之后才正常。
教训：给自进化打分，时间窗口的口径比打分公式重要得多。

## 怎么玩

Node.js 18+：

    git clone https://github.com/CatCatUncle/openworkbuddy.git
    cd openworkbuddy && npm install
    npm run app     # 桌面版；或 npm start 走浏览器 http://localhost:3800

第一次打开有五步向导，粘一个 API Key（当场验活）就能说话。也有命令行：`wb "帮我写一份本周周报"`，
答案落 stdout，能塞进管道和 cron。

协议是 PolyForm Noncommercial：个人、学习、非营利免费，公司里用需要授权。这是个取舍，欢迎在评论里聊。
用崩了开 issue，哪怕只贴一句报错；想写个技能的，一个 Markdown 文件就是一个 PR。
```
