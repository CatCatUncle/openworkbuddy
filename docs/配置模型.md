# 配置模型

界面里 **设置 → 模型** 直接改，保存即热生效。新增模型时表单顶部有**渠道预设**下拉：选一个（OpenAI / Anthropic / OpenRouter / 火山方舟 / 阿里云百炼 / DeepSeek / 智谱 / Kimi / Ollama），接口地址和协议自动填好，只差粘 Key。手动改 `config.json` 也行：

```jsonc
{
  "models": [
    {
      "name": "DeepSeek",                          // 界面上显示的名字
      "provider": "openai",                        // openai 兼容 / anthropic
      "base_url": "https://api.deepseek.com/v1",
      "api_key": "sk-...",
      "model": "deepseek-chat"
    }
  ],
  "active_model": "DeepSeek"
}
```

| 服务商 | base_url | model 示例 |
|---|---|---|
| OpenRouter（一个 Key 通吃） | `https://openrouter.ai/api/v1` | `deepseek/deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-5.2` |
| Anthropic Claude | 留空走官方；填中转也认（写到 `/v1` 那一层或省略都行） | `claude-sonnet-5`（`provider` 填 `anthropic`） |
| 火山方舟（豆包） | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seed-1-6-250615` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义 Qwen | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-max` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-32k` |
| Ollama 本地 | `http://localhost:11434/v1` | `qwen3:8b`（向导会去问你这台机器真装了哪些，不用手抄） |

模型条目还能带 `extra_body`，透传厂商私有参数（比如 OpenRouter 的 `reasoning`）。

## 判断模型：它不在上面那张表里，因为它不会写字

Jev（TypeSafe System One）是另一种东西。上面每一条都是「吃一段话、吐一段话」，Jev 是**吃一段材料加一道有类型的题，吐回来一个选项 / 一个分数 / 一个概率，外加一格「有多确定」**。

所以它不能写进 `models[]`——挂上去每一趟都是 400（OpenRouter 会直接回一句「这是 decisions 模型，用 /api/alpha/decisions」）。它在 `providers[]` 里，走自己那条路。

### 配

**配过 OpenRouter 就什么都不用做**，原来那把 Key 直接能用。想走出厂那家：

```jsonc
{
  "providers": [
    { "id": "typesafe", "kind": "typesafe", "api_key": "sk-..." }   // 去 console.typesafe.ai 办
  ]
}
```

两条都配了走官方。也认 `TYPESAFE_API_KEY` / `OPENROUTER_API_KEY`，**各认各家、不串**——别家的 Key 不会被拿去凑数。自建网关就在那条渠道的 `base_url` 上填自己的地址，填了就发去那儿（不填才走官方）。

要更细的控制，或者想彻底关掉：

```jsonc
{
  "decide": {
    "off": false,                                   // true = 一键关掉，所有调用点安静退回老路
    "route": "openrouter",                          // openrouter | typesafe
    "base_url": "https://自建网关/api/alpha/decisions",
    "api_key": "sk-...",                            // 或者 "channel": "某条渠道的 id"
    "model": "typesafe/jev-1.13"                    // 钉死版本号，别名会跟着上游发版漂
  }
}
```

### 用

| 入口 | 干什么 |
| --- | --- |
| `openworkbuddy jev` | 命令行问一道题，不给参数就测活（见 [命令行用法](命令行用法.md)）|
| `GET /api/decide` | 这台机器上它能不能用、走的哪条路（**不含 Key**，可以直接贴进 issue）|
| `POST /api/decide` | `{state, questions}` → `{answers, lines, cost, cost_text}` |
| `POST /api/decide/selftest` | 拿固定材料真问三道题 |
| 设置 → 模型 → 「测一下」 | 那个按钮认得出它，不会拿对话接口去 ping 一个必然的 400 |
| agent 手里的 `decide` 工具 | 配上之后自动挂上（没配就不摆出来），让 agent 自己把一批判断一趟问完 |

三种问法：`noul`（是非 → 一个概率）、`choice`（单选，`criteria` 是 `{选项: 说明}`）、`score`（打分，`criteria` 是从低到高的档位数组）。一次最多 32 道题。

**产品内部用它的地方。一是目标模式的验收**：每条验收标准变成一道是非题，过 70% 才打勾，不到就留着不打、并在卡上写明是「拿不准」而不是「没干」。没配这个模型的机器安静退回原来那条对话模型的路。

**二是 agent 自己调的 `decide` 工具**：配了才摆出来，没配就不摆——摆了又用不了，模型会白费一趟去试。一趟最多 32 道题，每条回答带确定度；低于门槛的那几条它不当定论，会单独挑出来交给人。配套的 **triage 技能**（`skills/triage`）把这件事教成一条完整的活：定判准 → 拿十来条试跑 → 跑批 → 交两份（能直接走的 / 要人看的）。工单分派、简历初筛、反馈归类这类活都是这个形状。

**三是定时任务「跑绿之后再看一眼」**（默认关，在 设置 → 智能体设置 里开）。定时任务判成功那套判据只回答「是不是**明显**失败」，而且正文一超过 400 字它就主动让路——agent 洋洋洒洒写两千字解释它没办成，运行记录照样一个勾。打开之后，这一类绿会多问一道是非题：这一轮到底办完没有。它**只挂疑问、不改判**——绿还是绿，运行记录和通知末尾多一句「这条你自己看一眼」；模型自己拿不准（确定度不到 75%）就不出声。每条约两万分之一美金。没配判断模型时这个开关不生效，界面上会直说。

### 钱和量

输入 $0.042 / 百万 token，**输出不要钱**，一趟三道题约 $0.00002。便宜到不用管，但它快到可以放进循环里——所以「设置 → 用量」里给它单独立了一格按**题数**记的额度：一次请求能塞 32 道题，按请求数记那道闸等于没有。

## 视频模型：五家协议，各说各的话

对话有 OpenAI 兼容这个最大公约数，视频没有。提交路径、参数名、怎么轮询、结果从哪个字段取，五家没一处对得上，所以 `generate_video` 是一家一条分支：

| 渠道 | base_url | model 示例 | 收首帧 | 收尾帧 |
|---|---|---|---|---|
| 阿里云百炼 · 通义万相 | `https://dashscope.aliyuncs.com/api/v1` | `wan2.2-t2v-plus` / `wan2.2-i2v-plus` | ✅ | ✅（`wanx2.1-kf2v-plus`） |
| 火山方舟 · Seedance | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seedance-1-0-pro-250528` | ✅ | ✅ |
| 智谱 · CogVideoX | `https://open.bigmodel.cn/api/paas/v4` | `cogvideox-3` / `cogvideox-flash` | ✅ | ❌ |
| MiniMax · 海螺 | `https://api.minimax.chat/v1` | `MiniMax-Hailuo-02` / `I2V-01-live` | ✅ | ❌ |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Wan-AI/Wan2.2-T2V-A14B` | ✅ | ❌ |

尾帧那一栏不是摆设：另外三家的接口里根本没有这个字段，硬发过去要么被忽略（片子照出、钱照扣，你对着成片纳闷尾帧怎么没生效），要么整单报参数错。所以给不收尾帧的渠道传 `last_frame`，会在发请求之前就拦下来。

**走中转或自建网关的话**，地址里看不出上游是谁。按这个顺序点名：

1. 渠道卡上的**渠道类型**选成实际那一家 —— 界面上就能改，优先级最高，连地址都压得住；
2. 认不出就按地址里的域名猜（`dashscope` / `volces`·`ark` / `bigmodel` / `minimax` / `siliconflow`）；
3. 一台网关后面挂着好几家上游时，在 `config.json` 的 `media_models` 条目上逐条写 `"protocol": "dashscope"`。

三条都认不出，`generate_video` 不会闷头发一个必然失败的请求 —— 视频是按条计费的异步任务，白发一趟要等好几分钟才看得到错。它会直接告诉你支持哪五家、这次按什么认的、认到了什么。

`config.json` 是唯一存着所有 API Key 的文件，已经在 `.gitignore` 里，**别手滑提交**。
