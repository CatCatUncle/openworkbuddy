# 开源版与商业版的边界

> 这份文档回答一个问题：**这套代码里，哪些应该公开，哪些应该留在私有仓库？**
>
> 它不是营销文案。它是一条工程上的划线规则，以及按这条规则逐个模块过一遍的结论。
> 每加一个新功能之前，先对照第 1 节那条规则问一句：这个东西归哪边。

---

## 1. 划线的规则

一句话：

> **开源版给的是「能力」，商业版卖的是「责任」。**

- **能力**：这个 Agent 能干什么活、干得多好。写文件、生图、跑代码、装技能、接 IM、
  无限画布、执行追踪、自进化、记忆——全部开源，一个不留。
- **责任**：当一家公司把它部署给 200 个人用，IT 和法务会要求的那些东西。
  单点登录、审计导出、离线授权、高可用、合规材料、有人接电话的 SLA——这些收费。

### 为什么这么划，而不是把功能砍一半

最容易想到的做法是「开源版限制 3 个人 / 不给 API / 水印」。这条路走不通，原因有三个：

1. **砍出来的开源版没人 star。** 一个处处撞墙的 demo 传不开，传不开就没有商业线索。
   我们的商业线索**全部**来自「有人自己装上用爽了，然后发现公司要用得买授权」。
   开源版越强，这个漏斗的入口越大。
2. **砍功能拦不住不想付钱的人，只拦得住想付钱的人。** 代码是公开的，限制会被删掉。
   真正拦得住的是**法律**（PolyForm NC 协议）和**运维现实**（SSO、审计、SLA 你自己造不出来）。
3. **能力和责任的用户根本不是同一批人。** 一个人自己用，永远不会想要 SAML；
   一家公司买单，看的也不是「能不能生视频」而是「出了事找谁」。
   把线画在这两拨人之间，双方都不觉得被坑。

参照物：GitLab CE/EE、Sentry、Metabase、Cal.com 走的都是这条线。
反例是那些把 API 关掉、把导出关掉的「开源版」，社区口碑普遍很差。

## 2. 逐个模块的结论

### 2.1 全部开源（现在就在公开仓库里，不打算拿走）

| 模块 | 是什么 | 为什么开源 |
|---|---|---|
| `agent.js` `tools.js` `llm.js` | Agent 主循环、40+ 工具、多渠道模型 | 这就是「能力」本身。藏起来等于没有开源版 |
| `skills.js` `plugins.js` `mcp.js` | Markdown 技能、插件、MCP 连接器 | 生态要长起来，必须让人能自己写、自己装 |
| `im.js` `im-ilink.js` `im-wechat.js` | 飞书 / 企微 / iLink 远程指挥 | 个人用户也在飞书上指挥它，这不是企业专属 |
| `public/js/app-07-canvas.js` | AI 短剧无限画布 | 这是项目最容易被记住的一块，必须开源 |
| `trace.js` | 本地执行追踪 + Langfuse 上报 | 可观测性是信任的基础，藏起来会让人怀疑它在偷偷干什么 |
| `evolve.js` `memory.js` | 自进化、长期记忆 | 同上，而且这两块的价值需要长期使用才显现，正好靠开源版养 |
| `cli.js` `repl-commands.js` | 命令行与 REPL | 开发者第一次接触往往从 CLI 开始 |
| `org.js` `admin.js` `account.js` `quota.js` | **多租户、企业管理后台、用量计费、付费 API 额度** | 见下面那段说明 |
| `security.js` | 审批、审计流水、危险操作拦截 | 安全能力不该成为付费墙后面的东西 |
| `Dockerfile` `docker-compose.yml` `deploy/` | 自托管部署物 | 自托管是这个项目的核心主张 |

**关于企业管理后台为什么也开源**：这是最反直觉的一条，但它是对的。

一个只有单机版的开源项目，在公司里的评估结论永远是「玩具」。
让评估的人第一天就能开出组织、拉进 20 个同事、看见用量报表和审计流水——
他得到的结论会是「这东西是认真做过的」。而这套后台**越好用，越会暴露出**
他真正缺的那几样：怎么接公司的 SSO？审计怎么进 SIEM？断网机房怎么装？
——那几样才是我们卖的。

换句话说：企业管理后台是**商业版最好的销售员**，不是商业版本身。

### 2.2 商业授权才有（私有仓库 `openworkbuddy-enterprise`）

这些**目前一个都还没写**。列在这里是为了确定方向，别把工夫花错地方。

| 能力 | 具体是什么 | 为什么它必须收费 |
|---|---|---|
| **SSO / 目录同步** | SAML 2.0、OIDC、LDAP / AD、SCIM 自动开停户 | 500 人的公司不可能手动拉名单。这是刚需，而且个人用户完全用不上 |
| **审计外送** | 审计流水实时推到 Splunk / ELK / 阿里云 SLS，带签名防篡改 | 有合规要求的公司才需要；实现它要对接一堆企业中间件，工作量真实 |
| **离线授权与气隙部署** | 离线许可证文件、内网镜像仓库、无外网安装包 | 银行、政务、制造业的内网机房，装不上就是装不上 |
| **高可用与横向扩容** | 多实例、共享状态（Redis / PG）、滚动升级、备份恢复 | 开源版是单进程 + 文件存储，够一个团队用；上百人要另一套架构 |
| **白标与品牌定制** | 换 logo、换名字、换域名、定制登录页 | 协议里商标权本来就单独留着，见 COMMERCIAL-LICENSE.md |
| **数据驻留与加密** | 指定存储区域、KMS 托管密钥、字段级加密 | 跨国公司的硬要求 |
| **合规材料** | 等保 / ISO 27001 / SOC2 配合材料、渗透测试报告、安全问卷代答 | 这是人力服务，不是代码 |
| **SLA 与技术支持** | 响应时限、专属群、版本长期维护分支、上门实施 | 这是这门生意里最值钱、也最难被白嫖的部分 |

### 2.3 灰区：想清楚了再动

| 东西 | 倾向 | 理由 |
|---|---|---|
| 行业技能包（金融尽调、合同审阅、医疗文书） | **单独卖，不进任何一版** | 它的价值在领域知识不在代码。按包卖，开源版和商业版都能装 |
| 托管云版（我们替客户跑） | 另一条产品线 | 跟代码边界无关，是运营问题 |
| 模型代理网关（统一记账、按部门分摊） | **先开源**，做大了再说 | 现在 `quota.js` 已经做了七成，拆出去反而伤开源版 |

## 3. 仓库怎么分

```
CatCatUncle/openworkbuddy            公开 · PolyForm Noncommercial 1.0.0
└── 上面 2.1 的全部内容

CatCatUncle/openworkbuddy-enterprise 私有 · 商业授权
├── enterprise/sso/                  SAML / OIDC / LDAP / SCIM
├── enterprise/audit-export/         SIEM 外送
├── enterprise/license/              离线许可证校验
├── enterprise/ha/                   多实例与共享状态
├── enterprise/brand/                白标
└── docs/                            实施手册、合规材料
```

**技术上怎么接起来**：开源版留**挂载点**，不留实现。

开源版里已经有一处现成的例子可以照抄：`admin.js` 的 `createAdminRouter({ deps })`——
所有外部能力都是通过 `deps` 传进去的，不是 `require` 进去的。
企业版按同样的形状塞进去就行：

```js
// server.js（开源版）
const ent = tryRequire("@openworkbuddy/enterprise"); // 装了就用，没装就是 null
if (ent) ent.mount(app, { org, account, security, config });
```

这样做的三个好处：
1. 开源版**不留任何被阉割的痕迹**——没有灰掉的按钮，没有「升级到企业版」的弹窗。
   那种东西是开源项目里最招人烦的。
2. 企业版是**加法**不是减法，两边可以独立演进，不用每次同步 diff。
3. 客户拿到的就是开源版 + 一个 npm 包，出了问题两边都能单独排查。

**绝对不要做的**：在开源仓库里留下功能开关、试用倒计时、或者「此功能需要企业版」的提示。
一旦有人在代码里读到这些，项目在社区里的定性就变了。

## 4. 开源版要让人一眼看出「这东西很强」

这是上面那条规则的另一面：既然靠开源版引流，它就得**真的强**，而且强得看得见。

已经做到的（README 第一屏应该把这些说清楚）：

- 说一句话 → 产出**能双击打开的文件**（xlsx / docx / pptx / 图 / 视频），不是聊天记录
- **AI 短剧无限画布**：角色、场景、镜头、首帧、视频、音频、时间线，DAG 连线
- **40+ 内置工具** + Markdown 技能 + MCP 连接器 + 插件，全部热装
- **飞书 / 企微 / iLink 远程指挥**，支持文件、图片、语音
- **执行追踪**：每次模型调用、每个工具、每条路径、耗时和 token，本地可查，不上传
- **企业管理后台**：多租户、成员部门、用量计费、付费 API 额度闸门、操作审计
- **完全自托管**：模型 Key 在自己机器上，可以接任何 OpenAI 兼容渠道
- **20 个测试套件 3000+ 条断言**，CI 全绿才发版

还该补的（排期见 `docs/路线图.md`）：

- 三列部署选项表（本机一键装 / 自托管 / 更多平台），每列一句话一个链接
- 一段 60 秒内跑完的「从零到第一个交付物」录屏

## 5. 复查清单

每次要加一个新功能，按顺序问：

1. **它让 Agent 多干一件活吗？** → 开源。
2. **它只有在「很多人用同一个实例」时才有意义吗？** → 再问第 3 条。
3. **它要对接企业中间件（IdP、SIEM、KMS、内网仓库）或者需要有人签字负责吗？** → 商业版。
4. **都不是？** → 默认开源。有疑问时往开源那边倒——
   收回来容易（下一版挪走），放出去再收回来会得罪人。
