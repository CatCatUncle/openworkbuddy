# 开源版与商业版的边界

> 这份文档回答两个问题：
> **一，我装的这份跟花钱买的那份有什么不一样？**（第 0 节，普通用户看这一节就够了）
> **二，这套代码里哪些该公开、哪些该留在私有仓库？**（第 1 节起，写给维护者自己看）
>
> 第 1 节那条规则是判据。每加一个新功能之前先对照它问一句：这个东西归哪边。

---

## 0. 先回答最常被问的那句：开源版和商业版有什么区别？

**代码上没有区别。今天只有一份代码，就是你眼前这个仓库。**

「开源版」和「商业授权版」不是两个安装包，也不是两条分支，而是**同一份程序的两种用法**。
区别只在于你拿它干什么、以及要不要为此付钱：

| | 开源用法（PolyForm NC） | 商业授权 |
|---|---|---|
| 装的是哪份代码 | 本仓库 | **一模一样的本仓库** |
| 能用的功能 | 全部 | 全部（不多一个，也不少一个） |
| 谁免费 | 个人自用、学习、科研、公益、政府；公司**评估试用**阶段 | — |
| 谁必须买 | — | 公司拿它做实际业务、对外产品、给客户交付、打包售卖 |
| 版本更新 | 一直有 | 一样 |
| 模型 Key 与数据 | 在你自己机器上 | 一样 |
| 改代码、二次开发 | 可以（保留版权声明） | 可以 |
| 打「OpenWorkBuddy」这个名字对外 | 不可以 | 要单独谈（商标不在协议里） |
| 出了问题找谁 | Issues，看缘分 | 约定响应时限、专属联系方式 |
| 价格 | 0 | 谈 |

一句话：**买商业授权买的不是功能，是「可以拿它赚钱」这件事**，外加一个能找到人的电话。

### 那 SSO、审计外送、内网部署这些呢？

那是**路线图，不是现状**。第 2.2 节列的企业能力（SSO / 目录同步、SIEM 外送、离线授权、
高可用、白标）**现在一个都还没写**——所以今天买授权也拿不到它们，别被那张表误导。

将来写出来之后，它们会以一个**加装包**的形式存在（做法见第 4 节），
开源版不会因此被拿走任何东西：**现在有的，以后还有。**

### 开源版有没有被砍过？没有，也不会有

仓库里没有一处功能开关、没有试用倒计时、没有「此功能需企业版」的灰按钮——
多租户、企业管理后台、成员与部门、用量计费、操作审计、执行追踪，全都在里面跑。
这不是姿态，是第 1 节那条规则推出来的结果。

### 买了授权之后，企业管理和数据同步怎么办？

这是被问得最多的一对问题，答案跟「买授权」这件事**没关系**——因为装的是同一份代码：

| 你想要的 | 现在怎么做 | 跟授权有没有关系 |
|---|---|---|
| **企业管理**（组织、成员、部门、角色、额度、审计） | 已经在你装的这份里。部署到一台服务器 → 关掉自助注册 → 管理员发邀请码开户 → 进 `/admin.html`。见 [多人协作](./多人协作.md) | 没有。开源版一样有 |
| **多设备看同一份数据** | 不是「同步」，是**让它们连到同一台服务**：局域网放开 `HOST`、内网穿透、或者部署到 VPS。桌面端 / 浏览器 / 手机 / 终端 `openworkbuddy` 本来就是同一台服务的四张脸 | 没有 |
| **换机器搬家** | 旧机器导出备份 → 新机器导入恢复，单向。见 [数据同步与搬家](./数据同步与搬家.md) | 没有 |
| **多实例之间互相同步 / 异地容灾** | **做不到，今天没有这个东西。** 它属于第 2.2 节「高可用与横向扩容」，还没写 | 将来有，但现在买也拿不到 |

为什么不做双向同步：会话记录和用量账本都是 append 的 JSON，两头同时写必然冲突。
本地优先这套的正确形态是**集中部署 + 定时备份**，不是两份数据互相追。

### 三句话判断你要不要买

1. 你用它做的事，直接或间接给你或你公司带来钱吗？**不带来 → 免费，不用问。**
2. 带来 → **需要授权，来谈**；还在评估试用、没投进实际业务 → 先不用谈。
3. 你要换个名字 / logo 对外卖 → 除了授权，**还要单独谈商标**。

判不准就直接问一句，比事后扯皮省事。怎么谈见 [COMMERCIAL-LICENSE.md](../COMMERCIAL-LICENSE.md)。

## 1. 划线的规则

一句话：

> **开源版给的是「能力」，商业版卖的是「责任」。**

- **能力**：这个 Agent 能干什么活、干得多好。写文件、生图、跑代码、装技能、接 IM、
  无限画布、执行追踪、自进化、记忆——全部开源，一个不留。
- **责任**：当一家公司把它部署给 200 个人用，IT 和法务会要求的那些东西。
  单点登录、审计导出、离线授权、高可用、合规材料、有人接电话的 SLA——这些收费。

### 为什么这么划，而不是把功能砍一半

最容易想到的做法是「开源版限制 3 个人 / 不给 API / 水印」。这条路走不通，原因有三个：

1. **砍出来的开源版没人 star。** 一个处处撞墙的 demo 传不开，传不开就没有商业线索。
   我们的商业线索**全部**来自「有人自己装上用爽了，然后发现公司要用得买授权」。
   开源版越强，这个漏斗的入口越大。
2. **砍功能拦不住不想付钱的人，只拦得住想付钱的人。** 代码是公开的，限制会被删掉。
   真正拦得住的是**法律**（PolyForm NC 协议）和**运维现实**（SSO、审计、SLA 你自己造不出来）。
3. **能力和责任的用户根本不是同一批人。** 一个人自己用，永远不会想要 SAML；
   一家公司买单，看的也不是「能不能生视频」而是「出了事找谁」。
   把线画在这两拨人之间，双方都不觉得被坑。

参照物：GitLab CE/EE、Sentry、Metabase、Cal.com 走的都是这条线。
反例是那些把 API 关掉、把导出关掉的「开源版」，社区口碑普遍很差。

## 2. 逐个模块的结论

### 2.1 全部开源（现在就在公开仓库里，不打算拿走）

| 模块 | 是什么 | 为什么开源 |
|---|---|---|
| `agent.js` `tools.js` `llm.js` | Agent 主循环、40+ 工具、多渠道模型 | 这就是「能力」本身。藏起来等于没有开源版 |
| `skills.js` `plugins.js` `mcp.js` | Markdown 技能、插件、MCP 连接器 | 生态要长起来，必须让人能自己写、自己装 |
| `im.js` `im-ilink.js` `im-wechat.js` | 飞书 / 企微 / iLink 远程指挥 | 个人用户也在飞书上指挥它，这不是企业专属 |
| `public/js/app-07-canvas*.js` `routes/canvas.js` `routes/drama.js` | AI 短剧无限画布 | 这是项目最容易被记住的一块，必须开源 |
| `trace.js` | 本地执行追踪 + Langfuse 上报 | 可观测性是信任的基础，藏起来会让人怀疑它在偷偷干什么 |
| `evolve.js` `memory.js` | 自进化、长期记忆 | 同上，而且这两块的价值需要长期使用才显现，正好靠开源版养 |
| `cli.js` `repl-commands.js` | 命令行与 REPL | 开发者第一次接触往往从 CLI 开始 |
| `org.js` `admin.js` `account.js` `quota.js` | **多租户、企业管理后台、用量计费、付费 API 额度** | 见下面那段说明 |
| `security.js` | 审批、审计流水、危险操作拦截 | 安全能力不该成为付费墙后面的东西 |
| `eval/` | 评测任务集与基线分 | 分数自己说不算数，得让人能复跑 |
| `Dockerfile` `docker-compose.yml` `deploy/` | 自托管部署物 | 自托管是这个项目的核心主张 |

**关于企业管理后台为什么也开源**：这是最反直觉的一条，但它是对的。

一个只有单机版的开源项目，在公司里的评估结论永远是「玩具」。
让评估的人第一天就能开出组织、拉进 20 个同事、看见用量报表和审计流水——
他得到的结论会是「这东西是认真做过的」。而这套后台**越好用，越会暴露出**
他真正缺的那几样：怎么接公司的 SSO？审计怎么进 SIEM？断网机房怎么装？
——那几样才是我们卖的。

换句话说：企业管理后台是**商业版最好的销售员**，不是商业版本身。

### 2.2 商业授权才有（**路线图，一个都还没写**）

⚠️ 先看清楚这行字：**下面这些能力目前一样都不存在**，不在公开仓库里，也不在任何私有仓库里。
列在这里是为了确定方向、别把工夫花错地方，**不是今天买授权能拿到的东西**。
真写出来之后会放进私有仓库 `openworkbuddy-enterprise`，以加装包形式挂上去（第 4 节）。

| 能力 | 具体是什么 | 为什么它必须收费 |
|---|---|---|
| **SSO / 目录同步** | SAML 2.0、OIDC、LDAP / AD、SCIM 自动开停户 | 500 人的公司不可能手动拉名单。这是刚需，而且个人用户完全用不上 |
| **审计外送** | 审计流水实时推到 Splunk / ELK / 阿里云 SLS，带签名防篡改 | 有合规要求的公司才需要；实现它要对接一堆企业中间件，工作量真实 |
| **离线授权与气隙部署** | 离线许可证文件、内网镜像仓库、无外网安装包 | 银行、政务、制造业的内网机房，装不上就是装不上 |
| **高可用与横向扩容** | 多实例、共享状态（Redis / PG）、滚动升级、备份恢复 | 开源版是单进程 + 文件存储，够一个团队用；上百人要另一套架构 |
| **白标与品牌定制** | 换 logo、换名字、换域名、定制登录页 | 协议里商标权本来就单独留着，见 [COMMERCIAL-LICENSE.md](../COMMERCIAL-LICENSE.md) |
| **数据驻留与加密** | 指定存储区域、KMS 托管密钥、字段级加密 | 跨国公司的硬要求 |
| **合规材料** | 等保 / ISO 27001 / SOC2 配合材料、渗透测试报告、安全问卷代答 | 这是人力服务，不是代码 |
| **SLA 与技术支持** | 响应时限、专属群、版本长期维护分支、上门实施 | 这是这门生意里最值钱、也最难被白嫖的部分 |

**那在这些写出来之前，商业授权卖的是什么？** 三样，都不是功能：

1. **一张允许你拿它赚钱的许可证**——法律上的必需品，没有它公司用就是违约；
2. **商标与白标的口子**——想换名字换 logo 对外，只有这条路；
3. **能找到人的支持**——约定响应时限、直接联系方式、按你的场景出实施建议。

### 2.3 灰区：想清楚了再动

| 东西 | 倾向 | 理由 |
|---|---|---|
| 行业技能包（金融尽调、合同审阅、医疗文书） | **单独卖，不进任何一版** | 它的价值在领域知识不在代码。按包卖，开源版和商业版都能装 |
| 托管云版（我们替客户跑） | 另一条产品线 | 跟代码边界无关，是运营问题 |
| 模型代理网关（统一记账、按部门分摊） | **先开源**，做大了再说 | 现在 `quota.js` 已经做了七成，拆出去反而伤开源版 |

## 3. 还能再开源什么（2026-09-17 把仓库整个盘了一遍）

先说结论：**代码这一侧已经没有可放的了。**
非公开的只剩三类，每一类都有具体的、不是"舍不得"的理由：

| 没公开的东西 | 为什么不公开 | 能不能改 |
|---|---|---|
| 10 个第三方技能包（`ppt-master`、`frontend-design`、`webapp-testing`…） | 是别人写的代码，我们没有再分发的权利。应用内「技能库 → 推荐技能」一键从上游装，效果一样 | **不能。** 这是别人的授权，不是我们的选择 |
| `skills/hongshuskill/` | 查不到上游仓库、没有许可证；而且它会用真 Chrome 操作小红书账号，替别人分发不合适 | 不能 |
| `workspace/` `projects/` `.openworkbuddy/` `config.json` | 你的产出、你的 Key、你的提示词原文 | 不能，也不该——这些是**用户数据**，不是代码 |

除此之外全在仓库里，包括最容易被藏起来的那几样：
**企业管理后台、操作审计、用量计费、执行追踪、评测任务集与基线分、CI 配置、
打包脚本、Docker 与 Caddy 部署物、25 个自研技能包**。

所以「还有哪些能开源」这个问题，代码层面的答案是：没有了，已经全在这儿。

### 3.1 真正还能往外放的，是「许可」不是代码

代码全公开了，但 PolyForm NC 罩住整个仓库时会产生一个副作用：
**想给它写技能、写插件、写部署脚本的人会犹豫**——"我抄一段部署配置到公司内网，算不算商用？"

这个犹豫会直接掐死生态。所以真正还能开的口子在授权这一侧，而不是再放什么代码出来。

### 3.2 已经开的口子：生态层按 MIT

见 [LICENSE-ECOSYSTEM.md](../LICENSE-ECOSYSTEM.md)。下面这些路径**额外**按 MIT 授权，
商用也随便拿（仓库其余部分照旧 PolyForm NC）：

| 路径 | 为什么可以 MIT |
|---|---|
| `deploy/` `Dockerfile` `docker-compose.yml` `.github/workflows/` | 部署和 CI 配置本来就是给人抄进自己环境的。拦着它一点商业价值都没有，只会劝退人 |
| `scripts/` | 出图、打包、录 demo 的脚手架，跟产品能力无关 |
| `eval/tasks.js` `eval/baseline.json` | 评测集越多人复跑越有说服力。挡着不让商业公司跑，等于自己不让人验证分数 |
| `skills/skill-creator/` | 写技能的模板。模板必须能被自由复制，否则没人写技能 |
| 文档里的示例代码与格式规范 | 规范就是让人实现的。任何人可以照着 `docs/技能.md`、插件与连接器的格式写自己的东西 |

同时明确一件事（这是**澄清**，不是让渡）：
**你自己写的技能包、插件、连接器配置、工作流、提示词，是你自己的作品，不是本项目的衍生作品。**
你想怎么授权就怎么授权，想卖就卖，跟本协议无关。

### 3.3 想过、但这一版先不开的口子

| 考虑过的 | 现在的决定 | 理由 |
|---|---|---|
| 25 个自研技能包整体改 MIT | **先不开** | 「开箱就有 25 个能干活的技能」是产品价值的一部分。整包 MIT 等于允许别人原样打进收费产品。想写技能的人有 `skill-creator` 和格式规范就够了，不需要这一条 |
| 整个项目改 Apache-2.0 / MIT | **不改** | 那就没有商业线了。NC 是这门生意唯一的护栏，见第 1 节第 2 条 |
| 主程序某些模块单独 MIT（如 `engines/`） | **先不开** | 切得越碎，别人越难判断自己在哪一侧。边界清楚比边界宽松重要 |

这张表写在这儿是为了留个把手：以后想开哪个口子，改这一行就是了，不用重新想一遍。

## 4. 仓库怎么分

```
CatCatUncle/openworkbuddy            公开 · PolyForm Noncommercial 1.0.0
└── 上面 2.1 的全部内容（其中生态层另按 MIT，见 LICENSE-ECOSYSTEM.md）

CatCatUncle/openworkbuddy-enterprise 私有 · 商业授权 · 还没建
├── enterprise/sso/                  SAML / OIDC / LDAP / SCIM
├── enterprise/audit-export/         SIEM 外送
├── enterprise/license/              离线许可证校验
├── enterprise/ha/                   多实例与共享状态
├── enterprise/brand/                白标
└── docs/                            实施手册、合规材料
```

**技术上怎么接起来**：开源版留**挂载点**，不留实现。

口子**已经在 `server.js` 里了**（包还不存在，但接口先定死，免得将来改主干）。
形状照抄 `admin.js` 的 `createAdminRouter({ deps })`：外部能力一律**传**进去，不是让它 `require` 进去。

它是**两个**口子，不是一个 —— 这一点最容易做错：

```js
// server.js（开源版）。装了就多几条路由，没装就是这几行什么也没干
const enterprise = (() => {
  let entry = null;
  try { entry = require.resolve("@openworkbuddy/enterprise"); }
  catch { return null; }            // 没装 = 正常状态，一个字都不打
  try { return require(entry); }
  catch (e) { console.error("[enterprise] 加装包装上了，但加载失败：", e.stack); return null; }
})();
const entDeps = { org, account, security, config, admin };

// ① 认证之前：只给 SSO 回调这类「按定义就还没登录」的路由
if (enterprise?.mountPublic) enterprise.mountPublic(app, entDeps);

app.use(account.authGuard);

// ② 认证之后（也过完租户隔离和凭证脱敏）：企业包绝大部分东西走这儿
if (enterprise?.mount) enterprise.mount(app, entDeps);
```

三处写法上的讲究，都是踩过才知道的：

- **为什么分两个口子**：SAML 的 ACS、OIDC 的 `redirect_uri` 是 IdP 打回来的那一跳，
  身份正是它们要带回来的东西。全挂在 `authGuard` 后面的话，这一跳会被自己人挡在门外，
  **SSO 根本走不通**。但也不能因此把整个企业包挪到闸前——那等于审计外送、白标设置
  全都免登录。所以安全的那个叫 `mount`，免登录的那个得**显式**写 `mountPublic`，手滑写不出来。
- **为什么先 `require.resolve` 再 `require`**：合成一步的话，「没装」和「装了但自己缺依赖」
  报的都是 `MODULE_NOT_FOUND`，后者会被当成前者悄悄咽掉，
  客户拿到的就是一台**企业功能静悄悄失踪**的服务器——这种最难查。
- **为什么 `mount` 不包 try**：要不要「加载失败就别让服务起来」是企业包自己的判断
  （SSO 没挂上就不该悄悄退回密码登录）。它 `throw` 就是 fail-closed，不 throw 就照常起。
  开源版不替它做这个决定，也就不该把它的 `throw` 吃掉。

这几条连同「界面里不许出现付费墙话术」，都由 `test/deploy.js` 第【8】节盯着，改坏了会红。

这样做的三个好处：
1. 开源版**不留任何被阉割的痕迹**——没有灰掉的按钮，没有「升级到企业版」的弹窗。
   那种东西是开源项目里最招人烦的。
2. 企业版是**加法**不是减法，两边可以独立演进，不用每次同步 diff。
3. 客户拿到的就是开源版 + 一个 npm 包，出了问题两边都能单独排查。

**绝对不要做的**：在开源仓库里留下功能开关、试用倒计时、或者「此功能需要企业版」的提示。
一旦有人在代码里读到这些，项目在社区里的定性就变了。

## 5. 开源版要让人一眼看出「这东西很强」

这是上面那条规则的另一面：既然靠开源版引流，它就得**真的强**，而且强得看得见。

已经做到的（README 第一屏应该把这些说清楚）：

- 说一句话 → 产出**能双击打开的文件**（xlsx / docx / pptx / 图 / 视频），不是聊天记录
- **AI 短剧无限画布**：角色、场景、镜头、首帧、视频、音频、时间线，DAG 连线
- **40+ 内置工具** + Markdown 技能 + MCP 连接器 + 插件，全部热装
- **飞书 / 企微 / iLink 远程指挥**，支持文件、图片、语音
- **执行追踪**：每次模型调用、每个工具、每条路径、耗时和 token，本地可查，不上传
- **企业管理后台**：多租户、成员部门、用量计费、付费 API 额度闸门、操作审计
- **完全自托管**：模型 Key 在自己机器上，可以接任何 OpenAI 兼容渠道
- **21 个测试套件 3000+ 条断言**，CI 全绿才发版

还该补的（排期见 `docs/路线图.md`）：

- 三列部署选项表（本机一键装 / 自托管 / 更多平台），每列一句话一个链接
- 一段 60 秒内跑完的「从零到第一个交付物」录屏

## 6. 复查清单

每次要加一个新功能，按顺序问：

1. **它让 Agent 多干一件活吗？** → 开源。
2. **它只有在「很多人用同一个实例」时才有意义吗？** → 再问第 3 条。
3. **它要对接企业中间件（IdP、SIEM、KMS、内网仓库）或者需要有人签字负责吗？** → 商业版。
4. **都不是？** → 默认开源。有疑问时往开源那边倒——
   收回来容易（下一版挪走），放出去再收回来会得罪人。

还有一条否决项：**任何让开源版变弱的改动，一律不做。** 包括但不限于人数上限、
调用次数上限、功能开关、试用倒计时、「升级解锁」的提示。
