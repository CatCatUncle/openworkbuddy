# OpenWorkBuddy 架构优化路线（2026-08）

> 写给未来的自己和贡献者：这份文档回答三个问题——现在的架构长什么样、哪里会先撑不住、按什么顺序改。
> 每一项都带「为什么 / 怎么做 / 怎么算做完」，验收一律以 `npm run eval` 跑分不回归为底线。

## 一、现状盘点（as-is）

一句话：**单进程 Electron 应用，里面住着一个 Express 服务和一个手写的 agent 循环，前端是一个无构建的单文件页面。**

```
Electron main 进程
├── server.js        Express :3800（会话/设置/评测/技能/记忆 全部 API）
├── agent.js         agent 主循环（步循环 + 自动续跑外循环 + 子代理递归）
├── tools.js         ~20 个内置工具 + 写后自检（JS/JSON/MD/HTML/PY/SH）
├── llm.js           多模型适配（DeepSeek / OpenAI 兼容 / …）
├── memory.js        长期记忆（JSON 文件 + 关键词召回）
├── diagram.js       四类图渲染管线（echarts SSR / viz WASM / mermaid / plantuml）
├── feishu-doc.js    飞书 convert API 写文档
├── eval/            评测 v2（12 题黑盒 + 机器判分 + AI 评委 + 人工打分）
└── public/index.html  单文件前端（~310k 字符，一个内联 <script>）
```

这套架构的**刻意选择**要先说清楚，免得后人当成债来还：

- **无构建**：`index.html` 直接改直接刷新，没有 webpack/vite。这是特性不是欠账——贡献门槛为零。
- **JSON 文件当数据库**：sessions/users/memory 全是文件。单用户桌面场景下够用且可 `cat` 可 `git diff`。
- **server 跑在 Electron main 里**：让 mermaid/截图白嫖 Electron 的隐藏窗口，代价是重业务会卡主进程（见 P2）。

## 二、真实的痛点排序

按「先撑不住的先修」排，不按「听起来高级」排：

| # | 痛点 | 证据 |
|---|------|------|
| 1 | **上下文管理粗糙**：长任务靠「裁剪最老消息」保命，裁掉的可能正是关键约束 | 自动续跑上线后，20 轮长任务会把早期决策全裁飞 |
| 2 | **记忆召回是关键词匹配**：换个说法就召回不到 | memory.js 现状 |
| 3 | **改提示词/工具全凭手感**：eval v2 刚补上「有没有退步」的答案，但还没进工作流 | 本轮之前 11 题只有机器判分 |

### P1 · 上下文工程（预计 1-2 周，收益最大）

**为什么**：自动续跑把任务时长拉到了小时级，「裁最老的」策略在长任务里必然丢关键信息。这是当前对结果质量影响最大的单点。

**怎么做**（按顺序，每步独立可交付）：
1. **工具结果分级压缩**：tool_result 进 history 前按工具分类——`read_file`/`fetch_url` 这类「可重取」的结果在超过 N 步后压成一行摘要+路径（要用再读一次），`run_node` 报错这类「不可重现」的保留全文。
2. **裁剪时生成「被裁摘要」**：现在裁剪是静默丢弃；改为把被裁的消息批量让模型压成一段「前情提要」插回 history 头部（一次裁剪一次小模型调用，成本可控）。
3. **PROGRESS.md 从纪律升级为机制**：续跑轮开始时由框架自动把 PROGRESS.md 内容注入 system 而不是指望模型自己去读。

**怎么算做完**：造一道 40 步以上的长任务 eval 题（中途埋一个「第 3 步说过的约束」），裁剪后仍能守住约束即通过。

### P2 · 评测驱动开发闭环（与 P1 并行，流程改动为主）

**怎么做**：

3. 题库补短板：长任务题（P1 验收题）、多轮对话题、记忆召回题。

**怎么算做完**：连续三次核心改动都有 eval 前后分数记录在 commit message 里。

### P3 · 记忆向量召回（1 周）✅ 2026-08-24 完成

落地形态与原计划略有出入，记录如下：
- llm.js `createEmbedder(config)`：优先 `config.embedding` 显式指定；否则在模型列表里找**认识的**厂商复用 key（DashScope/智谱/OpenAI/本地 Ollama；DeepSeek/OpenRouter 没有 embeddings 接口，不猜）。没 key 的条目跳过（Ollama 例外）。连挂 3 次自行停用并留痕，绝不静默。
- memory.js：向量单独存 `data/memory_vectors.json`（memories.json 保持人能读；换嵌入模型自动全量重算）；`ensureVectors()` 启动/换模型/新记一条后后台补算。
- **召回只在装不下时发生**：promptBlock 超 6000 字预算才筛，打分 = 0.7×余弦 + 0.3×中文二元组关键词；没向量退关键词，没线索退新旧排序（老实现的盲切尾巴恰好吃掉最新记的，已修）。挑没挑、挑了几条，提示词里明说。
- 线索（hint）= 用户最后一条消息前 500 字；专家拿委派任务描述当线索。提示词组装链因此转 async。

**为什么**：关键词召回对中文尤其脆（「部署」召不回「上线」）。

**怎么做**：不引入向量库——单用户几百条记忆，**本地 embedding + 余弦暴力扫**就是最优解：
1. llm.js 加 embed 接口（DeepSeek/OpenAI 兼容的 embeddings endpoint）。
2. remember 时算一次向量存进 memory JSON；召回时对 query 算向量、内存里全量余弦排序，取 top-k 再过一遍现有关键词逻辑兜底。
3. 没配 embedding 模型时静默退回纯关键词（不新增必填配置）。

**怎么算做完**：记忆召回 eval 题——换措辞提问能召回原记忆。

### P4 · 前端解体 ✅ 2026-08-25

**为什么**：单文件是特性，但 277k 字符的**单 script** 不是。可以既无构建又分文件。

**实际做法（与原计划的偏差）**：没用 ES Modules，用的是**顺序加载的经典脚本**（`public/js/app-01.js` ~ `app-06.js`，六个 `<script src>` 按序排列）：

- 经典脚本共享同一个全局作用域（含顶层 let/const），六段拼回去和原内联块**逐字节相等**——语义等价有数学保证，不需要梳理 import/export 依赖图。ESM 方案要先把 283 个顶层声明的引用关系全理清，改动面和风险大一个量级，收益却一样（文件变小、刷新即生效不变）。
- 切分点由 acorn 按**顶层语句边界**贪心切（单片 ≤55k 字符），每片独立过 `node --check`。
- 经典脚本拆分唯一的语义风险是「立即执行的顶层代码前向引用了后面片段的声明」（函数提升不跨 script 标签）——自动审计过一遍，**零前向引用**。
- 拆分/审计脚本在会话 scratchpad 的 split.js，需要重切时可复跑。

**验收**：单片最大 54,788 字符（目标 ≤60k）✅；index.html 缩到 75k ✅；浏览器全页面回归（登录/新任务/专家/自动化/任务历史/设置，刷新后控制台零报错）✅；改代码直接改 `js/` 下分片、刷新即生效，开发体验不变 ✅。

### P5 · agent 执行隔离与安全（择机）— 软护栏 ✅ 2026-08-24；utilityProcess 明确缓做

- run_shell 软护栏 ✅：动手前盘点发现安全中心的 checkCommand + 界面审批流早已覆盖 `rm -rf`（删除保护）、sudo/mkfs（询问名单）和文件黑名单，真正缺的是路线图点名的那几个形态。已补一张 `DANGER_PATTERNS` 高危表：`> /dev/` 直写、`dd of=/dev/`、`compose down -v`、`git push --force`、SQL 删库/清表、格盘分区。**全档位生效（全自动也拦）、永久放行名单盖不住**、批过一次按 danger:key 记在本会话不反复骚扰、「只看不动」档仍是直接拒绝。
- agent 循环挪 `utilityProcess`：**缓做，有意为之**。mermaid 渲染（gen_diagram/browser-render）依赖 main 进程的 BrowserWindow，挪出去要么断这条能力要么加一条 IPC 往返桥；eval 已在子进程跑通证明可行性，但眼下收益（崩溃隔离）对单用户桌面场景不及改造成本。等出现真实的「agent 干崩 main」案例再动。

### 追加 · 长跑韧性三连 ✅ 2026-08-25

自动续跑把任务拉到小时级后，三个新的「先撑不住」浮出来，一并补上：

1. **卡循环检测（agent.js）**：同一工具+同一入参连续拿到**同一结果** 3 次 → 注入系统提醒换思路；5 次 → 直接拦截不执行（返回错误结果说明为什么）。键里带结果指纹，「改一遍读一遍」的正常校验循环不会误伤——文件变了内容就变，计数自动清零。另有工具级连败计数（换参数也算）连挂 4 次提醒一次。此前只有提示词纪律（"连续失败 3 次就换思路"），现在是机制。
2. **token 预算护栏（设置 → Agent）**：`max_tokens_budget`，整棵任务树（含专家、含自动续跑）共享一个用量闸，80% 预警、超了强制收尾且**不再自动续跑**（预算是花费上限，续跑就违背本意）。0 = 不限（默认）。步数挡不住小步快跑烧钱，时间挡不住便宜模型慢慢磨，这道闸按钱的正比例量收口。
3. **重启中断标记（server.js）**：正在跑的会话 id 落盘 `data/running.json`（起跑写入、收尾清除）；启动时清算名单，被打断的那轮在回放里补一条明确的中断说明（进度都在，可以说「接着上次进度继续」）。此前应用中途重启，那一轮就无声断在半空，用户分不清是完成了还是死了。

验收：零 token 假模型压测（循环 4 执行 3 拦截 1 提醒；预算 80% 预警→超限收尾→零续跑）+ 真实重启清算实测 + `npm test` 全绿。

### 追加 · 启动 30 秒白窗根修 ✅ 2026-08-25

桌面版每次打开都要盯 30 秒白窗——不是 Electron 慢，是壳里的 `waitForServer` 只认 `r.ok`，而探活端点 `/api/info` 挂在登录守卫后面回 401，于是每次启动都空等满 200×150ms 超时才加载页面。改成「服务端有任何 HTTP 应答就算活」，实测页面加载 31682ms → **629ms**。启动链路已埋永久分段计时（Electron 就绪 / 服务端初始化 / 服务端就绪 / 页面加载完成），下次再慢，看日志就知道慢在哪段。

### 追加 · 上下文中枢升级（借鉴 pi agent）✅ 2026-08-25

对照 pi（earendil-works/pi）的 compaction 设计补了三块，全在既有 compactHistory 上生长：

1. **任务中分轮压缩（split turn）**：原先压缩只在任务开跑前做一次、只会切在用户轮边界，单轮长跑任务中途永远压不动，只能靠 trimHistory 把早期工具输出盲截成空壳。现在步循环里每步先试智能压缩：用户轮不够切时退到助手消息边界下刀（工具调用/结果永远成对），把任务早期几十步浓缩成接手摘要。切点搜索方向必须向前（更早）——越界点常落在结尾的工具结果上，它所属的调用要一起保留。
2. **结构化摘要 + 确定性文件清单**：摘要提示词改成 pi 式固定小节（目标/已完成/进行中/关键决定/下一步/关键上下文）；读过、改过的文件从工具调用里机械提取，不靠摘要模型转述，跨多次压缩累计合并（借鉴 cumulative file tracking）。分轮压缩会把本任务原始指令压掉——【最近的用户指令原文】机械保留并跨次接续。
3. **项目挂载自动读 AGENTS.md / CLAUDE.md**：项目目录里放了就自动进系统提示词（截 6000 字符），不用往项目指令里手抄。

录制白名单（server recordingEmit + 前端 makeRecCounter）同步加了 `compact`，两边口径必须一致。新配置：`compact_keep_chars`（分轮压缩保留的近期字符数，默认 30000）。零 token 压测 13 项断言全绿（scratchpad/compact-test.js），循环护栏/token 预算回归不受影响。

### 追加 · 模型挂起/繁忙自动换道（备用渠道 failover）✅ 2026-08-26

真实使用数据挖出的头号未治死因：199 个任务轮次里，「模型响应超时（300 秒无输出）」杀死 7 个任务、"Service is too busy" 杀死 3 个——加起来超过其它所有非人为死因。同渠道重试（llm.js 已有）救不了服务端整体过载的场景，需要换道。

- **显式备用渠道**：`config.agent.failover_model`（渠道名，默认空=关闭）。红线是「绝不静默降级用户配置的模型」——只有用户在 设置→智能体设置 里亲手选了备用渠道才会换，否则照旧如实超时/报错。
- **两个触发点**（都在 runTask 步循环的 catch 里）：① 挂起——stall 计时器触发且不是手动停止、不是任务总时长到点、剩余时间 >30 秒；② 硬错误——llm 层同渠道重试用尽后仍抛错（too busy / 欠费 / 5xx 都算）。触发后 `step--; continue;` 重试当前步。
- **一次换道封顶**：每个 runTask（含每位专家的子任务）最多换一次，备用渠道也挂就如实收尾，不搞换道链。`L` 从 const 改 let，换道后新委派的专家跟着走新渠道（llmOverride: L）。
- **大声播报**：专用 `failover` 事件（不是转瞬即逝的 status），进录制白名单（server.js 与 app-02.js 两份 KEEP 必须同步加），app-01.js 用错误色渲染 `🔀 …已切换到备用渠道「×××」`，直播与回放都看得见。
- **可测性**：createAgentRuntime 新增可注入 `llmFactory`（默认懒 require ./llm 的 createLLM，避免环形依赖）；零 token 四场景压测全绿（挂起换道 / 硬错换道 / 未配置照旧超时 / 备用=当前渠道不空转）。
- 坑：挂起判定 stallMs 有 10 秒地板（Math.max(10000,…)），测试里把 llm_timeout_ms 调到 1 秒也得等 10 秒，别误判为失效。

### 追加 · 第46轮 打包分发 + 一批按真实数据挖出来的修复 ✅ 2026-08-28 ~ 08-30

### 追加 · 第48轮 三处「看得见的假象」 ✅ 2026-09-03

### 追加 · 第49轮 文件预览的白名单陷阱 ✅ 2026-09-03

用户点开一个文件，界面回「该格式暂不支持应用内预览，可点右上 🗔 用系统程序打开，或 ⬇ 下载」。

三个毛病叠在一起：

1. **判据的形状反了**。预览路由是一张**文本扩展名白名单**（`txt|csv|json|js|cjs|css|xml|log|yml|yaml`），白名单外的一律掉进兜底。而工作目录里数出来：**22 个 .mp3、19 个 .swift、11 个 .plist、9 个 .py、6 个 .mp4、4 个 .srt、4 个 .h**，全在白名单外。.mp3/.mp4 尤其别扭——文件列表里明明给了 🎬 图标，点开却说不支持。白名单这个形状本身就是 bug：模型每产出一种新后缀，就得有人回来改一次代码。
   - 改成反着列：只写「当文本打开必然满屏乱码」的二进制后缀，其余**一律先当文本试**；真是二进制（含 NUL，或替换字符超过 1%）再退回兜底。**后缀认不出来时让内容说了算。**
   - 音频/视频给真播放器（`<audio>/<video> controls`）。服务端 `res.sendFile` 本来就回 `Accept-Ranges`，进度条能拖、长视频不用等整包下完——实测工作目录里的真文件：mp3 44.9s / 33.0s、mp4 47.1s 720×1280，全部 206 + Content-Range。
   - `.ts` 是个专门的坑：mime 库把它认成 `video/mp2t`，跟着 mime 走会给 TypeScript 源码套一个播放器。所以路由按显式后缀表走，不按 mime，并且钉了断言。

2. **兜底那句话在指认不存在的东西**。标题栏早就从 emoji 换成 SVG 图标了，「点右上 🗔 …或 ⬇」照着找一辈子也找不到。改成直接给两个能点的按钮（用系统默认程序打开 / 打开所在位置）。

3. **大文件会卡死渲染进程**。老代码是整包 `fetch` 完再 `slice(0, 100000)`——几百 MB 的日志在 slice 之前就已经把内存吃光了。改成带 `Range: bytes=0-524287` 只取头 512KB，并在末尾标出「只显示了开头」。

`test/frontend.js` 加了第三个窗口，**跑 app-01.js 里那一段真源码**（段标题被改就当场报错，不许静默跳过）：60 项断言覆盖路由表（含每一种真实产出后缀）、.ts 不当视频、播放器真的出来、白名单外的纯文本真的显示内容、后缀没认出来但内容是二进制要退回、兜底按钮真能触发打开/定位、Range 头真的发了、Office 仍旧交给本机程序。负向对照：拿掉修复，测试当场红。

### 追加 · 第50轮 docx/xlsx/pptx/zip/csv 的应用内预览 ✅ 2026-09-03

第49轮把「认不出来的当文本试」这条路走通了，但还剩一类文件天生没法当文本试：**docx / xlsx / pptx / zip 都是「一包 XML 打成 zip」**，浏览器直接打开只会是二进制乱码。老代码对它们的处理是 `OFFICE_RE` 一律甩给本机 Office/WPS——可这个应用自己的技能里就有 `docx`、`excel-report`、`ppt-design`、`ppt-master` 四个，**产出最多的几种格式恰恰是应用内唯一看不了的几种**（会话里 pptx 被提到 148 次、zip 59 次、csv 32 次、docx 31 次、xlsx 17 次）。

新增 `preview.js`：服务端把包拆开，`GET /api/files/preview/:name` 只吐**结构化数据**。

- **零新依赖**。ZIP 用 Node 自带 `zlib.inflateRawSync` 手写一个最小读取器（EOCD 回扫、中央目录遍历、method 0/8）；OOXML 的 XML 用手写扫描器（正则拆 OOXML 太脆），元素/属性/CDATA/注释都过一遍，遇到孤立的闭标签往上回退到同名祖先而不是把树搞坏；xlsx 直接复用已经装着的 `exceljs`。
- **只吐数据不吐 HTML**。文件内容是模型写的或从网上下的，服务端要是转成 HTML 直接塞进渲染进程，等于自己开一个 XSS。拼 HTML 的活统一留在前端一处，每个字段都过 `esc()`——**转义漏没漏只需要审那一个地方**。docx 内嵌图额外再确认一次 `data:image/` 前缀，别让别的协议混进来。
- 拆出来的东西：docx 保留标题级别/粗斜下划线/列表层级/表格/内嵌图（转成 data URI）；xlsx 多工作表带切页；pptx 一页一卡，标题、层级、备注都在；zip 列清单。**pptx 有两个坑**：备注页里混着页码占位符（`sldNum/dt/ftr` 得按 `p:ph type` 滤掉，不然备注回来是个 "1"），以及 pptxgenjs 的 `placeholder:"title"` 根本不发 `p:ph type="title"`（没有标题占位符时把首行提上来当标题）。
- csv/tsv 不走服务端——内容前端已经取回来了，就地按 RFC4180 拆（**字段里带逗号、带双写引号、带换行都是常事，`split(",")` 会把表拆散架**），分隔符按首行嗅 `,` / `\t` / `;`。
- `OFFICE_RE` 收窄成只剩 `.doc/.ppt/.xls` 三个 Word97 时代的二进制老格式——它们不是 zip+XML，拆不开，继续交给本机程序。

两层都钉了断言：`test/e2e.js` 的 `testPreviewExtract` **不喂手搓样本**，用 `docx`/`exceljs`/`pptxgenjs` 真库生成再拆回来逐条对（写「标题一」就得回「标题一」，级别、粗体、表格一个不能丢），zip 清单拿真库产的包验，坏文件必须报错而不是吐半截垃圾；`test/frontend.js` 的预览断言从 60 项加到 **100 项**，覆盖新路由、结构化渲染、转义（`<脚本>` 必须变 `&lt;脚本&gt;`）、非 `data:` 图源被挡、xlsx 切页真切、拆不开时退回兜底按钮而不是白屏，以及 CSV 的四种拆法。负向对照：把 `OFFICE_RE` 改回去，测试当场红。

### 追加 · 第51轮 自进化：从"每天往提示词里加句话"变成一条能验的闭环 ✅ 2026-09-03

按 Warp 那套 self-improving agent 的路子改。它的顺序是**先有验收台，再让 agent 对着验收台调自己**——`eval/run.js` 那套失败码分类、pass@k、基线对比早就有了，缺的是前面两环：**反馈收不上来**，以及**改动没人管**。

先说最要命的那处断链：界面上每条回复底下的 👍👎，**点了只是换个高亮色，一个字节都没往外送**。不会报错，界面看着还挺正常，链子从源头就是断的。

新增 `evolve.js`（439 行，零新依赖），五段：

1. **信号**——把 `data/sessions/*.json` 里真实发生过的失败数成带证据的条目。**按形状归类，不按原文**：原文里有路径有行号有时间戳，照原文聚类的话同一个毛病会散成几十个"只出现过一次"，永远过不了证据门槛。每条信号带会话 id + 第几轮 + 原文摘录，**点得回去**——没有证据的信号只是观点，改了也没法验。
2. **反馈**——`POST /api/feedback` 落盘。👎 点下去当场就记，理由是**选填**的补充（摩擦得够小）；同一轮反复点是**改判**不是攒记录。
3. **闸门**——代码侧先毙一批，别拿"看着像那么回事"的提案浪费人的注意力。
4. **人审**——`decideProposal` **永远不自动生效**。规则一条一个文件（`data/learned/*.md`），人能直接读直接改，撤销就是删一个文件。
5. **打分**——`scoreRules` 拿规则生效前的基线出现率跟现在比。**只看数字，不看措辞**：没降就自动建议下架。

闸门这层是整套东西的成败所在，它挡的全是这类系统最典型的烂法：

- **代码问题不许被写成提示词规则**。跑真数据出来的第一名是「check_page 把预览容器自己的 Electron 安全警告当成页面报错」，276 个回合里 23 次（8.3%）——这是工具误报，得改代码；「渠道余额不足」21 次，得去充值。给这两样加提示词纯属自我安慰，所以 `actionable` 分 `prompt / config / code` 三档，**只有 prompt 档准变成规则**，另外两档进 notes 提醒人。
- **一次是偶然，三次才是模式**：少于 3 次证据不许提。
- **不许越堆越长**：最多 12 条、每条 ≤400 字、总预算 4000 字，满了必须**指名换下一条**才能加；指纹去重挡掉换个说法再来一遍。提示词里加措辞不生效，十有八九是有一条在反着说——所以提案模板里写死了：新规则和旧的打架就用 `retire_rule` 把旧的下架，不许叠。
- **必须给验收口径**：说不清"生效后哪个数字该降"的提案直接毙掉。

归类做到什么程度才算数，看这个例子：`edit_file` 的报错原本有 20 次挤在「edit_file 报错」这个大杂烩桶里，等于没归类。拆开看，其中 19 次是同一个形状——**写完自检把产物顶回来**（JS 语法坏了 / `<body>` 没闭合 / 用了没定义的 CSS 变量），文件是写进去了，毛病在内容：一次没写完整就交，然后反复打补丁。剩下 1 次是中文的「是一个目录，不是文件」，只认 `EISDIR` 的正则漏了它。补完之后 `tool_error:edit_file` 这个桶**一条不剩**，19 次浮上来成了 prompt 档的第一名。

界面在 设置 → 自进化：信号排行（标着该谁治）、待审提案（带现场原话和验收口径，采纳/驳回）、生效中的规则（带打分和下架）。夜间自动复盘**默认关**——每晚要调一次模型，是花钱的事，得自己点开；跑砸了成败都落一行（`data/evolve_runs.json`），后台飞轮吞掉异常等于这条链早停了而你还以为它在转。

两层断言，都做了负向对照：

- `test/e2e.js` 的 `testEvolveLoop` 在临时 `WB_DATA_DIR` 里造会话跑全链——窗口过滤、👎 改判不重复、闸门六种毙法、提案不点头不进提示词、打分只认数字（基线 0.9→0.5 算有效，0.33→0.33 就是没起作用且建议下架）、下架留档、后台失败留痕。**负对照**：把「只有 prompt 档准变规则」那行改成恒真，红；把 check_page 的真报错判断跳过，红；把自检顶回来那条归类去掉，红。

### 追加 · 第52轮 自进化挖出的第一条真修复：zsh 的通配符会**拒绝执行整条命令** ✅ 2026-09-03

上一轮那套东西装完当天就先拿它自己挖了一遍：近 30 天 227 个助手回合，`tool_error:run_shell`
还有 16 次堆在大杂烩桶里——和上一轮拆掉的 `edit_file` 是同一个毛病，归类没做完。而
run_shell 一族（catch-all 16 + 找不到文件 14 + 通配符 13 + 超时 9）加起来 **52/227 = 23% 的
回合踩过 shell 的坑**，是全系统最大的失败面。

把 14 次 `zsh_glob` 的原文摊开看，10 次是同一个形状，而且伤害比"多一句报错"重得多：

**zsh 的通配符没匹配上，是整条命令拒绝执行，不是命令跑了然后报错。**

- `ls /usr/local/bin/python*` 探测装没装 → **ls 压根没运行**，只有 zsh 一句 `no matches found`。
  模型分不清是"没装这个版本"还是"我命令写错了"，于是接着换个写法再探一遍。
- `for f in *.md; do ...; done` 没匹配上 → 整个循环连同后面的收尾**一起不执行**，exit 1。
  真实会话里就有一条 `zsh:12: no matches found: *.md`，前面 11 行白跑。
- `curl http://a.com/x?id=1` 不加引号 → **`?` 和 `[]` 在 zsh 里也是通配符**，命令直接不跑。

根因是 tools.js 的 `pickShell` 在 macOS 上写死 `/bin/zsh -c`，而模型写的是 bash 味的命令。
修法一个开关：`zsh -o nonomatch -c`，行为回到跟 bash 一致——通配符原样传给命令，由命令
自己报 `No such file`，脚本接着往下走。没换成 bash 是因为 macOS 自带的是 bash 3.2，
`**` 递归通配会**悄悄退化成单层**，那是比报错更糟的错法。

验：`testShellGlobCompat` 钉行为不钉措辞——循环后面的收尾必须还在、带 `?` 和 `[]` 的 URL
必须真跑起来、报错必须来自命令自己、能匹配上的通配符不许被顺带改坏、参数钉死在 `pickShell`
那一层。**负对照**：摘掉 `-o nonomatch`，红。

写这条测试时自己先踩了一次假绿：② 原本写成 `content.includes(URL)`，而 zsh 拒命令时那句
抱怨里**也带着这个 URL**——错误信息把答案抄了一遍，负对照照样绿。断言改成只认 stdout 段
才真的红。所以负对照不是走过场：它当场逮到的是这条测试本身。

### 明确不做的事

- ❌ 微服务 / k8s / 独立数据库——单用户桌面应用，永远不需要。
- ❌ 引入前端框架和构建链——无构建是产品性格。
- ❌ 向量数据库服务——几百条记忆用暴力扫。
- ❌ 多租户——这是个人 agent，不是 SaaS。
